# `experiments/` — T2·T3·T5 실험 설정 (D-94)

> 🚨 **여기 있는 것은 「설정」이지 「코드」가 아니다.** 코드(harness)는 팀장이 든다.

## 파일이 두 층이다

    harness.<트랙>.yaml     팀장이 고정한다 — split · 시드 · 평가 지표 · 무변화 3회 · 열어 줄 손잡이
    <이니셜>_<번호>.yaml     팀원이 채우는 **유일한 파일** — 모델과 하이퍼파라미터

🔴 **harness 는 트랙마다 하나**다 (2026-09-12 밤 배정 개정). 인코더(T2)와 sLLM(T5)은
**split 도 평가 지표도 다르다** — 한 파일로 두면 「같은 조건」이 트랙을 건너 거짓이 된다.
게이트: `test_트랙마다_harness_가_따로다`.

🔴 **팀원 설정은 harness 를 못 덮는다.** 주석이 아니라 검증기가 막는다 —
`scripts/experiment.py` 의 `LOCKED` 와 게이트 `test_고정값을_팀원_설정이_못_덮는다`.

★ D-94 가 「트랙째 위임」을 기각한 이유가 이것이다 —

> 각자 **다른 split · 다른 시드 · 다른 평가 스크립트**로 돌아온다.
> 숫자는 다섯 개 나오는데 **비교가 불가능하다.** 그러면 실험이 아니라 다섯 개의 일화가 된다.

## 쓰는 법

```
uv run python -m scripts.experiment --check experiments/ksr_01.yaml
```

통과하면 **MLflow 에 올라갈 params 를 그대로 찍어 준다.** 고정분(`fixed.*`)이 같이 올라가므로
나중에 표를 보고 「같은 조건이었나」를 물을 수 있다 (D-178).

## 설정 파일 모양

```yaml
owner: ksr            # 🚨 docs/<이니셜>/ 이 있어야 한다 — 명단의 정본은 디스크다 (D-99)
track: T5             # T2 인코더 / T3 ML·리랭킹 / T5 생성·배달(sLLM LoRA)
run: kcbert-lr3e5     # MLflow run 이름. 같은 사람이 여럿 돌리면 번호로 가른다
base_model: beomi/kcbert-base
revision: <커밋 SHA>   # 🚨 태그는 움직인다 (기획서 8-4 #9)
params:               # 🔴 harness 의 allowed_params 에 있는 키만
  lr: 3e-5
  epochs: 3
note: 왜 이 조합을 골랐는지 한 줄
```

🚨 **트랙 번호의 뜻은 여기가 정본이 아니다** — 기획서 8-5 다 (D-54).
⛔ T1(데이터·거버넌스)·T4(그래프·RAG)는 하이퍼파라미터를 나눠 돌리는 종류가 아니라 **거부한다**
   (`test_실험_트랙이_아니면_거부한다`).
