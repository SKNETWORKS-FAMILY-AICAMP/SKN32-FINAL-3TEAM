왜 층이 아니라 기능인가 (D-208)
① 억지 컷이 필요 없다 층으로 자르면 tests/** 에서 팀장과 겹쳐 「검사 내용은 팀장 · 도는 판은 남」이라는 인위적인 선을 그어야 했다 🚨 경계를 억지로 그어야 한다는 것 자체가 그 분할이 틀렸다는 신호다
② 눈에 보이는 산출물이 남는다 층으로 나누면 그의 일이 「팀장을 위한 서비스」가 되어 밀려도 아무도 모른다
③ 소유 = 승인권이 아니라 기본 담당 남이 고쳐도 된다 — 알리고, 같은 파일을 동시에 열지 않는다 (D-211) 잠금은 여덟 자리뿐이고 전부 이유가 있다 (계약 §5 등급 1)
개발 순서 — 통합을 마지막이 아니라 처음에
1차 · 핵심 — walking skeleton · 문구 하나가 한 바퀴
→
2차 — 판정 품질 · 근거 검색
→
3차 · 살 붙이기 — 생성 · 템플릿 · 통계

뒤에 붙는 산출물이 상상이 아니라 실측 위에 놓이게 하려면 통합이 먼저다. Git 은 개인 브랜치 → 팀장 흡수 → main PR, 직접 커밋 금지.

기능으로 자르면 파일 소유가 저절로 갈린다. 규칙을 늘려 지키게 하는 대신 부딪칠 일이 없게 나눈다 — 이유 없는 잠금이 많아지면 이유 있는 잠금까지 같이 안 읽힌다 (D-167 · D-211).
