판정 1회 — 무엇을 읽고 무엇을 쓰는가

데이터층은 읽기만 한다 · [실측]/[기획] · 2026-09-13
[실측] 지금 돈다 [기획] 계약·표는 섰고 코드가 없다 🔴 값이 없어 비어서 돌아온다
1
사용자 → API
광고 문구 · 제품 맥락 전달 실측POST /judge — 계약은 나가고 엔진은 501 을 지킨다 (D-124 · D-147) 실측POST /u/judge — 화면 경로. 지금은 골든 픽스처로 분기를 그린다 본문은 text + product 뿐이다 — 🚨 input_mode 라는 칸은 없다
2
API → 런타임층
work_doc · copy_sentence 생성 기획표는 섰다 — 🔴 라우터가 아직 DB 에 안 붙는다 (D-124 · 화면이 DB 없이 떠야 한다) 실측동의 없으면 expires_at 필수 — CHECK 이 이미 막는다
3
API → 데이터층
dict_entry 정확매칭 → 위험도 하한 실측사전 536행 적재됨 (유형 붙은 것 430) 기획매칭 코드가 없다 — app/ 에서 dict_entry 를 읽는 곳은 관리자 표시뿐이다 exact_match = true 인 항목만 하한 자격을 갖는다
4
API → 데이터층
어휘 ts_rank_cd + 벡터 KURE-v1 → RRF → 근거 조문 실측/search 로 실제로 돈다 · 청크 2,400 = 벡터 2,400 실측RRF Σ 1/(k+rank) · k=60 [문헌] (D-193) · v_current_chunk — 현행 조문 · RAG 허용 소스만 기획🔴 그래프의 retrieve 노드는 아직 스텁이다 — 코어는 도는데 판정이 그것을 못 쓴다
5
API → 데이터층
v_risk_lookup → 제재 · 위험도 기획뷰는 있고 0행을 낸다 — sanction_rule 적재기가 아직 없다 별표 파싱은 끝났다 (5법령 · 12건 · 243행) — 남은 것은 적재기다
6
API → 데이터층
violation_article → 라벨 ↔ 조문 대응 기획0행 — 사람 판정 + 2인 확인이 선행이다 (D-66) 원천 300노드는 law_norm 이 이미 파싱해 뒀다
7
API → 런타임층
judgment 저장 — 새 행을 쌓는다 실측표·제약은 섰다 — law_version · attempt 0~2 · 덮어쓰지 않는다 기획쓰는 코드가 없다 — 2행과 같은 자리다
8
API → 사용자
violations · evidence · risk · rewrite 실측응답 스키마는 /openapi.json 에 완전히 나가 있다 — 팀원은 그것으로 붙는다 기획값을 채우는 엔진이 없다 · disclaimer 는 항상 붙는다 — 빼는 옵션이 없다
쓰기는 런타임층에만 데이터층은 읽기만 한다 5 · 6 은 값이 없어 지금은 비어서 돌아온다 실측 행 1 / 8

🚨 「도면이 8행이니 8행이 돈다」로 읽지 않는다. 지금 값이 끝까지 흐르는 줄은 4행 하나이고, 그것도 /search 에서만 돈다 — 판정 그래프는 아직 그것을 부르지 않는다. ⛔ 「설계상 있다」와 「지금 돈다」를 같은 글씨로 적지 않는 것이 이 장의 목적이다 (D-219 · A-04).

판정은 데이터층에 한 글자도 쓰지 않는다. 사용자 문구가 조문·사전·제재 표를 오염시킬 경로를 방향으로 막았다 — 쓰기는 런타임층 7표에만 간다 (E-02).
