## 2. 되살리는 순서

순서가 중요하다 — **판정 → 스키마 → 화면** 이다. 화면부터 열면 D-107 이 막으려던 「화면이 있으니 했다」가 된다.

1. **판정 (팀장)** — 왜 닫았는지를 푸는 결정이 먼저 있어야 한다.
   | 화면 | 먼저 풀어야 하는 것 | 개정 대상 |
   |---|---|---|
   | 가입 심사 | 승인이 **무엇을 켜 주는지** (역할 · 프로필 공개 권한) · 인플루언서 · 기업을 검증할 수단 | D-260 ④ · D-66 · D-68 |
   | 기업 회원 | 사업자 진위 확인 수단 · 기업 단위로 달라지는 것(요금제 · 구성원 권한) | D-260 ④ · D-69 · D-104 |
   | 심사 서류 | 🔴 **파일을 받아도 되는지** — 보관 위치 · 암호화 · 보관 기한 · 파기 절차 | **D-107 조건 1** · D-260 ⑤ · D-129 |
2. **스키마 (팀장 · 등급1 잠금)** — `app/models.py` 에 표 · `alembic/versions/` 에 마이그레이션 · `db/schema.sql` 은 거버넌스 층이라 해당 없음.
   9/16 초안(`member` · `enterprise` · `signup_review` · `signup_review_doc`)이 출발점이지만, `member` 는 이미 `user_account` 로 합쳐졌다(D-260 ②) —
   새 표는 `user_account.id` 를 FK 로 건다. 두 벌 금지 (D-99).
3. **읽기 화면 (psj)** — 라우터의 `CLOSED` 화면을 지우고, 남겨 둔 템플릿을 다시 부른다.
   - 조회는 `app/routers/admin_dbread.py` 의 `run()` 을 쓴다 — 못 읽으면 0건이 아니라 안내(`admin/_db_notice.html`) · 404 는 읽었는데 없을 때만.
   - 예: `admin_cs.py`(문의) · `admin_members.py`(회원)가 같은 모양이다.
4. **쓰기 (승인 · 반려 · 서류 상태)** — 관리자 쓰기는 허용 목록에 있어야만 연다.
   - `tests/test_auth_boundary.py` 의 `ADMIN_WRITES` 에 (메서드, 경로) 추가 — **팀장 판정 대상**
   - 핸들러는 `require_governor` · `csrf_ok` · `audit` 를 반드시 부른다 (`REQUIRED_CALLS`)
5. **테스트 · 문서**
   - `tests/test_admin_closed_screens.py` 에서 그 화면을 빼고, DB 화면 테스트(`test_admin_dbread_screens.py` 와 같은 모양)를 더한다
   - 요구사항 정의서 「구현 상태」 열을 `표시만` → `구현` 으로 (D-107 조건 4)

## 3. 매출 통계는?

D-260 ⑥ 으로 **같이 닫기로 한 화면**(라벨 `Phase 4 이후`)이지만, 10-20 현재 통계 화면을 따로 수정하는 중이라 이번에 손대지 않았다.
