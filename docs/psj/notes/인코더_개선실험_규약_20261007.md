> 2026-10-07 · 박수진 · 소성민 (T2 인코더 파인튜닝 공동) · Baseline = v10
> 두 사람이 실험을 나눠 돌려도 결과를 그대로 합칠 수 있게, **무엇과 견주고 · 어디서 재고 · 언제 통과인지**를 먼저 고정한다.

## 2. 공통 dev

| 항목 | 규칙 |
|---|---|
| 떼는 법 | 원천별 묶음 15% + 6종 보충(유형마다 양성 10건까지) · 시드 42 · **문장 단위 · 합성 아님** (v11 노트북 섹션 3) |
| 결과 | 재동결 10-05 골든(`529c970556d7`)에서 **749행 · 지문 `4ebfcb231da703b5`** |
| 지문 | `sha256("\|".join(sorted(dev id)))` 의 앞 16자. 다르면 다른 dev 다 |
| 학습에서 빼는 것 | dev 묶음에 든 행 전부(합성 · 낱말 포함) + dev 와 같은 문구 |
| 정답 | 조건 M · D · L 은 유형이 적혀 있어도 음성. 그 밖은 골든의 유형 |

- dev 를 바꾸면(보강 · 재분할) **2판**으로 올리고 Baseline 을 새 dev 로 다시 잰다. 1판 수치는 지우지 않는다.
- 2판을 만들 때도 학습 분할 안에서만 뗀다. test 행은 dev 로 옮기지 않는다(옮기려면 팀장 판정).

## 3. 결과물의 형식

학습 코드는 각자 달라도 된다. **내놓는 파일만 같으면** 같은 자로 잰다.

| 파일 | 내용 | 두는 곳 |
|---|---|---|
| dev 행별 확률 CSV | `id` 칸 + `p_<유형>` 9칸 (순서 — 질병 · 건기식 · 의약품 · 거짓_과장 · 소비자_기만 · 후기 · 부당 비교 · 비방 · 기능성화장품). dev 749행 전부 · 시드마다 하나 | 저장소 밖 · 팀 공유 드라이브 |
| `label_scheme.json` | `label_list` 9칸 · `label_thresholds` | 모델 zip 안 |
| 모델 zip | 채택 후보만 | 저장소 밖 · 팀 공유 드라이브 |

## 4. 채점

`docs/psj/e2e_prototype/score_encoder_dev.py` 하나로 잰다. 표준 라이브러리만 쓴다.

```
python docs/psj/e2e_prototype/score_encoder_dev.py --probs <시드42.csv> <시드43.csv> <시드44.csv> --scheme <label_scheme.json 또는 zip> --baseline-probs <v10_dev행별확률.csv> --baseline-scheme <v10_scheme.zip> --baseline-seed-prauc 0.7167 0.7081 0.7165 --target "<겨냥한 지표와 목표>" --out-md docs/psj/reports/<실험이름>_dev채점.md
```

| 고정한 것 | 값 |
|---|---|
| 채점 행 | dev 749행 전부. 광고 문구 줄만(「이유」 구역 · 조건 M · 유형 없는 위반을 뺀 325행) 본 값을 함께 낸다 |
| 모델 고르기 | 회차 · 시드 = 6종 dev macro PR-AUC 가 가장 높은 것 (8종으로 넓히지 않는다 · D-321 결정 4) |
| 문턱 | 유형마다 dev F1 최대 · 격자 0.1 ~ 0.9(0.025) · dev 양성 10 미만이면 0.5 · 편입 대기 칸은 1.01(끔) |
| 시드 | 42 · 43 · 44. 시드 평균과 표준편차를 낸다 |
| 측정 불가 | 30건 미만인 칸 (D-40). 방향만 본다 |

- 스크립트는 골든에서 dev 를 다시 만들어 확률 CSV 의 id 와 대조한다. **다른 dev 로 잰 확률은 받지 않는다.**
- 문턱 규칙을 바꾸는 실험(목표 재현율 등)은 `--scheme` 으로 그 문턱을 넣어 잰다.

## 5. 통과 기준

Baseline 대비다. **실험을 돌리기 전에만 고친다.**

| 기준 | 내용 | 허용 |
|---|---|---|
| B | 6종 dev macro PR-AUC (시드 평균) 하락 | 0.02 이내 |
| G1 | 위반 탐지율(유형 있는 위반에 후보가 하나라도) 하락 | 2%p 이내 |
| G2 | 유형별 재현율 하락 — dev 양성 30 이상인 유형만 | 5%p 이내 |
| G3 | 음성(D · L) 오판정 증가 | +1행 이내 |

- **탈락** — 하나라도 넘으면.
- **채택 후보** — 탈락이 없고, ① PR-AUC 시드 평균이 +0.008 이상(시드 표준편차 0.004 의 두 배) **또는** ② 그 실험이 겨냥한 지표가 미리 적은 목표만큼 나아졌다.
- **겨냥한 지표를 먼저 적는다.** 실험마다 「무엇을 얼마로」를 돌리기 전에 실험 카드(7절)에 쓴다. 예 — 「유형 오인율 11.8% → 9% 이하」.
- **문턱을 맞춘 비교를 같이 낸다.** 재현율 기준(G1 · G2)은 문턱이 옮겨 가기만 해도 걸린다. 스크립트가 Baseline 과 같은 위반 탐지 수로 맞춘 자리의 수치를 함께 찍는다. **판정은 위 표로 하고**, 이 비교는 탈락이 품질 탓인지 문턱 탓인지 가르는 데만 쓴다.
- 채택 후보가 나오면 **다른 한 사람이 같은 설정으로 한 번 더 돌려** 재현되는지 본다.

## 6. test

- test(golden `test_sentence` 2,489행)는 봉인이다. **이 규약의 실험은 전부 dev 로만 고른다** (D-175).
- test 채점은 채택 후보에 대해 팀장 판정 뒤 1회다. 그 결과로 설정을 다시 고치지 않는다.
- 이미 잰 test 결과를 다시 세는 것은 진단으로 표시하고 문턱 · 규칙을 고르는 데 쓰지 않는다.

## 7. 실험 한 번의 순서

1. **실험 카드를 쓴다** (아래 양식) — 바꾸는 것 하나 · 겨냥한 지표와 목표.
2. 시드 42 · 43 · 44 로 학습한다. dev 묶음과 dev 와 같은 문구를 학습에서 뺀다.
3. 시드마다 dev 행별 확률 CSV 를 낸다.
4. 채점 스크립트를 돌린다 (`--target` 에 카드의 목표를 그대로).
5. 집계표(md)를 저장소에 올린다. 행 단위 목록 · 확률 CSV · 모델 zip 은 저장소 밖에 둔다.
6. 채택 후보면 다른 한 사람이 재현한다. 그다음 test 여부를 팀장에게 묻는다.

```
실험 이름:
담당 · 날짜:
Baseline 과 다른 점 (하나만):
겨냥한 실패 · 원인:            (예 — F1 유형 오인 · 거짓_과장 쏠림)
겨냥한 지표와 목표:            (예 — 유형 오인율 11.8% → 9% 이하)
잃어도 되는 것:                (예 — 위반 탐지율 −2%p 까지 = G1)
결과 (채점 뒤 채운다):
판정:                          탈락 / 통과 · 차이 없음 / 채택 후보
```

## 9. 저장소에 두는 것 · 두지 않는 것

| 둔다 | 두지 않는다 |
|---|---|
| 집계표(md · 건수만) · 실험 카드 · 노트북(출력 없이) · 채점 스크립트 | 행 단위 목록 · 행별 확률 CSV · 모델 zip · 노트북 실행 출력 · 문장 원문 |

행 단위 파일은 행별 정답이 드러나고(D-175), 인용 문구는 공개 저장소에 두지 않는다(D-249). 팀 공유 드라이브로 나눈다.

## 10. 2판 — 시드 평균 · Baseline 의 흔들림만큼 여유 (2026-10-08 · 박수진)

> 🔴 소성민(공동 규약) 확인 전이다. 확인되면 이 줄을 지운다.

### 왜 고치나

1판의 G1 · G2 · G3 는 **아무것도 바꾸지 않은 모델도 시드만 바꾸면 걸리는 폭**이었다. 판정을 「가장 좋은 시드 하나」로 해서 운이 크게 끼었다(카드 11 — 시드 44 만 위반 탐지가 높았다).

Baseline 재현(카드 9 노트북 · v10 과 같은 코드) 시드 42 · 43 · 44 를 각자의 문턱으로 잰 값:

| 지표 | 시드 42 · 43 · 44 | 범위 | 1판 허용 |
|---|---|---:|---:|
| 6종 PR-AUC | 0.7175 · 0.7080 · 0.7162 | 0.0095 | −0.02 |
| 위반 탐지 (/510) | 491 · 502 · 489 | 13행 (2.5%p) | −2%p |
| 음성(D · L) 오판정 (/86) | 17 · 21 · 18 | 4행 | +1행 |
| 질병_예방치료_표방 재현율 | 83.3 · 90.0 · 83.3% | 6.7%p | −5%p |
| 건강기능식품_오인 재현율 | 78.6 · 64.3 · 57.1% | 21.4%p | −5%p |
| 의약품_오인 재현율 | 51.4 · 62.2 · 45.9% | 16.2%p | −5%p |
| 거짓_과장 재현율 | 93.0 · 95.6 · 94.9% | 2.5%p | −5%p |
| 소비자_기만 재현율 | 63.3 · 53.1 · 46.9% | 16.3%p | −5%p |

(v10 의 원래 시드 42 · 43 · 44 도 거의 같다 — 위반 탐지 491 · 500 · 485 · 음성 17 · 21 · 18.)

### 2판의 규칙

| 항목 | 1판 | 2판 |
|---|---|---|
| 무엇끼리 견주나 | 가장 좋은 시드 하나 · 그 시드의 문턱 (PR-AUC 만 시드 평균) | **시드 3개 평균끼리** — 시드마다 자기 문턱(규칙대로)으로 잰 값의 평균 |
| Baseline | v10 (선택 시드 42 의 수 · 규약 1절) | **Baseline 재현 시드 42 · 43 · 44** (카드 9 노트북의 시드별 CSV) |
| B 6종 PR-AUC | −0.02 | −0.02 (그대로) |
| G1 위반 탐지 | −2%p | **−2.5%p** |
| G2 유형별 재현율 | 모든 유형 −5%p | **유형마다 max(5%p, 범위)** — 질병 6.7 · 건기식 21.4 · 의약품 16.2 · 거짓_과장 5.0 · 소비자_기만 16.3%p |
| G3 음성 오판정 | +1행 | **+4행** |
| 채택 후보 | 탈락 없음 + (PR-AUC +0.008 또는 목표) | 같다 |

- **여유를 범위로 잡은 까닭** — 시드 3개 평균끼리의 차이가 우연으로 날 수 있는 폭(약 2 표준오차 ≈ 1.63 σ)이 시드 3개의 범위(평균 ≈ 1.69 σ)와 거의 같다. 결과를 보고 정한 값이 아니라 Baseline 재현의 흔들림에서 기계적으로 나온 값이다.
- **G2 가 넓어진다** — 건기식 · 의약품 · 소비자_기만은 dev 양성이 37 ~ 98건이라 시드만 바꿔도 15 ~ 21%p 가 흔들린다. 이 세 유형에서 G2 는 큰 하락만 잡는다. 유형별로 더 좁게 보려면 dev 를 보강해야 한다(2절의 2판 dev).
- 채점 스크립트 `--rule v2` 로 잰다 — 이 모델 · Baseline 재현 모두 시드별 CSV 셋이 있어야 한다.

### 적용 범위

- **카드 13 부터** 적용한다. 2판은 카드보다 먼저 커밋한다.
- **이미 판정한 카드(1 ~ 12)의 판정은 바꾸지 않는다.** 2판으로 다시 읽은 값은 「2판 재판독 · 참고」로만 적는다.
- 지난 카드가 2판으로 통과로 읽혀도 그대로 채택하지 않는다 — **새 시드(45 · 46 · 47)로 같은 설정을 다시 돌리는 확인 카드**를 거친다. 2판의 값을 그 카드의 결과를 보고 정하지 않았다는 것을 그렇게 보인다.
