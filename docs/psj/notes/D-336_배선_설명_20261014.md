# D-336 「배선」이 뭔가 — D4-10 을 앱에 붙이려면 (2026-10-14 · 박수진)

**배선** = 앱 코드에서 **품목을 인코더까지 실제로 넘겨주는 연결**. 지금 앱은 인코더에 **문장 하나만** 넘기게 짜여 있어서, D4-10 처럼 **품목 + 문장**을 받아야 하는 모델을 꽂으면 제대로 못 돈다.

## 지금 앱 코드 (`app/encoder.py`)

```python
def predict(self, text: str) -> EncoderPrediction:
    inputs = self.tokenizer(text, truncation=True, max_length=self.scheme.max_tokens, ...)
```

- 입력이 **문장 하나**(`text`)뿐 — 품목을 받을 자리가 없다
- 문턱도 `label_scheme.json` 의 `label_thresholds` **한 벌만** 읽는다 — `label_thresholds_by_cat`(품목 앎 문턱)은 안 읽는다
- 그래프의 `encode` 노드는 문장마다 인코더를 **한 번** 부르고, 품목 분기(식품 · 건기식 · 화장품 …)는 그 결과 하나를 같이 쓴다

## D4-10 이 학습한 입력

```
[CLS] 화장품 [SEP] 가려움증을 없애 줍니다 [SEP]
[CLS] 모름  [SEP] 가려움증을 없애 줍니다 [SEP]
```

지금 앱에 그대로 꽂으면 품목 자리 없이 문장만 들어간다 → 학습 때 본 적 없는 입력이라 확률이 틀어진다. **에러 없이 조용히 엉뚱한 수를 내는 게 위험**하다. 그래서 모델 잠금(D-333)에 올리기 전까지는 앱이 이 폴더를 올리지 않는다.

## 배선 = 고칠 연결 세 군데

| # | 자리 | 지금 | 바꿀 것 |
|:-:|---|---|---|
| 1 | 인코더 로더 (`app/encoder.py`) | `predict(text)` · 문장만 · 길이 128 | `predict(품목, text)` · 토크나이저에 **(품목, 문장) 쌍** · 문장 쪽만 자름 · 길이 136 |
| 2 | 문턱 | `label_thresholds` 한 벌 | 「모름」 → `label_thresholds` · 품목 앎 → `label_thresholds_by_cat` (칸 이름은 팀장 판정) |
| 3 | 그래프 | 문장마다 한 번 · 분기가 같은 결과를 씀 | **기록 판정**(품목 미확정) → 「모름」으로 부름 · **품목 분기 · 재검수** → 그 품목으로 부름 · 분기 넷은 한 배치로 묶음(문장당 약 66 ms · 따로면 168 ms) |

전제 → 품목 입력 — 식품 → 식품 · 건기식_인정 · 건기식_비인정 → 건기식 · 화장품 → 화장품 · 일반상품 → 모름 (D-336 결정 3)

## 왜 test(봉인) 정식 회차가 이걸 기다리나

`eval_graph`(팀장 평가 도구 · 봉인 회차를 `sealed_runs.jsonl` 에 기록)는 **앱 그래프를 그대로 돌린다**. 위 세 가지가 끝나야 D4-10 을 정본 잣대로 잴 수 있다. 앱 코드는 팀장 담당이라 D-336 집행 요청 문서(`docs/psj/reports/판정인코더_D4-10_D-336집행요청_박수진_20261014.docx`)에 넣어 두었다.

- 모델 쪽(문턱 두 벌 `label_scheme.json` · 새 이름 폴더)은 준비 끝 — `make_d410_scheme.py`
- 그 전까지 판정 로직 성능은 프로토타입(`judge_stage2`)으로 dev 에서 잰 수를 본다 — 첫 판정 탐지 424.3 / 510 · 재판정 168.0 / 216 · 정상 문구 재판정 통과 92%
