# 인코더 파인튜닝 — 진행 상황 보고 (3주차 제출용)

- **작성**: psj (2026-09-16)
- **제출 목적**: 3주차 산출물 "머신러닝/딥러닝 학습결과서" / "학습한 ML/DL 모델"의
  **진행 상황 보고 대체** — 아래 사유로 실제 학습을 아직 수행하지 못했다.

## 현재 상태 요약

**실제 파인튜닝 학습은 아직 시작하지 못했다.** 이유는 학습 데이터(골든셋)가
로컬에 준비되어 있지 않기 때문이다. 원인과 진행된 부분을 아래에 정리한다.

## 1. 왜 아직 학습을 못 했나 — 데이터 공급 파이프라인 확인 결과

`preprocess/golden.py` 가 골든셋을 만드는 스크립트인데, 다음 두 입력 파일을 읽는다:

- `data/derived/golden/split_manifest.json`
- `data/derived/injected_golden.jsonl`

이 파일들이 **로컬 저장소에 존재하지 않는다.** `data/**` 는 `.gitignore` 대상
(원본 데이터의 재배포 제약 때문 — `docs/03_데이터/실측_2026-09-07.md` 참고)이라
git pull 로는 받을 수 없고, 각자 로컬에서 수집·전처리 스크립트를 돌려 만들어야
하는 산출물이다.

`/admin/api/counts` 로 실측한 결과, 로컬 DB의 `golden_sample` 테이블도 **0건**이다.
즉 데이터 자체가 이 컴퓨터엔 아직 적재되지 않은 상태다. 실제로 팀 어딘가에
골든셋이 얼마나 준비되어 있는지는 확인 요청을 넣어둔 상태다 (2026-09-16, 팀장 확인 중).

## 2. 진행된 부분 — 학습 데이터 스키마·파이프라인 설계

DB 스키마(`db/schema.sql`) 상 `golden_sample` 테이블은 이미 상당히 구체적으로
설계되어 있다. 학습에 쓸 라벨 구조는 다음과 같다:

| 항목 | 내용 |
|---|---|
| 판정 라벨 | `violations`(위반 유형 배열), `three_elem`(허위·오인·비방 3요소), `infeasibility` |
| 측정 축 (D-74) | `certainty`(확실성), `tense`(시제), `sent_type`(문장유형) — 3축 |
| 표면 변환 축 (D-91) | `surface_variant`(원형 S0 대비 표현 변형) — 정규화 층의 효과를 별도로 측정 |
| 생성 이력 | `origin`(수집/주입 구분), `rule_id`(변환 규칙), `provenance`(재배포 가능 여부 추적) |
| 평가 분리 | `split`(train/test_sentence/test_holdout 등) — 주입 데이터는 평가 split에 못 들어가게
  제약(`ck_golden_injected_not_holdout`)으로 강제 |
| 단위 | `unit`(문장/낱말) — 사례집(낱말 단위)과 의결서(문장 단위)를 같은 척도로 섞어 세지 않도록 구분 |

## 3. 인코더 모델 자체 — 확정 안 됨

`app/retrieve.py` 를 보면 임베딩 모델명은 코드에 하드코딩되어 있지 않고
`chunk_embedding.model_id` 컬럼(DB)에서 읽어오는 구조다. 즉 **어떤 베이스
인코더를 쓸지는 아직 코드/원장 어디에도 확정된 값이 없다.** 이전 인계 문서에
"인코더 백본이 실제로 `kcbert-base`인지" 확인이 필요하다는 메모가 있었던 것으로
보아, 팀 내에서도 아직 최종 확정 전 단계로 보인다 — 추측으로 단정하지 않는다.

## 4. 다음 단계 (블로커 해소 시)

1. 골든셋 데이터(`data/derived/golden/*`) 공급 경로 확인 — 팀장 확인 대기 중
2. 인코더 베이스 모델 확정
3. `preprocess/golden.py` 실행 → `golden_sample` 적재
4. 파인튜닝 실행 · 평가(D-74 3축 기준)

## 남은 리스크

- 골든셋 데이터가 팀 내에도 아직 준비되지 않은 경우, 파인튜닝 자체가 이번 주
  안에 불가능할 수 있다 — 이 경우 4주차 산출물 일정에 영향을 줄 수 있어 조기에
  공유가 필요하다.
