# 판정 근거(source) 등급 기준 — G0~G3 (D-15 · D-16 · D-106 기준 정리)

- **작성**: psj (2026-09-14, 2026-09-16 전면 수정)
- **상태**: 등급 체계 자체는 팀 확정(D-15·D-16·D-106) — 이 문서는 그 확정 내용을
  `/admin/sources` 화면 판정자가 참고할 체크리스트 형태로 정리한 것
- **범위**: `/admin/sources` 화면에서 `source.grade` 값(G0~G3)을 판정할 때 참고하는
  기준표. 2인 확인 절차 자체(제안→확인→이력, §8 ⑰)는 아직 팀 논의 중이고,
  이 문서는 그 절차가 참조할 "등급 판단 기준"만 정리한 것.

## ⬜ 2026-09-16 정정 — L1~L4 는 이 등급 체계가 아니었다

이 문서 초안(2026-09-14)은 목업 화면 안내문의 **"L1 법적 기준 → L2 행정 기준 →
L3 공식 참고 → L4 내부 검증"** 문구를 그대로 등급 기준표 제목으로 썼다. 이건
**틀린 전제**였다 — `source.grade` 컬럼의 실제 값은 `grade_t` enum
(`G0`/`G1`/`G2`/`G3`, `db/schema.sql`)이고, 이 등급은 **"근거의 신뢰도 서열"이
아니라 "이 소스를 어떤 용도로 써도 되는가"를 나타내는 이용조건 게이트**다
(D-15). L1~L4는 DB 어디에도 대응하는 값이 없는, 목업 디자인 단계의 표현이었다.

## G0~G3 정의 (D-15 · D-16 · D-106)

| 등급 | 정의 | 핵심 근거 |
|---|---|---|
| **G0** | 미표기·미확인 — 이용조건을 아직 확인하지 못함 | D-15. **fail-closed** — 확인 전까지 전 용도(U1~U4) 닫힘. 2인 판정으로만 G0 → 다른 등급으로 승격 가능 (D-66) |
| **G1** | 확인된 "허락 없음" — 배제 | D-106. "확인해봤더니 라이선스가 없다/거부됐다"로 **판명된** 상태. 수집 스크립트가 실행 자체를 거부한다. 🚨 G0(미확인)과 다르다 — G1은 **확인 결과가 배제**인 것 |
| **G2** | 사실만 취함 — 원문·해설 문장은 취하지 않음 | D-16. 2차 문서(협회 해설서 등)의 "사실"(예: 금지 표현 목록)은 원 출처(법령·고시)로 소급해서 취하지만, 협회의 해설 문장·편집·배열 자체는 저작물이라 취하지 않음 |
| **G3** | 원문 자유 | 원문을 그대로 보관·색인·인용·배포해도 되는 공개/허락된 소스 |

### 용도(U1~U4) × 등급 매트릭스 (D-15)

| | U1 학습 | U2 원문 색인 | U3 화면 인용 | U4 배포 |
|---|:-:|:-:|:-:|:-:|
| **G3** 원문 자유 | 가능 | 가능 | 가능 | 가능 |
| **G2** 사실만 | 가능 | deny | deny | 가능 |
| **G1** 배제 | deny | deny | deny | deny |
| **G0** 미확인 | deny | deny | deny | deny |

- **G2의 U2·U3 deny는 정책이 아니라 정의다.** 원문을 보관하지 않는 등급에서
  원문 색인·화면 인용을 열면 등급 표기 자체가 거짓이 된다.
- **G0은 fail-closed다.** 확인 전까지 전부 닫혀 있고, 2인 판정으로만 승격된다
  (D-66 four-eyes 원칙과 직결).
- 이 매트릭스는 `source_use` 테이블(`docs/02_설계/거버넌스데이터층_DDL.md`)로
  구현돼 있다 — `registry.require(src, use=...)` 가 미등록·G1이면 수집 자체가
  실행되지 않는다 (D-15).

## 판정자용 확인 순서 (실무 체크리스트)

1. 이용조건을 아직 확인 못 했다 → **G0** (fail-closed, 전 용도 닫힘)
2. 확인해봤더니 라이선스가 없거나 명시적으로 거부됐다 → **G1** (배제, 비교군으로도
   안 씀 — D-106)
3. 확인해봤더니 허락은 있지만 원문 자체를 보관·재배포하면 안 되고 "사실"만
   취할 수 있다(2차 문서의 해설·편집 저작권 등) → **G2**
4. 확인해봤더니 원문을 그대로 써도 된다(공공저작물, 명시적 허락, 라이선스 명확) →
   **G3**

⚠️ **"미확인"을 "아마 괜찮음"으로 읽지 않는다** (D-101). data.go.kr 접근 차단
등으로 이용허락범위를 못 읽은 채 G3로 매겨진 사례가 실제로 있었고, 그건 판정
실수였다. 근거의 `why`·`note`에 "미확인"·"확인 필요"·"불명"·"차단"류 표현이
있으면 등급을 낮추는 게 아니라 **더 자세히 검토해야 할 대상**으로 취급한다.

## 1차·2차 확인자 역할

- **1차 확인자**: 위 체크리스트를 따라가며 이용조건을 실제로 확인하고 등급을 제안
- **2차 확인자**: 1차 확인자의 "판단"을 재검토하는 게 아니라, 1차 확인자가 확인한
  **사실 근거**(라이선스 문서, 이용허락범위, 출처)가 실제로 그 등급 조건을
  충족하는지 같은 체크리스트로 다시 확인하는 역할. 이렇게 하면 재량이 줄어
  2인 확인이 형식적 서명이 아니라 실제 검증으로 작동한다 (D-66).

## 남은 결정 사항 (팀 논의 필요)

- `dict_entry`(표현 사전) 등록에도 이 체크리스트를 적용할지 — `dict_entry`는
  현재 2인 확인 제약이 스키마에 없음
- 화면에서 등급을 입력하는 흐름 자체(즉시 반영 vs 승인 대기 상태) — §8 ⑰
- `grade_decided_by`/`grade_reviewed_by`를 채우는 주체가 항상 `governor`
  역할이면 되는지, 별도 권한이 필요한지
