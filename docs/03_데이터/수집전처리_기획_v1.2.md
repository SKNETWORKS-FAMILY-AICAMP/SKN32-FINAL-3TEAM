## 1. 역산 — 태스크에서 데이터로

**소스를 먼저 나열하면 「모을 수 있는 것」을 모으게 됩니다. 태스크에서 역산하면 「모아야 하는 것」이 나옵니다.**

| # | 태스크 (기획서 5-1) | 담당 | **필요 데이터의 최소 형태** | 없으면 죽는 것 | 조달 층 |
|:-:|---|:-:|---|---|:-:|
| 1 | **카테고리 판별** (4클래스) | 인코더 | `(광고문구, 제품카테고리)` 쌍 | **파이프라인 첫 단계.** 여기가 틀리면 적용 법령이 통째로 틀림 | 1·2층 |
| 2 | **위법 유형 판정** (8클래스) | 인코더 | `(문장, 위법유형[다중], 근거조문)` | 제품 본체 | **1·2층** |
| 3 | **3요소 다중 라벨** | 인코더 | `(문장, 거짓과장성/오인성/저해성)` | 표시광고법 사건의 판단 구조 재현 | 1층 (의결서) |
| 4 | **위험도 순서형** (4등급) | 인코더+코드 | `(위법유형 → 제재수준)` 매핑표 + 실제 처분 레코드 | *"걸리면 얼마나 무는가"* — 제품의 절반 | **4층** |
| 5 | **질의 의도 분석** (5클래스) | 인코더 | `(질의, 의도)` — **자체 작성 가능** | 두 진입점 라우팅 | 자체 |
| 6 | **문장↔금지유형 매핑** | cross-encoder | `(문장, 금지유형)` 쌍 + negative | 리랭킹 트랙 전체 | 2·3층 |
| 7 | **주장 스팬 추출** (BIO) | 인코더 | `(문장, 주장 span 오프셋)` | **주장 원장** — 발표 핵심 지표 3번 | 파생 (4-6절) |
| 8 | **RAG 근거 제시** | 검색 | 조문·고시·별표 청크 + `effective_date` | 인용 검증·근거 서술 | **3층** |
| 9 | **사례 검색** | 검색 | 제재 사례 청크 + 유형 태그 | 위험도 설명의 설득력 | 1·4층 |
| 10 | **대체 문구 생성** | sLLM | **시정 전/후 페어** + 정답 문체 코퍼스 | 진입점 A의 출구 | 1·2층 |
| 11 | **금지표현 정확매칭** | 코드 | 금지 표현 **사전**(문자열 목록) | 위험도 **하한** + 이질적 판정기 B | **2·3층** |
| 12 | **세그먼트 도출** | ML | 리뷰/VOC 텍스트 + 인구통계 집계 | Phase 3 전체 | **6층** |
| 13 | **지향 키워드 후보** | 코드+ML | **인정 기능성 문구 원문** + 심의 통과 문구 | 진입점 B의 어휘 공간 | **2층** (v2.4 정정) |

### ★ 역산에서 드러난 것 셋

**① 5번(질의 의도)은 수집 대상이 아닙니다.** 5클래스 × 40건 = 200건을 **팀이 직접 작성**하면 끝납니다. 수집 계획에 넣으면 시간만 씁니다. **1W 공동작업 1시간**으로 배치합니다.

**② 7번(주장 스팬)도 수집 대상이 아니라 파생물입니다.** 결함 주입 시 **어느 구간을 변형했는지 좌표를 그대로 기록**하면 BIO 라벨이 공짜로 나옵니다 (4-7절). 별도 라벨링 0시간.

**③ 🚨 4번(위험도)의 라벨은 「규정」과 「실제 처분」 두 곳에서 나옵니다.**

```
규정 경로 :  시행규칙 [별표] 행정처분 기준  ->  위반유형 -> 처분   (연역 · 결정론)
실측 경로 :  식약처 행정처분결과 API        ->  실제 부과된 처분   (귀납 · 분포)
```

기획서 4층은 **규정 경로만** 적었습니다. 실측 경로(2-0절 발견 ①)를 더하면 **QWK 평가의 정답을 규정에서 만들고, 분포 검증을 실측으로** 할 수 있습니다. 두 경로가 갈리는 지점이 곧 **감경·가중 사유**이고, 그것이 「주의 vs 처분」 경계 학습 데이터입니다.

#### 🔄 AI Hub — v1.1 정정 (D-71)

**v1.0에서 「배포 모델 학습 금지」로 판정했는데 틀렸습니다.** 이용정책 본문의 재배포 금지 조항을 보고 `U4`가 막힌 것으로 읽었고, 전파 규칙을 적용해 `U1`까지 막았습니다. **FAQ에 명시적 허용이 있었습니다.**

> - 다운로드 받은 데이터로 학습하여 만들어진 **AI모델과 서비스는 자유롭게 배포, 활용**하실 수 있습니다.
> - 개발한 모델을 **영리적으로 판매, 활용하는 행위는 제한하지 않으나** AI허브 데이터를 사용하였음을 명시하여야 합니다.
> - 다만 사전 협의한 경우를 제외하고 **데이터를 재가공하여 배포하는 행위**는 원칙적으로 불가합니다.

**막히는 것은 「데이터 재배포」이지 「모델·서비스 배포」가 아닙니다.** 두 축을 하나로 뭉갠 것이 오판의 원인이고, 그래서 **제약 플래그 `NOREDIST`를 신설해 축을 분리**했습니다.

```
U4        모델·서비스 배포          ←  용도 축 (U1~U4)
NOREDIST  데이터 재가공·배포 금지   ←  제약 플래그 (BY/NC/SA/PII/TOS/GATED와 같은 층)

배포 모델 학습 = { f | f.U1 AND f.U4 }     ← NOREDIST는 여기 걸리지 않는다
데이터셋 공개  = { f | NOREDIST 없음 }
```

### 4-2. [P2] 정규화 — 🚨 비파괴가 핵심

> 🔄 **v1.2 — 이 절의 계약은 [`docs/03_데이터/전처리_사양.md`](../03_데이터/전처리_사양.md) 으로 이관됐습니다 (D-84 ①).**
> 아래는 요약이고, **필드 이름과 규칙 ID의 단일 출처는 그쪽**입니다. 규칙표에 **N7(한자 음차)** 이 추가됐고,
> 🚨 **N4(구분자 제거)는 전역 치환이 아니라 사전 어휘 구간에만 적용**합니다 — `비타민 C` 의 공백까지 지우면 정상 표현이 깨집니다.

**광고 문구에는 회피 표기가 실재합니다.** `다ㅇㅣ어트`, `치·료`, `면역ㄹㅕㄱ`, `ｄｉｅｔ`. 그런데 정규화를 원문에 파괴적으로 적용하면 두 가지가 깨집니다.

```
① 원문 오프셋이 깨진다  ->  하이라이트 UI · 주장 스팬 BIO 라벨이 전부 어긋난다
② 🚨 회피 표기 자체가 위법 신호다  ->  정규화로 지워버리면 그 신호를 잃는다
```

**따라서 원문·정규화문·오프셋 매핑을 함께 보관합니다.**

```python
@dataclass
class NormalizedText:
    raw: str                    # 원문 (표시·오프셋 기준)
    norm: str                   # 정규화문 (매칭 기준)
    offset_map: list[int]       # norm[i] -> raw 의 시작 오프셋
    evasion_flags: list[str]    # ["JAMO_SPLIT", "SEP_INSERT", "FULLWIDTH"]
```

**규칙표**

| # | 규칙 | 예 | 파괴적? |
|:-:|---|---|:-:|
| N1 | 유니코드 **NFKC** 정규화 | `ｄｉｅｔ` → `diet` | 매핑 보존 |
| N2 | 제어문자·zero-width 제거 | `치​료` → `치료` · 플래그 `ZWSP` | 매핑 보존 |
| N3 | **자모 분리 복원** | `다ㅇㅣ어트` → `다이어트` · 플래그 `JAMO_SPLIT` | 매핑 보존 |
| N4 | **구분자 삽입 제거** | `치·료`, `치.료`, `치*료` → `치료` · 플래그 `SEP_INSERT` | 매핑 보존 |
| N5 | 반복 문자 축약 | `대박!!!!!` → `대박!!` | 매핑 보존 |
| N6 | 공백 정규화 (연속 공백 → 1칸) | | 매핑 보존 |
| N7 | 🚨 **이모지는 제거하지 않는다** | 이모지가 문장 경계 신호 | — |
| N8 | 🚨 **대소문자·숫자는 건드리지 않는다** | 수치가 판정 대상 | — |

> ★ **`evasion_flags` 는 버리는 부산물이 아니라 피처입니다.** 회피 표기가 있다는 것은 **작성자가 위법성을 인지하고 있었다**는 신호이므로, 위험도 인코더의 입력 피처로 넣고 **가산 근거로 기록**합니다 (안전 방향 단조성 — 올리기만 하므로 기획서 3-5절 원칙과 정합).

### 4-3. [P4] 문장 분할 — 광고 텍스트는 마침표가 없습니다

**일반 문서용 분할기를 그대로 쓰면 상세페이지 한 장이 문장 1개가 됩니다.**

|:-:|---|---|

### 4-7. ★ [P10] 결함 주입 — 시정 변환의 역함수

> **★ 이 절이 이 문서의 핵심 설계 기여입니다.**
>
> 기획서에는 두 개의 규칙이 **따로** 있습니다.
> - **5-4절 결함 주입**: 승인 문구 → 위법 변형 (골든셋 생성)
> - **5-7절 변환 규칙 R1~R3**: 위법 문구 → 시정 (sLLM 학습 데이터)
>
> **이 둘은 같은 규칙표의 양방향입니다.** 하나만 만들어 두 번 씁니다 — *"하나를 만들어 두 번 쓴다"* 는 이 프로젝트의 철학과 정확히 같은 구조입니다.

```
     [적법 문구]  ──── 정방향(주입) ────>  [위법 문구]
          ^                                     |
          └──────── 역방향(시정) ───────────────┘

  정방향 산출 : 골든셋 (정답을 아는 위법 샘플)      -> 인코더 학습·평가
  역방향 산출 : (위법, 시정) 페어                    -> sLLM SFT
  ★ 부산물   : 변형 구간 좌표 = 주장 스팬 BIO 라벨   -> 라벨링 비용 0
```

> 🔄 **v1.1 — 이 양방향성이 D-74로 확정됐습니다.** D-25(결함 주입)와 D-26(시정 페어 귀납)이 각각 규칙을 만들고 있었는데, 둘이 같은 변환의 반대 방향입니다. **규칙표를 하나만 유지합니다.**

|:-:|---|---|
| 1 | **1문장당 1규칙만 적용** | 다중 라벨이 되면 유형별 Recall 분리 보고가 흐려짐 |
| 2 | **변형 전/후 오프셋을 반드시 기록** | ★ 주장 스팬 BIO 라벨이 여기서 나옴 |
| 3 | 🚨 **원본 문구도 `V0` 라벨로 함께 넣는다** | 안 넣으면 골든셋이 전부 위법 → 기획서 5-3절 클래스 불균형 재발 |
| 4 | **유형별 목표량을 먼저 정하고 역산 배분** | 유형당 **최소 150건** (train 120 / dev 30) |
| 5 | 🚨 **주입본은 절대 test_holdout 에 넣지 않는다** | 평가는 **실사례 홀드아웃**으로만 (4-8절) |
| 6 | 변형 규칙 ID를 샘플에 기록 (`rule_id`) | **규칙별 검출률 분리 보고** 가능 |
| 7 | 🔄 **주입과 동시에 측정 축 3종을 채운다** (4-6절 ⑤) | T9 → `시제=과거`, T1 → `확실성=확실`. **규칙이 곧 라벨** |
| 8 | 🔄 **`provenance` · `redistributable` 을 모든 행에 기록** | AI Hub 유래가 섞이면 골든셋 전체를 공개 배포할 수 없다 (D-71) |

### 4-8. [P12] 골든셋 분할 — 🚨 출처 분리

**무작위 분할은 누수입니다.** 같은 의결서의 문구가 train과 test에 섞이면 F1이 부풀려집니다 (기획서 6-2).

| 분할 | 출처 | 용도 |
|---|---|---|
| **train** | 공정위 의결서 (전체의 80%) + **주입 골든셋 전량** | 학습 |
| **dev** | 공정위 의결서 (20%) + 주입 dev | 하이퍼파라미터 |
| 🚨 **test_holdout** | ★ **협회 심의 사례 · 식약처 보도자료 · 행정처분 API** | **평가 전용** |

**규칙 넷**

1. **분할 키는 `doc_id`** (문장이 아니라 문서). 같은 의결서의 문장은 전부 같은 분할로.
2. 🚨 **test_holdout 에는 주입본을 넣지 않는다.**
3. **유형별 건수를 분할 직후 집계**하고, **30건 미만 유형은 「측정 불가」로 마킹**한다 (기획서 6-3).
4. 분할 결과를 `derived/golden/split_manifest.json` 에 **시드와 함께 고정**한다.

```json
{"seed":20260828,"split_at":"2026-09-XX","dataset_version":"v0.3",
 "counts":{"train":{"V1":142,"V2":118,...},
           "test_holdout":{"V1":34,"V2":31,"V7":11}},
 "unmeasurable":["V7"],
 "source_sets":{"train":["ftc_decisions_bulk"],
                "test_holdout":["kfia_approved","mfds_press","mfds_sanctions"]}}
```

> ★ **`unmeasurable` 필드를 스키마에 넣는 것이 이 설계의 정직성입니다.** 발표에서 *"V7은 표본 11건이라 측정 불가로 보고합니다"* 라고 말할 수 있게 하는 것은 슬라이드가 아니라 **이 JSON 한 줄**입니다.
