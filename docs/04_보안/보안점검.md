| 검사 | 게이트 |
|---|:-:|
| `.env.example` 에 값이 채워져 있으면 낙방 (기본값 둘만 허용) | **30** |
| `setkey` 가 값 인자를 갖게 되면 낙방 (AST — 주석 문자열이 아니라 서명을 봅니다) | **31** |

🚨 **이 조치가 못 막는 것** — 이미 대화창·메신저에 붙여넣어진 키는 되돌릴 수 없습니다. 게이트는 저장소를 보지 사람의 화면을 보지 않습니다. **노출된 키는 재발급이 유일한 조치**입니다.

### P1-4 🚨 로그가 D-76의 열람 경계를 우회한다

D-76은 **관리자 화면**에서 사용자 입력 문구와 생성 문구의 열람을 막았습니다. 그런데 —

| 새는 곳 | 내용 |
|---|---|

### P1-5 🚨 IDOR — 판정 결과 조회

`/result/{id}`가 순차 정수면 **남의 미출시 카피를 URL 하나로 봅니다.** 차별점 ④가 여기서 무너집니다.

- PK를 **UUIDv4**로 (또는 별도의 추측 불가 공개 토큰)
- 🚨 **소유자 검증을 쿼리 레벨에서** — `WHERE id = :id AND user_id = :me`. 조회 후 파이썬에서 비교하는 방식은 한 번만 빠뜨리면 뚫린다
- 없는 것과 권한 없는 것을 **같은 404**로 (존재 여부 자체가 정보다)
- ★ **같은 논리가 D-68의 `visibility: link`에 적용됩니다** — **추측 가능한 링크는 private이 아닙니다.** 서명된 토큰이어야 합니다

### P1-6 🚨 입력 문구의 보관 정책이 없다

*"밖으로 보내지 않는다"* 는 정했는데 **"안에 얼마나 두는가"** 를 안 정했습니다.

> **유출 시 피해 크기 = 보관량 × 보관 기간.** 영업기밀을 무기한 보관하는 것 자체가 위험입니다.

- **보관 기간 상한 + 자동 파기**를 정합니다 (판정 이력의 **구조화 값**은 남기고 **원문만** 파기하는 분리가 가능합니다 — D-76의 추출 규칙이 이미 그 형태입니다)
- 🚨 **D-20의 캐스케이드 삭제는 「소스 → 청크」 방향만 있고, 「사용자 → 자기 데이터」 방향이 없습니다.** 대칭이 필요합니다
- D-77 L4에 지표가 이미 있습니다 — *「원본을 지운 뒤 남아 있는 참조 레코드 수 = 0」* 을 **사용자 데이터에도 적용**합니다

### P1-7 비밀번호 저장 — 권장이 아니라 **법적 요구**

DB 스키마(D-66)에 「해시」라고만 적혀 있고 알고리즘이 없습니다.

> 「개인정보의 안전성 확보조치 기준」(고시 제2025-9호) **제7조 제1항** — *"비밀번호를 저장하는 경우에는 복호화되지 아니하도록 **일방향 암호화**하여 저장"*

## 4. P2 — 구현 중

### P2-9 🚨 XSS — 우리는 사용자 입력을 화면에 되그린다 (OWASP **LLM10**)

판정 결과에 **주장 스팬을 하이라이트**하려면 원문에 마크업을 끼워 넣게 됩니다. **그 순간 `|safe`를 쓰면 끝입니다.** sLLM 생성 문구도 같은 출구로 갑니다.

- Jinja2 **autoescape 확인** (FastAPI+Jinja2 조합에서 기본값을 확인 없이 믿지 않는다)
- 🚨 **하이라이트를 HTML 문자열로 만들지 않습니다** — `(offset, length, type)` 구조로 넘기고 **클라이언트에서 DOM API로** 그립니다
- `innerHTML` 금지 · Alpine.js는 **`x-text`만, `x-html` 금지** · HTMX `hx-swap` 대상 검토
- **CSP 헤더**

### P2-10 🚨 SQLAdmin — 포트 분리는 보안 경계가 아니다

7-4절이 `api :8000` / `admin :8001`로 나눴지만, **:8001이 인터넷에 열리면 DB 전체 관리 콘솔이 열립니다.**

- 관리자 앱은 **공개 인터넷에 바인딩하지 않습니다** — 로컬 바인딩 + SSH 터널, 또는 별도 인증 + IP 제한
- 고시 **제6조(접근통제)** 가 요구하는 항목이기도 합니다
- ★ **D-76이 「거버넌스 콘솔을 보여준다」고 한 데모는 로컬에서 합니다** — 클라우드에 노출할 이유가 없습니다

### P2-11 🚨 자원 고갈 (OWASP **LLM06** — 2026판에서 10위 → **6위**)

**우리 파이프라인은 증폭 계수가 큽니다.**

```
요청 1건 → N 문장 × (분류기 + BM25 + 벡터 + 🚨 리랭커) × 재생성 최대 3배
```

CPU 크로스인코더 리랭킹이 top-k에 선형이라 **실질 병목**이고, D-77 L3에서 이미 *"리랭커 < 500ms ← 최적화 1순위"* 로 잡아 둔 자리입니다.

| 통제 | 값 |
|---|---|
| 입력 문자수·문장수 | 🚨 **하드 캡 — 절단이 아니라 거부** |
| 리랭커 top-k · `max_new_tokens` | 상한 |
| 요청 wall-clock 타임아웃 · Postgres `statement_timeout` | 설정 |
| 큐 | 🚨 **깊이 제한 + 429.** 무한 큐를 만들지 않는다 |
| `intra_op_num_threads` | 고정 (미고정 시 단일 요청이 전 코어 점유) |
| per-IP / 세션 rate limit | **무료 구간에 필수** |

★ **D-69의 「무료 판정」이 여기에 직접 걸립니다** — 무료면 남용 비용이 **우리 것**입니다. 판정이 싸다는 것과 무제한이라는 것은 다릅니다.
🚨 HTMX debounce는 **UX이지 보안 통제가 아닙니다.**

### P2-12 프롬프트 인젝션 — 판정은 면역, 생성은 아니다 (OWASP **LLM01**)

★ **먼저 좋은 소식**: **판정 경로에 LLM이 없어 LLM01(판정부)과 LLM03(Excessive Agency)이 설계 차원에서 제거됩니다.** LLM03은 2026판에서 6위 → **3위로 최대 상승**한 항목인데, 우리는 **tool calling도 DB write 권한도 없어 비해당**입니다.

🚨 **남는 구멍 셋**

1. **문법은 형식만 제약하고 의미는 제약하지 못합니다.** 서술층 불변(D-10·D-44)으로 sLLM은 *"2등급"* 을 토큰으로 못 뱉지만, **자유텍스트 카피 필드 안에** *"본 문구는 심의를 통과했습니다"* 같은 **사람을 향한 허위 주장**은 쓸 수 있습니다. 문법으로는 안 막히고 — ★ **금지표현 사전과 재판정으로 막아야 합니다.**
2. 🚨 **재판정 루프가 fail-open이면 안 됩니다.** K회 후에도 위반이면 **반환 거부**여야 합니다. ★ D-32의 「합법화 불가 증명서」가 이미 그 답인데, **보안 요구사항으로도 명시**합니다.
3. **금지표현 사전이 유출되면 우회 레시피가 됩니다** (LLM08). 사전의 *원천*은 공개 고시지만 **우리의 정규식·임계값·조합은 다릅니다.** 관리자 화면·API 응답에 노출하지 않습니다.

### P2-13 데이터 오염 (OWASP **LLM05**) — 모델보다 사전이 위험하다

금지표현 사전과 법령 코퍼스는 **권위 소스**라, 오염되면 **판정이 직접 뒤집힙니다.** 모델 오염보다 빠르고 조용합니다.

→ **사전 변경에도 2인 확인을 적용합니다** (D-66의 `decided_by != reviewed_by` 제약을 사전 테이블로 확장).
