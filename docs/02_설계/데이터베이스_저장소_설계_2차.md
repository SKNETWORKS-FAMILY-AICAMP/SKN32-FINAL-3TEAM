### 4-1. 🆕 넓게 한 번 찾고 법별로 거른다 (판정 그래프 설계 · 원장 ㊲ ㊳)

- `rt.wide()` — 원 SQL 을 `row_number() OVER (PARTITION BY law ORDER BY 거리/점수)` 로 감싸 **법마다 폭만큼** 받는다(`_per_law()`). 판정 그래프의 법 노드는 `law_view()` 로 **갈래마다 먼저 거른 뒤 섞는다** — 섞은 뒤 거르면 순위가 부풀었다(6 vs 2)
- 동치 — 법 필터는 `WHERE` 한 줄이고 거리 · `ts_rank_cd` 는 행과 질의만으로 정해지므로, 법마다 따로 찾은 것과 같다. 기기 실측 **124/124 「=」**(질의 31 × 법 범위)
- 비용 — 인덱스가 없어 어차피 전 행 거리를 셈하므로 법 안 순번이 더하는 몫이 작다. 기기 조회 중앙 **전역 251 ms / 법마다 246 ms**(인코딩 포함 · 31건)
- `search()` 는 그대로다 — 화면 검색 경로는 바뀌지 않았다(후보 폭을 융합한 뒤 규범당 상한 `per_law_cap` 2 를 걸고 상위 5 를 자른다 · 09-27)

## 7. 1차 체크리스트는 어떻게 됐나

| 1차 항목 (`DB_스키마.md` 「W1에 반드시」) | 2차 |
|---|---|
| 청크 · 학습샘플 · 사전에 `fragment_id` FK | ✅ (1차에 이미 확인) |
| 소스 단위 캐스케이드 삭제 스크립트 + 테스트 | 🟡 DDL 실측에서 `DELETE FROM source` 한 줄로 9개 표가 0 이 됐다(1차 제출본 §1-1 ②) · 운영용 스크립트 · 게이트 테스트가 있는지는 **이번에 확인하지 않았다**(D-188) |
| alembic `upgrade → downgrade → upgrade` 왕복 검증 | ⬜ 기록을 못 찾았다(1차와 같음) · `tests/test_db_schema.py` 는 downgrade 의 **모양**만 본다 |
| 세그먼트 `source_set_version` → 재학습 트리거 | ⬜ 6층 미수집이라 대상 없음 |
| k-익명성 `K_MIN` | ⬜ 같음 |
| 사용자 입력 행 `consent` | 🟡 문서 단위(`work_doc.consent_store` · `consent_train` · D-128) — 행 단위는 없다 |
| 문장 · 청크 `raw` / `norm` / `offset_map` | 🟡 문장은 있다 · 청크는 `text`(인용)/`context`(검색)로 갈랐다(D-158) |
| 나머지(`is_public` · 2인 확인 CHECK · `surface_variant` · `provenance` · `subject_type` · `image_description`) | ✅ 1차에 확인 · 변동 없음 |
