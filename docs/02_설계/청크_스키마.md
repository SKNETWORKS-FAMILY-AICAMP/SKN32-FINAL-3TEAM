## 필수 메타데이터 (기획서 4-5 + 실제 스키마)

🔄 **2026-09-12 밤 — 이 표가 실제 스키마와 갈려 있었다.** 08-31 이후 `chunk` 에 일곱 칸이
늘었는데(`paragraph`·`item`·`paragraph_no`·`context`·`token_count`·`tsv`·`doc_type`) 표는
그대로였고, 그 사이 **하나는 만들어 놓고 아무도 안 읽는 값**이 되었다(`part` · D-199).
계약 문서가 낡으면 「없는 칸」과 「안 적은 칸」이 구별되지 않는다.

| 필드 | 타입 | 설명 |
|---|---|---|

| `fragment_id` | fk | 🚨 필수 — 캐스케이드 삭제 경로 (D-20) |
| `doc_id` | fk | 원문서 |
| `law_id` | str | 법령/고시 식별자 |
| `article` | str | 조 — 「제8조」·「제8조의3」 |

| `item` | str | **호 — 「1.」** |
| `paragraph_no` | smallint | 항 서수 — 원문에 항번호가 없어도 우리가 센 것. 호의 31%(283/909)가 그렇다 (D-117 · 0008) |
| `context` | text | **자립 텍스트** = 조 제목 + 항 본문. 임베딩 입력이자 화면 문맥 (0008). 🔄 **별표는 별표 제목 + 상위 항목**(2026-09-24 · 짧은 목록 청크가 벡터 상위를 점령해서). 🚨 NULL=미적재 · ''=붙일 문맥 없음 |
| `part_no` / `part_total` | smallint | 🆕 **쪼갠 조각 번호/총수** (0011 · D-199). `part_total > 1` 이면 **이 근거는 조문의 일부**다 |
| `doc_type` | str | 법령 / 별표 |
| `law` | text | 🔄 **법 축** — 표시광고법 / 식품표시광고법 / 화장품법 / 건강기능식품법. **법 ID 로 정한다** (0019 · W6 · D-271 ①). 대응표 `collect/law_map.py`. ⛔ 종전 `category text[]`(일반 / 식품 / 건기식 / 화장품)는 낱말로 정해 265청크가 「일반」으로 떨어졌다 |
| `text` | text | **인용 단위** — 한 글자도 안 바꾼다 (D-158) |
| `token_count` | int | `text` 의 토큰. `ck_chunk_tokens(512)` 가 보는 축 |
| `input_token_count` | smallint | 🆕 **`embed_input()` = context + text 의 토큰** (0011 · D-200). **상한 CHECK 없음** |
| `tsv` | tsvector | 생성열 — 어휘 색인. `context + text` (0010 · D-193) |
| `effective_date` | date | 🚨 개정일 — 현행 기준 필터 (2026.7.1 과징금 고시 사례) |
| `superseded_at` | date | 폐지 — 삭제가 아니라 필터 |
| `exempt_of` | text | 🆕 **적용 제외 목이면 그 목을 제외로 만든 단서 목(부모)의 경로**, 아니면 빈 문자열 (0021 · 2026-09-28 · D-238 개정 (나)). 「다만 … 제외한다」의 하위 목은 해당하면 위반이 **아닌** 경우다 — 검색은 그대로 찾고, 위반 근거 좌표는 부모로 올린다(`app/retrieve.py` `basis_citation`). 🚨 NULL=미적재 · ''=제외 목이 아니다 — 둘을 합치지 않는다. NULL 인 별표 청크에는 위반 근거 좌표를 세우지 않는다. `ck_chunk_exempt` — 값은 **별표 청크만** 든다(조문 쪽 단서는 아직 안 가른다 ⬜). 값은 `preprocess/chunk.py` 가 `preprocess/law_norm.exemption_parents()` 로 계산한다. 🔴 열 자리는 **맨 끝**이다 — 옮긴 DB 는 `ADD COLUMN` 으로 끝에 붙고 뷰가 `c.*` 다 |
| `embedding` | vector(1024) | `chunk_embedding` 에 별도 표. `model_id`·`input_sha256` 동반 (D-176) |

⬜ `source_grade` 는 **이 표에 두지 않는다** — `fragment` → `source` 조인으로 읽는다.

## 검색 갈래 (2026-09-12 · D-167 · D-193)

기획서 5-6 의 파이프라인이 정본이다.

```
문장 -> [BM25 + 벡터 하이브리드] 상위 50      <- POOL. **잠정값**이다 (D-205)
              v
      [cross-encoder 리랭커] 상위 5           <- 미착수. 모델 미선정
              v
      [인용 검증: 코드]  존재가 아니라 **일치**까지
```

🔄 **실물(2026-10-06 대조 · `app/retrieve.py`)** — 리랭커 자리가 비어 있는 동안 두 갈래는 **순위 융합(RRF · `fuse`)** 으로 합친다(D-193). 부르는 문이 둘이다.

```
화면 검색   search()   두 갈래 후보 폭(50) -> RRF -> 규범당 상한 diversify(per_law_cap 2) -> 상위 top_k(5)
판정 그래프  wide()     법 필터 없이 한 번 · 두 갈래를 **법마다 폭만큼** 받는다 (섞지 않고 따로)
            law_view() 법별 노드가 **자기 법 것만 거른 뒤** 섞고(RRF) 규범당 상한을 건다
```

- **규범당 상한**(`diversify` · `per_law_cap` 2 `[임의]` · 2026-09-27) — 한 규범(`law_id`)이 상위 `top_k` 를 다 차지하지 못하게 한다. 넘친 것은 버리지 않고 뒤로 민다 — 후보 폭 안에서 순서만 바뀐다. 후보 폭 전체를 합친 **뒤에** 걸고 자른다(자른 뒤에 걸면 밀려난 자리를 못 채운다).
- **넓게 한 번 찾고 법별로 거른다**(D-291 · 2026-09-28) — 섞은 뒤 거르면 다른 법 청크가 순위를 부풀린다. 법마다 폭만큼 받으므로 거른 결과는 법 필터로 따로 찾은 결과와 같다.
