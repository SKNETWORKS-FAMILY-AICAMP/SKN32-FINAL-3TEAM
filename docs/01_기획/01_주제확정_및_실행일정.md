> 🚨 **BFF 는 화면 전용 백엔드다. 판정 코어 API 는 팀장이 하나만 만든다** — 둘로 나누면 판정 게이트가 두 벌이 된다 (D-90 · D-119).
> ⚠️ 위 표의 주차별 칸은 사실원장 「팀」의 배정을 공식 주차에 얹은 것이다 — **배포 담당은 아직 미배정**(사실원장에 없음). 🔄 *2026-09-21 — 사실원장 「팀」이 **소성민**(배포·운영 · D-208)으로 적고 있다*
> 🔄 종전 「W9부터 화면·배포를 인코더 A 로 이관」 규칙(D-50)은 **전제가 바뀌어 폐기** — 팀원이 화면·BFF 를 세트로 맡으므로 이관 자체가 필요 없다. T4 단일 장애점 대응은 「2인 페어」에서 **「계약(`app/contracts.py` · 골든 픽스처 · 계약 테스트)」** 으로 바뀌었다 (D-124).

## 6. 발표 준비 (7W~9W)

### 6-1. 데모 시나리오 — 두 장면 고정

```
[장면 1 - 진입점 A, 30초]
  위법 문구 붙여넣기
    -> 문장별 빨간 줄 + 근거 조문 + 위험도
    -> 대체 문구 3종 세트 (본문 + 필수 병기 문구 + 배치 지시)
    -> 재판정 통과 O

[장면 2 - 진입점 B, 45초]  ★ 하이라이트
  제품/세그먼트 선택
    -> 지향 키워드 칩: 초록 9개(통과) + 회색 3개(차단)
    -> 회색 칩 hover: "'눈 피로 회복' = 질병 표방 / 식품표시광고법 제8조"
    -> 통과 칩으로 카피 3안 -> 프론티어에 3점
    -> 균형안 클릭 -> 본문 + 병기 문구 + 배치 + 근거
```

> ★ **차단된 회색 칩이 데모의 핵심입니다.** 생성 도구가 아니라 **판정 코어를 품은 생성 도구**임이 한 화면에 보입니다.

### 6-2. 반드시 준비할 답변 3개

| 질문 | 준비된 답 |
|---|---|
| *"**심의 도구 B** 같은 게 이미 있지 않나요?"* | **우리가 먼저 인정합니다.** 그다음 — 선행 도구는 **건기식 단일 법령·검수 전용**. 우리는 **다법령 라우팅 + 판정 코어가 곧 생성기의 리워드 모델 + 진입점 B**. ⚠️ 「위험도 정량화」는 차별점에서 뺐습니다 |
| *"페르소나가 실제 소비자를 대변한다는 근거는?"* | **없습니다. 그래서 그 주장을 하지 않습니다.** 우리가 주장하는 것은 **「세그먼트 언어 정렬」**까지이고, 전환율은 말하지 않습니다 |
| *"취약계층을 정밀 타깃하는 것 아닌가요?"* | **먼저 인정하고 먼저 대응책을 제시합니다** — pain point 축을 **설계에서 제거**했고, 취약 세그먼트 감지 시 **판정 임계값을 강화**합니다 |
