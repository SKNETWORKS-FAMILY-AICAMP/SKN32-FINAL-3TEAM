## 3. DB `CHECK` 제약 — 행 단위 (PostgreSQL 16 실증 완료)

| 제약 | 막는 것 | 근거 |
|---|---|:-:|
| `ck_source_four_eyes` — `grade_decided_by <> grade_reviewed_by` | 혼자 판정하고 혼자 검토하는 것 | D-66 |
| `ck_golden_injected_not_holdout` | 🚨 **주입본이 평가셋에 들어가는 것** — 자기가 만든 문제를 자기가 푸는 것 | 기획서 6-2 |
| `ck_surface_pairing` | 표면 변형이 S0 원형 없이 존재하는 것 — **짝이 없으면 델타를 못 잰다** | D-91 |
| `ck_segment_k_anon` — `member_count >= K_MIN` | k-익명성 미달 세그먼트 | 기획서 4-2 |
| `ck_chunk_tokens` — `token_count <= 512` | 리랭커가 삼키지 못하는 청크 | D-84 ③ |
| 전 테이블 `fragment_id ... ON DELETE CASCADE` | 소스를 지웠는데 파생물이 남는 것 | D-20 |

> ★ **캐스케이드는 걸어 두는 것과 실제로 지워지는 것이 다른 문제**다.
> `DELETE FROM source` 를 실제로 돌려 **9개 테이블이 0이 되는 것**을 확인했다. D-77 L4의 세 번째 지표가 이것이다.

## 5. 수집 시점에만 남길 수 있는 것 (D-71)

**되돌릴 수 없으므로 게이트보다 앞선다.**

| 필드 | 어디에 | 왜 나중에 못 하는가 |
|---|---|---|
| `provenance` | 골든셋·학습샘플 **행마다** | 섞인 뒤에는 **어느 줄이 어디서 왔는지 알 수 없다** |
| `redistributable` | 같음 (상속값을 **행에 복사**) | 소스가 캐스케이드로 지워지거나 등급이 바뀌면 조인의 답이 달라진다 |
| `raw` / `norm` / `offset_map` | 문장·청크 | 정규화를 파괴적으로 하면 **원문 좌표가 영구히 소실**된다 (D-84 ①) |
| `surface_variant` / `surface_of` | 골든셋 | 나중에 붙이려면 **골든셋 전체를 재생성**해야 한다 (D-91) |

> 🚨 **골든셋에 `redistributable: false` 소스에서 온 문장이 한 줄이라도 섞이면 그 골든셋 전체를 공개할 수 없다.**
> AI Hub 6종이 정확히 그 함정이다 — **등급은 G3 인데 데이터셋 재배포는 막혀 있다.** 등급과 재배포는 다른 축이다.

다음 빌드에서 날아가고, **그 사이에 두 벌이 갈린다** — 실제로 사실원장이 그렇게 갈렸다 (D-90 트레이드오프).

★ **재현 확인** — 재빌드한 HTML이 현재 파일과 **바이트 단위로 같고**, 재생성한 레지스트리의 **md5가 같다.**
