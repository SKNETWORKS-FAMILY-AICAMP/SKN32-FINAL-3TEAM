### 2-3. 추가 재료 2차: `ftc_stage.jsonl` 15건 더 — 의도적으로 다른 교정 전략

1차 실행(§5)에서 과적합을 확인한 뒤, `ftc_stage.jsonl`의 나머지 263건 후보를 다시

| 사건 | 위반 패턴 | 교정 전략 |
|---|---|---|
| 초유함량 비교우위 표현 | 허위 비교우위 | 비교 표현 삭제 |
| ADHD 프로그램 최상급 표현 | 최상급 남발 | 최상급 삭제 |

| 매트리스 방충제 절대 안전 표현 | 허위 안전성 단정 | 완화 표현으로 (→ held_out) |

제외한 것 — 왜: 문구가 브랜드/제품명뿐인 행(상호·제품명만 있는 행) — 인용된

사회적 참사 사건이라, 광고문구 교정 학습데이터로 가볍게 다루는 게 부적절하다고 판단.
뒷광고/리베이트 행 — "문구를 고쳐쓰는" 과제 형태와 안 맞음(절차 위반, 텍스트 위반이
아님).

## 4. 학습 설정 — 라운드별 변화

| 항목 | 1·2차 | 3차 | 4차 |
|---|---|---|---|
| 베이스 모델 | `Qwen/Qwen2.5-1.5B-Instruct` | 동일 | **`Qwen/Qwen2.5-3B-Instruct`** |
| LoRA | r=8, alpha=16, dropout 0.05, `q/k/v/o_proj` | 동일 | 동일 |
| 데이터 | train 700 (2차: ftc_stage 5배 오버샘플→840) | 동일 | 동일 |
| epoch | 10 → 3 | 3 | 3 |
| batch size | 2 | 2 | **1**(VRAM 확보) |
| gradient checkpointing | 안 씀 | 안 씀 | **씀**(3B가 10GB VRAM에 빠듯해서) |
| 학습 타깃 형식 | `{RewriteSet JSON}` | **`"핵심 주장: X\n{JSON}"`** | 동일(3차 형식 유지) |

**3차에 프롬프트를 바꾼 이유**: 1·2차 결과(§5, §5-1)에서 모델이 완전 신규 문구의
핵심 내용을 통째로 날리는 게 반복됐다("당뇨병 환자도 안심하고 드실 수 있는 치료
효과" → "치료 효과에 도움을 줄 수 있음"). "위반 지우고 JSON만 내라"는 지시만으로는
부족하다고 보고, **"핵심 주장을 먼저 밝히고 그걸 지키면서 위반만 고친다"는 추론
순서를 학습 타깃 자체에 넣었다**(chain-of-thought SFT). `injected_golden.jsonl`에
이미 있던 `핵심주장` 필드(784건)를 그대로 쓰고, `ftc_stage` 37건은 Claude가 직접
핵심주장을 붙였다.

**4차에 모델을 키운 이유**: 3차 결과물에 오타("드릴"/"드실" 혼용)가 있고 문장이
부자연스럽다는 지적이 있었다 — 기획서(9/17) §2가 이미 제시했던 "1.5B가 부족하면
3B로" 옵션을 실행했다. 10GB VRAM에 3B(bf16 기준 가중치만 ~6GB)를 태우기 위해
batch_size를 2→1로 낮추고 gradient checkpointing을 켰다(peft 권장대로
`enable_input_require_grads()`도 같이 걺).

## 5-1. 2차 조정 실행 결과 (2026-09-23)

§2-3의 실사례 15건 추가 + §4의 오버샘플링·epoch 축소를 적용해 재실행했다.

| | 2차-1차실행 (806쌍, 10epoch, 오버샘플 X) | 2차-2차실행 (821쌍, 3epoch, ftc_stage 5배) |
|---|--:|--:|
| 학습 loss | 0.1275 → 0.0003 | 0.0933 → **0.0017** (epoch 1→3 평균) |
| held-out 스키마 통과율 | 120/120 | **121/121 (100%)** |

loss가 덜 극단적으로 떨어지긴 했다(0.0003 → 0.0017 — 여전히 낮지만 완전한 암기까지는
아닌 수준). held_out 실사례 2건(§2-4에서 일부러 뺀 것)과, 학습에 전혀 없던 새 문구
2개로 다시 테스트했다:

```
[held_out 실사례 — 1차에서 실패했던 것] "〔공정위 인용 문구 A — 업력·업계 순위 주장 · 비공개〕"
  기대: "〔A 교정문 — 순위를 빼고 판매 사실만 · 비공개〕"
  1차 실행: "〔A에서 '체지방'이 빠지고 꼬리표만 붙음〕"   ← "체지방" 유실
  2차 실행: "〔A의 감량 주장은 살리고 꼬리표를 붙임〕"
  → ✅ "체지방" 보존, 문법 정상화. (다만 "판매해 왔습니다" 대신 여전히
     "~도움을 줄 수 있음" 꼬리표를 붙인다.)

[held_out 실사례 — 2차에서 새로 추가한 것] "〔공정위 인용 문구 B — 절대 안전 주장 · 비공개〕"
  기대: "〔B 교정문 — 기준 준수 사실만 표시 · 비공개〕"

  → ❌ 원래의 위반 주장("인체에 무해")을 거의 그대로 두고 "함유"만 붙였다.
     이 사건은 held_out으로 뺀 유일한 사례라 비슷한 교정 전략을 학습에서
     한 번도 못 봤다 — 실패가 오히려 "학습 안 한 패턴은 여전히 못 고친다"는
     걸 깔끔하게 보여준다.

[완전히 새로운 문구] "이 크림 바르면 주름이 완전히 사라집니다"
  1차 실행: "이 크림 바르면 주름에 도움을 줄 수 있음"          (양호)
  2차 실행: "이 크림 바르면 주름이 감소에 도움을 줄 수 있음"     (조사 오류 — 미세 후퇴)

[완전히 새로운 문구] "당뇨병 환자도 안심하고 드실 수 있는 치료 효과"
  1차 실행: "치료 효과에 도움을 줄 수 있음"        (핵심 내용 손실)
  2차 실행: "치료에 도움을 줄 수 있음"              (핵심 내용 손실 — 개선 없음)
```

### 2차 조정이 증명하는 것 / 증명하지 않는 것

- **증명하는 것**: 오버샘플링한 특정 패턴(최상급·순위 주장류)은 held_out에서
  내용 보존이 실제로 개선됐다 — 방향은 맞다.
- **증명하지 않는 것**: **완전히 새로운 문구에 대한 일반화는 거의 그대로다.** 두
  novel 테스트 모두 1차와 같은 실패(핵심 내용 손실 또는 무변화)를 반복했다. 37건
  (오버샘플 후 비중 21%)으로는 "몇 가지 패턴을 더 외우게 한 것"이지 모델이 위반을
  진짜 이해하는 수준까지는 못 갔다 — §2-1 원작성자가 경고한 "틀을 배운다"의 스케일이
  달라졌을 뿐, 구조는 그대로다.

## 5-2. 3차 조정 — 핵심주장 명시 프롬프트 (2026-09-30, Qwen2.5-1.5B)

2차까지도 완전 신규 문구에서 핵심 내용을 날리는 문제가 그대로였다. **데이터를 더
넣는 대신, 학습 타깃 자체에 "핵심 주장을 먼저 밝히고 그걸 지킨다"는 2단계 추론을
넣었다**(§4). 데이터는 821쌍 그대로, 학습 타깃 포맷만 바꿨다.

| | 2차-2차실행 (핵심주장 X) | 3차 (핵심주장 명시, 1.5B) |
|---|--:|--:|
| 학습 loss | 0.0933 → 0.0017 | 0.0790 → **0.0014**(epoch 1→3) |
| held-out 스키마 통과율 | 121/121 | 121/121 (100%) |

```
[완전히 새로운 문구] "당뇨병 환자도 안심하고 드실 수 있는 치료 효과"
  2차 실행: "치료 효과에 도움을 줄 수 있음"                              ← 핵심 통째로 유실
  3차 실행: 핵심 주장: 당뇨병 환자도 안심하고 드릴 수 있는 치료 효과
            "당뇨병 환자도 안심하고 드릴 수 있는 치료 효과에 도움을 줄 수 있음"
  → ✅ 핵심 주장이 거의 다 보존됐다(대표 실패사례가 처음으로 풀렸다).
     다만 "드릴"(← "드실") 오타 발생 — 아래 §5-3에서 다시 나온다.

[held_out 실사례] "〔공정위 인용 문구 B — 절대 안전 주장 · 비공개〕"
  3차 실행: 핵심 주장: 〔공정위 인용 문구 B — 절대 안전 주장 · 비공개〕
            "〔B 원문을 거의 그대로 두고 '함유'만 붙임〕"
  → ❌ 여전히 못 고침 — 이 교정 전략(절대 안전성 표현 완화)은 held_out으로
     빼서 학습에 한 번도 노출되지 않았으니 예상된 실패.

[완전히 새로운 문구·신규 테스트] "국내 1위 다이어트 보조제, 3일만에 5kg 감량"
  3차 실행: 핵심 주장: 다이어트 보조제
            "다이어트 보조제"
  → ❌ 새로운 실패 유형 — 절이 여러 개인 복잡한 문장에서는 오히려 더 많이 날렸다.
```

**정리**: chain-of-thought 프롬프트가 **단순한 문장에서는 확실히 통했다** — 지난
라운드들의 대표 실패사례(당뇨병 건)를 처음으로 풀었다. 하지만 (a) 오타가 여전하고
(b) 절이 여러 개인 복잡한 문장에서는 더 심하게 정보를 날리는 새 실패 유형이 나왔다.
프롬프트 엔지니어링만으로는 모델 자체의 표현력 한계를 못 넘는다는 뜻으로 읽었다.

## 5-3. 4차 조정 — Qwen2.5-3B-Instruct로 스케일업 (2026-09-30)

3차 결과물의 오타·부자연스러움 지적을 받아, 베이스 모델을 1.5B → 3B로 올렸다(다른
설정은 3차와 동일 — 핵심주장 프롬프트 그대로, 데이터도 그대로). 10GB VRAM에 맞추려
batch_size 2→1 + gradient checkpointing을 썼다(§4).

| | 3차 (1.5B) | 4차 (3B) |
|---|--:|--:|
| 학습 파라미터 | 2,179,072 / 1,545,893,376 (0.14%) | 3,686,400 / 3,089,625,088 (0.12%) |
| 학습 loss | 0.0790 → 0.0014 | 0.0619 → **0.0008**(epoch 1→3) |
| held-out 스키마 통과율 | 121/121 | 121/121 (100%) |

같은 4개 문구로 3차와 나란히 비교:

| 입력 | 3차(1.5B) | 4차(3B) |
|---|---|---|
| "당뇨병 환자도 안심하고 드실 수 있는 치료 효과" | "...드**릴** 수 있는 치료 효과에 도움을 줄 수 있음" (오타) | "...드**실** 수 있는 치료에 도움을 줄 수 있음" — ✅ 오타 없음, "효과…도움" 중복도 사라져 더 자연스러움 |
| "이 크림 바르면 주름이 완전히 사라집니다" | "이 크림으로 주름 개선에 도움을 줄 수 있음" | "주름 개선에 도움을 줄 수 있음" — 깔끔 |
| "〔공정위 인용 문구 B — 절대 안전 주장 · 비공개〕"(held_out, 학습 미노출) | "〔B 원문을 거의 그대로 두고 '함유'만 붙임〕" (위반 표현 그대로) | "원료 함유" — ✅ 절대 안전 표현을 실제로 제거했다(학습 노출이 없었는데도) |
| "국내 1위 다이어트 보조제, 3일만에 5kg 감량"(복잡한 문장) | "다이어트 보조제" (거의 다 날림) | "다이어트 보조제, 3일간의 사용에 따른 변화 가능" — ✅ "3일" 개념을 살리고 자연스럽게 헤징. "5kg"라는 구체 수치는 빠졌는데, 검증 안 된 수치 자체가 위반 요소라는 관점에서는 적절한 판단일 수도 있다 |

**정리**: 4개 사례 전부에서 3차보다 나아지거나 최소 동일했다. 특히 3차가 가장 못했던
"복잡한 다중 절 문장"과 "학습에 없던 교정 전략"(절대 안전 주장) 둘 다에서 개선이 보였다 —
모델 크기가 프롬프트 엔지니어링만으로는 못 넘던 벽 일부를 밀어낸 것으로 보인다.

## 6. 여전히 남은 근본 문제 — "노잼"의 원인

품질을 직접 검수하다 나온 지적: **문장이 재미없고 "OOO에 도움을 줄 수 있음"만
반복된다.** 원인을 짚어보면 이건 모델의 결함이 아니라 **학습 데이터 자체의 성격**
이다.

`injected_golden.jsonl`의 T1 규칙(전체의 상당 비중을 차지 — §2-1) 정답 문구는
식약처가 실제로 승인하는 건강기능식품 고시 문구 스타일 그대로다 — 원래 관료적이고
밋밋한 게 "적법"의 정의이지, 소구력 있는 카피가 아니다. 모델은 이 스타일을 정확히
배운 것뿐이고, **학습 데이터 어디에도 "합법이면서 읽기 좋은 카피" 예시가 없었다.**

더 근본적으로는 `sLLM_파인튜닝_기획서_2026-09-17.md` §1의 원래 목표를 다시 보면:

> N=3 · K=2 — 보수안 / 균형안 / 공격안. 위험도가 서로 다른 재작성 후보 3개

**1~4차 전부 "보수안" 하나만 만드는 실험이었다.** "OOO에 도움을 줄 수 있음"은
가장 안전한 보수안 스타일 그 자체이고, 원래 설계는 여기에 소구력 있는 균형안·공격안을
더해 3개를 같이 내는 것이었는데 그건 이번 라운드까지 시도된 적이 없다. 다음 라운드
과제로 명시해 둔다(§8).

## 7. 이 결과가 종합적으로 증명하는 것 / 증명하지 않는 것

- **증명하는 것**: 모델 선정 → 데이터 구성(2회 보강) → 프롬프트 엔지니어링(핵심주장
  명시) → 모델 스케일업(1.5B→3B) → `app/contracts.RewriteSet` 스키마 검증까지, **각
  단계 개입이 측정 가능한 방향으로 결과를 바꾼다는 걸 확인했다** — 재현 가능한 실험
  루프다. 완전 신규 문구의 핵심 내용 유실·오타 문제는 실제로 줄었다(§5-2, §5-3).
  MCP 시연에서 "형식 갖춘 JSON이 나온다"는 보여줄 수 있다.
- **증명하지 않는 것**:
  - **소구력 있는 카피 생성** — 지금까지는 "위반을 없앤 가장 안전한 한 줄"만 만드는
    법을 배웠다. 기획서 원래 목표(N=3, 보수/균형/공격)의 극히 일부만 다뤘다(§6).
  - 복잡한 다중 절 문장에 대한 일반화 — 4차(3B)에서 나아졌지만 표본 1건뿐이라
    신뢰도가 낮다.
  - `mandatory_note`/`placement` 동시 생성 — 전 라운드 다 학습 데이터 자체가
    `body`만 채워져 있어 `null` 고정으로만 학습됐다.
  - `ftc_stage` 유래 37건 `body`의 법률적 정확성 — Claude 초안, 사람 재검토 전.
