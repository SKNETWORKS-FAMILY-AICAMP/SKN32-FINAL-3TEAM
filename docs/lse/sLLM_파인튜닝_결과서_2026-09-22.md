## 1. 배경 — 1차와 무엇이 달라졌나

1차(§7, 2026-09-17)는 `transform_pair`도 `ftc_decisions_body` 라이브 조회도 막혀서,
입력(위반 문구)은 실제 수집 데이터, 출력(교정문)은 직접 작성하는 절충안이었다 — 35쌍
(학습 30), Colab T4.

2차는 그 사이 pull로 들어온 새 파생 데이터를 다시 훑는 데서 시작했다:

- `data/derived/golden/injected_golden.jsonl`(902행)이 이미 위반→교정 쌍 구조로
  생성돼 있었다 — 1차가 찾다 막혔던 `transform_pair` 역할을 대체.
- 로컬 GPU(RTX 3080)가 확인돼 Colab 없이 로컬 학습으로 전환.

## 2. 데이터 구성 — 두 번 다시 짚었다

### 2-1. 1차 재료: `injected_golden.jsonl` (784건) — 그런데 "784"는 틀렸다

`TRANSFORM_RULES` T1/T2/T4/T5/T6/T7a/T7b로, 승인 원본 118건 중 112건(나머지 60건은
`split.py`가 평가용으로 봉인 — D-171·D-176, 건드릴 수 없음)에서 파생시킨 위반 문구
784건.

**"데이터 몇 개냐"는 질문에 숫자 784는 오답이었다.** `preprocess/inject.py` 원작성자가
이미 코드 주석에 남긴 경고("T6·T7은 고정 문장이라 한 자릿수 틀이다")를 실측했다:

| 규칙 | 건수 | 고유 틀 | 비율 | 판정 |
|---|--:|--:|--:|---|
| T1 | 112 | 3 | 2% | 틀고정 |
| T2 | 112 | 44 | 39% | 그나마 다양 |
| T4 | 112 | 4 | 3% | 틀고정 |
| T5 | 112 | 5 | 4% | 틀고정 |
| T6 | 112 | 5 | 4% | 틀고정 |
| T7a | 112 | 3 | 2% | 틀고정 |
| T7b | 112 | 3 | 2% | 틀고정 |

즉 실제 정보량은 "112개 원본 문장 × 7규칙의 3~5가지 고정 틀"이지 784개의 독립 사례가
아니다. 이 한계는 나중에 §5에서 그대로 실현된다.

### 2-2. 추가 재료: `ftc_stage.jsonl`의 실제 FTC 의결서 22건

"몇천 개 받지 않았냐"는 질문을 따라가 `data/derived/ftc_stage.jsonl`(8,272행, 실제
FTC 의결서 원장)을 다시 뒤졌다:

- 8,272행 중 실제 인용 위반 문구(`문구`)와 시정·금지 명령문(`주문_마스킹`)이 **둘 다**
  있는 행: 285건 (나머지 7,013건은 원문 추출이 안 된 "E" 분류 — 빈 사례).
- 그중 이 프로젝트 도메인(화장품·건강기능식품 등)이고, 명령문이 구체적 주장(퍼센트·
  최상급 표현)을 명시적으로 반박하는 행만 **22건** 추림. 나머지 263건은 상호명·건물명뿐
  이거나("하이브랜드" 등) 도메인이 다름(부동산 분양·학원·웨딩 등).
- `주문_마스킹`은 "~광고행위를 다시 하여서는 아니 된다"류 금지명령문이지 재작성된
  광고 카피가 아니어서, `RewriteSet.body`는 각 사건 명령문을 **Claude가 직접 읽고
  작성**했다 — 1차의 "교정 문구만 직접 작성"과 같은 성격의 합성이고, **법률 검토를
  받지 않았다**. `train_pairs.jsonl`에 `correction_confidence: heuristic_unverified`로
  표시해뒀다.
- 대표 사례: 글루코사민 "함유량 100%" 허위표시(동일 사건군 18건), 조제분유 유당함량
  과장 비교, 게르마늄 공법 최상급 표현, "동종업계 체지방 감량 1위" 근거 없는 순위 주장.

### 2-3. 최종 데이터셋

`docs/lse/train_pairs.jsonl` — **806쌍 (train 686 · held_out 120)**. `src`(원본 고유
id) 단위로 분리해 같은 원본의 다른 규칙 변형이 train/held_out에 걸쳐 섞이는 데이터
누수를 막았다. `ftc_stage` 유래 22건 중 유일하게 독립적인 사건(체지방 감량, 7765)은
"진짜 미학습 실사례" 검증용으로 일부러 held_out에 넣었다.

## 3. 실행 환경

- **GPU**: RTX 3080, VRAM 10GB, Ampere(SM 8.6) → **bf16 네이티브 지원**. 노트북은
  `torch.cuda.is_bf16_supported()`로 자동판별하도록 짜서 다른 GPU로 옮겨도 안전.
- **별도 venv**: 프로젝트 공용 `.venv`는 CPU torch(의도적 — GPU 패키지를 `pyproject.toml`
  락에 넣지 않는다는 팀 방침, KC-BERT 인코더는 CPU로 충분해 문제없음). GPU 학습은
  `.venv-sllm`을 새로 만들어 격리:
  `torch==2.11.0+cu128`, `transformers==5.17.0`, `accelerate==1.15.0`, `peft==0.21.0`.
- 노트북: `docs/lse/copylane_sllm_lora.ipynb` — Colab 전용 업로드 셀 없음, `.venv-sllm`
  커널 확인 어서트 포함, `jupyter nbconvert --execute --inplace`로 헤드리스 실행.

## 4. 학습 설정

| 항목 | 값 |
|---|---|
| 베이스 모델 | `Qwen/Qwen2.5-1.5B-Instruct` |
| 방법 | LoRA, r=8, alpha=16, dropout 0.05 |
| 타겟 모듈 | `q_proj, k_proj, v_proj, o_proj` |
| 학습 파라미터 | 2,179,072 / 1,545,893,376 (**0.14%**) |
| 배치 | 2, 10 epoch, 총 3,430 step |
| 옵티마이저 | AdamW, lr 2e-4, cosine schedule |
| loss 마스킹 | assistant(정답) 토큰만 loss, 질문 부분은 `-100` |

## 5. 결과

| | 1차 Colab (35쌍) | 2차 로컬 (806쌍) |
|---|--:|--:|
| 학습 loss | 1.44 → 0.87 | **0.1275 → 0.0003** (epoch 1→10 평균) |
| held-out 스키마 통과율 | 5/5 | **120/120 (100%)** |

숫자만 보면 개선된 것처럼 보인다. **그런데 epoch 3만에 loss가 0.005 밑으로 떨어진 건
정상 수렴이 아니라 과적합 신호였다.**

### 🔴 직접 확인한 실패 사례

저장된 adapter를 로드해 (a) held_out에 넣어둔 유일한 실사례, (b) 학습에 전혀 없던
새 문구 두 개로 따로 테스트했다:

```
[held_out 실사례] "2005년 설립 이래 동종업계 체지방 감량 1위"
  기대(직접 작성): "2005년 설립 이후 체지방 감량 제품을 판매해 왔습니다"
  모델 생성:        "2005년 설립 이래 동종업계 감량에 도움을 줄 수 있음"
  → "체지방"이 빠지고 문법이 깨졌다

[완전히 새로운 문구] "당뇨병 환자도 안심하고 드실 수 있는 치료 효과"
  모델 생성: "치료 효과에 도움을 줄 수 있음"
  → "당뇨병 환자도 안심"이라는 핵심 주장을 통째로 버렸다
```

두 사례 모두 스키마(JSON 형식)는 통과하지만, 원문의 핵심 내용을 보존하지 못했다.
모델이 위반을 이해해서 고치는 게 아니라, `injected_golden`에서 T1 규칙이 압도적으로
많이 준 **"OOO에 도움을 줄 수 있음"이라는 고정 꼬리표를 거의 모든 입력에 기계적으로
붙이는 법**을 배웠다 — §2-1에서 미리 경고했던 "틀 다양성 낮음 → 위반이 아니라 틀을
배운다"가 정확히 이 실행에서 재현됐다.

## 6. 이 결과가 증명하는 것 / 증명하지 않는 것

- **증명하는 것**: 모델 선정 → 데이터 구성(806쌍) → LoRA 파인튜닝 → 학습에 없는 입력
  생성 → `app/contracts.RewriteSet` 스키마 검증까지, **BFF 계약과 실제로 맞물리는
  사이클이 로컬 GPU에서 끝까지 돈다.** MCP 시연에서 "형식 갖춘 JSON이 나온다"는 보여줄
  수 있다.
- **증명하지 않는 것**:
  - 재작성 **내용 품질** — 원문 핵심 보존, 위반 유형별 적절한 교정. 이 adapter를 실제
    판정 결과에 그대로 노출하면 안 된다.
  - `mandatory_note`/`placement` 동시 생성 — 이번에도 학습 데이터 자체가 `body`만
    채워져 있어 `null` 고정으로만 학습됐다.
  - `ftc_stage` 유래 22건 `body`의 법률적 정확성 — Claude 초안, 사람 재검토 전.

   뽑아 틀을 늘리는 작업이 우선(원작성자도 "다음 작업"으로 명시해둠). 이건 팀 공유
