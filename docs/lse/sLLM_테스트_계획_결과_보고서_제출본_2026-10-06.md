## 1. 시험 대상 — 재생성 에이전트

CopyLane 의 에이전트 흐름에서 sLLM 은 **검수(판정 코어) 뒤에 붙는 재생성 에이전트**다.

```
[판정 코어 에이전트]  문장 분할 → 품목 → 근거 검색 → 사전 → 판정 → 위험도
        │ 위반 문장 + 위반 유형
        ▼
[재생성 에이전트 (sLLM)]  ① 1단계 sLLM(v12) → ② 후처리 → ③ 관문 → [④ 2단계 페르소나]
        │ 고친 문구
        ▼
[판정 코어 에이전트]  ⑤ 재판정 — 위반 유형이 붙으면 후보 탈락 (D-119)
        ▼
  후보 / 보류(사람 검토) / 합법화 불가
```

| 시험 대상 | 구성 요소 | 소스 |
|---|---|---|
| 모델 | 1단계 LoRA v12 · 2단계 페르소나 LoRA (Qwen2.5-3B-Instruct) | `docs/lse/train_stage1_v5.py` · `train_persona_stage2.py` |
| 안전장치 | 후처리 · 관문 | `docs/lse/postfix.py` · `docs/lse/stage_gate.py` |
| 에이전트 간 연결 | 재판정 · HTTP 서빙 · 앱 BFF | `docs/lse/rejudge.py` · `docs/lse/sllm_service.py` · `app/routers/user.py` · `app/routers/sllm_client.py` |

### 2-4. 누수 · 공정성 관리

- 인코더 평가 문장과 겹치는 행은 학습 · 평가에서 뺀다 · 정답표 문구가 학습 문구 **안에 부분으로** 든 경우 `seen_in_training` 으로 따로 센다.
- 판정 인코더로 채점하지 않는다(학습 · 채점에 같은 것을 쓰면 짜고 치는 판) — 정답표와 규칙으로 잰다.
- 평가 입력을 파일로 고정한다(`_private/real_inputs_frozen.jsonl`) — 팀 데이터 갱신으로 평가 문장이 바뀌지 않게.
- 생성은 그리디(무작위성 없음) — 같은 입력이면 같은 출력(재현 가능).

## 5. 결론

- ✅ **안전 기준(T1 · T2 · T4)을 모두 지켰다** — 모든 평가에서 위반 포장 0 · 고칠 수 없는 문구에서 후보 0 · 알려진 위험 출력 5/5 차단.
- 🟡 **살리기는 연습 문제에서 높고(25/28 · 13/14) 실전에서 절반에 못 미친다(8/20)** — 나머지는 보류로 사람에게 넘어간다. 안전 쪽으로 기운 결과다.
- 🟡 **관문이 보수적이다** — 정상 정답의 9.5% 를 보류한다(주로 개별인정형 기능성 문구). 인정 문구 목록을 늘리면 줄일 수 있다.
- 🟡 **재판정은 연결됐지만 판정 코어의 한계를 그대로 받는다** — 인코더 연결 전이라 통과를 낼 수 없고, 인정 기능성 문구 오탐이 있다.
- 🔴 **실제 광고 수치는 낙관적일 수 있다** — 정답표 v2 의 원천(사례집 2021 · 화장품 광고 Q&A)은 판정 인코더의 평가 원천이고, 10-05 에
  그 미리보기 결과를 보고 관문 · 후처리를 보강했다. 즉 「학습에 없던 87개」는 모델 학습에는 없지만 **규칙 조정에는 쓰인 문구**다.
  10-06 부터는 그 문구로 규칙을 조정하지 않는다(회귀는 학습 정답 · 직접 만든 연습 문제로만).
