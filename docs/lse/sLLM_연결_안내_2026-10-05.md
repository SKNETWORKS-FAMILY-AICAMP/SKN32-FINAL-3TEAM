## 4. 요청 · 응답

`POST /rewrite`
```json
{"text": "이 크림 바르면 주름이 완전히 사라집니다", "violation_types": ["거짓_과장"]}
```
- `violation_types`: 검수(판정 코어)가 준 위반 유형을 그대로 넘긴다(`app.contracts.Violation` 값). 없으면 `[]`.
- 선택: `"persona": "30대 직장인 — …"`(2단계 말투) · `"rejudge": true`(판정 코어 재판정 · DB 필요)
- 🆕 10-12 선택: `"polish": true` — 고객층 없이도 2단계로 **자연스럽게 다듬은 문장**을 낸다(앱은 켜서 부른다 · `sllm_client.POLISH`).
  다듬은 문장은 관문을 다시 지나고(건강 낱말 · 지어낸 사실 · 사실 낱말 바꿈 · 제품과 안 맞는 쓰는 법 → 막음), 막히면 1단계 문장을 낸다.
  다듬었으면 응답의 `plain` 에 1단계(담백한) 문장이 함께 온다

응답
```json
{
  "outcome": "candidate",
  "rewrite": {"body": "피부의 주름 개선에 도움을 줍니다",
              "mandatory_note": "주름 기능성화장품으로 심사·보고된 크림에 한함", "placement": null},
  "infeasible": null, "reasons": [], "repairs": [], "model": "v12", "latency_ms": 12187
}
```

| `outcome` | 뜻 | 화면에 |
|---|---|---|
| `candidate` | 고친 문구 후보 — `rewrite` 가 계약 `RewriteSet` 꼴 | 후보 + 조건(`mandatory_note`) · 🚨 적법 확정 아님 |
| `hold` | 관문 · 후처리가 막음 — `reasons` | 「사람 검토 필요」 |
| `infeasible` | 합법화 불가 — `infeasible` 에 위반 유형 | 증명서 경로(D-32) |

`"rejudge": true` 일 때 응답의 `rejudge` (끄면 `null`):
```json
"rejudge": {"status": "rejected", "core_outcome": "hold", "violations": ["건강기능식품_오인"],
            "hold_reasons": ["low_conf"], "basis": [], "rejected_body": "체지방 감소에 도움을 줄 수 있음", "note": null}
```
- `status`: `rejected`(위반 유형이 붙음 → `outcome` 이 `hold` 로 바뀌고 `reasons` 에 「재판정 탈락: …」) · `no_violation`(위반 없음 — 🚨 통과 보증 아님) · `passed` · `unavailable`(DB 없음 · `note` 에 이유)
- `rejected_body`: 탈락한 후보 문장(왜 떨어졌는지 보라고 남긴다)
- 🚨 10-05 현재 판정 코어는 인코더 연결 전 · 사전 개편 중이라 사전만으로 판정한다 — 인정 기능성 문구도 `건강기능식품_오인` 으로 떨어질 수 있다(위 예).

실측 예 (직접 만든 문구):

| 입력 | outcome | 결과 |
|---|---|---|
| 이 크림 바르면 주름이 완전히 사라집니다 | candidate | 피부의 주름 개선에 도움을 줍니다 + (주름 기능성화장품으로 심사·보고된 크림에 한함) |
| 암을 이기는 꾸지뽕 진액 | infeasible | 질병_예방치료_표방 |
| 고혈압 낮추는 오미자청, 문경 오미자를 설탕에 100일 숙성 | candidate | 문경 오미자를 설탕에 100일 숙성한 오미자청 |
| (빈 문장) | HTTP 422 | — |

## 5. 앱에서 부르는 예 (CPU `.venv` 그대로)

```python
import httpx  # 또는 requests

def sllm_rewrite(text: str, violation_types: list[str]) -> dict | None:
    try:
        r = httpx.post("http://127.0.0.1:8765/rewrite",
                       json={"text": text, "violation_types": violation_types}, timeout=60)
        r.raise_for_status()
        return r.json()
    except httpx.HTTPError:
        return None  # 🚨 서버가 없으면 「후보 없음」으로 — 지어내지 않는다(D-146)
```

## 5-1. 🆕 10-06 — 앱에 붙인 것 (팀장 승인 · **검수 결과 안에서 재생성**)

검수 결과의 지적 문장 아래 **「이 문장 고쳐 쓰기」** → 같은 검수 화면의 그 문장 아래에 고친 문구가 붙는다.

| 자리 | 파일 | 하는 일 |
|---|---|---|
| 검수 화면 버튼 · 결과 | `app/templates/user/review.html` · `_review_rewrite.html` | 지적 문장 중 **위반 유형이 있는** 문장에만 버튼 · 결과(후보 · 보류 · 합법화 불가 · 서버 없음) · 🆕 10-12 「다듬은 안 · 담백한 안」 |
| BFF `POST /u/review/rewrite` | `app/routers/user.py` `review_rewrite()` | 문구 칸 다시 판정 → `target`(문구번호:문장id) 문장을 sLLM 으로 → **앱 판정 코어로 재판정**(D-119) |
| 서버 호출 | `app/routers/sllm_client.py` | 표준 `urllib`(새 의존성 없음) · 서버 없으면 `down` |
| 테스트 | `tests/test_user_rewrite.py` | GPU · DB 없이(골든 픽스처 · 가짜 서버) |

- 🔴 판정(`JudgeResponse`)의 `candidates` 는 그대로 비운다(D-265 계약) — 고쳐 쓰기는 따로 부르는 재생성 호출이고 화면이 옆에 붙인다.
- 위반 유형은 **서버의 판정 결과**에서 읽는다(폼 값을 믿지 않는다). 사유 A(자격형) · 위반 유형 없는 문장(확신 부족만)은 고쳐 쓰지 않는다.
- 재판정에서 위반 유형이 붙으면 「보류 — 재판정에서 위반 의심」. 「위반 못 찾음」은 **통과 아님**으로 적는다.
- 서버 주소는 `COPYLANE_SLLM_URL`(기본 `http://127.0.0.1:8765`) — **앱과 sLLM 서버는 같은 PC**.
- ⏱️ 실측(10-06 · 3080): 첫 검수 30~65초(판정 코어 · 모델 올림) → 고쳐 쓰기 10~20초(문구 다시 판정 + sLLM). **시연 전에 한 번 돌려 둔다.**

## 6. 알아 둘 것

- ⏱️ **문장당 4~12초**(3080 · 1문장씩 · 요청은 줄 세움). 시연 문장은 미리 돌려 두는 것을 권한다.
- 🔄 10-12 후보는 **최대 2안**이다 — 「자연스럽게 다듬은 안」 + 「담백한 안(위반만 지운 1단계 문장)」. 둘 다 앱이 재판정하고,
  다듬은 안이 재판정에서 떨어지면 담백한 안을 후보로 올린다. D-34(N=3)는 아직 못 채운다.
- 다듬은 안은 처음 보는 제품에서 어색한 쓰임을 낼 수 있다(쓰는 법 사전이 일부를 막는다 · `docs/lse/usage_dict.py`) — 문장당 약 12~16 초
- 1단계는 「사실 + 위반」에서 위반만 지우는 데 강하고, 실전 「살리기」는 아직 40% 수준이다(나머지는 보류 · 사람 검토).
- 🚨 `candidate` 도 적법 확정이 아니다 — 재판정(D-119)과 사람 검수가 남는다.
- 🔒 요청 · 로그에 실제 광고(재배포 불가) 문구가 남을 수 있다 — 로그를 공개 저장소에 올리지 않는다.
