## 1. 10-06 — 재생성 앱 연결 (팀장 승인)

**검수 결과에서 위반 유형이 붙은 문장마다 「이 문장 고쳐 쓰기」** → 고친 문구가 그 문장 아래에 붙는다.

```
판정 결과의 위반 유형 → sLLM(v12) 고쳐 쓰기 → 판정 코어 재판정 → 결과 표시
```

| 결과 | 화면 |
|---|---|
| 고친 문구 후보 | 문구 + 필수 병기 + 재판정(「위반 못 찾음 (통과 아님)」) |
| 보류 | 재판정에서 위반 의심(탈락 문장 · 위반 유형) / 관문 차단(사유) |
| 합법화 불가 | 위반 유형(모르는 값이면 「유형 미상」 — 모델이 지어낸 사유는 안 그린다) |
| 서버 없음 | 「후보를 만들지 않았어요」(D-146 · D-147) |

- 사유 A(자격형) · 위반 유형 없는 문장(확신 부족 보류만)은 고쳐 쓰지 않고 **이유를 표시**한다(D-59 · 유형 없이 보내면 모델이 엉뚱한 불가를 냈다 — 실측).
- 판정 계약(`JudgeResponse.candidates`)은 비운 그대로다(D-265) — 고쳐 쓰기는 따로 부르는 재생성 호출이다.
- 위반 유형은 **서버의 판정 결과**에서 읽는다(폼 값을 믿지 않는다).
- 카피생성(ksr · 새 카피)에는 넣지 않았다 — 재생성(고쳐 쓰기)과 생성(새로 쓰기)은 다른 기능이다.

**파일**

| 파일 | 내용 |
|---|---|
| `app/routers/user.py` | `POST /u/review/rewrite` (`review_rewrite` · `_rewrite_sentence` · `_rejudge`) |
| `app/routers/sllm_client.py` | sLLM 서버 호출 — 표준 `urllib`(새 의존성 없음) · `COPYLANE_SLLM_URL` |
| `app/templates/user/review.html` | 버튼 · 이유 줄만 추가 |
| `app/templates/user/_review_rewrite.html` | 결과 칸 |
| `tests/test_user_rewrite.py` | GPU · DB 없이(골든 픽스처 · 가짜 서버) |

**실행 (같은 PC)**

```
.venv-sllm\Scripts\python.exe docs\lse\sllm_service.py --serve --port 8765   # sLLM (GPU)
.venv\Scripts\python.exe -m uvicorn app.api:app --port 8000                  # 앱
```

- 첫 검수 약 30초(판정 코어 준비) · 고쳐 쓰기 10~20초. 시연 전에 한 번 돌려 둔다.
- 서버 없는 PC 에서도 앱 · 테스트는 돈다(「서버에 연결하지 못했어요」).
- 자세한 것: `sLLM_연결_안내_2026-10-05.md` §5-1.

**아직 안 된 것**

- 후보는 1개(D-34 N=3 미충족) · 재판정 탈락 시 다시 만들기(D-126 K=2) 없음.
- 재판정은 「위반 못 찾음」까지 — 통과 판정은 인코더 연결 뒤.

## 2. 10-05 — 1단계 성능 개선 (v10 → v12 채택)

- 학습 데이터 다양화 · 화장품 데이터 추가 → **v12 채택**.
- 후처리(`postfix.py`): 원료명 앞부분 잘림 · 한 글자 오타를 원문 표기로 되찾기 · 지어낸 기능성 문구를 식약처 공식 문구로 교체 · 조건(필수 병기)은 메뉴 안의 것만, 제품 종류와 맞을 때만.
- 관문(`stage_gate.py`) 빈틈 막기: 지어낸 낱말 · 원료명 · 인정되지 않은 기능성 · 원문에 없는 화장품 기능 · 효과 수치 남김.
