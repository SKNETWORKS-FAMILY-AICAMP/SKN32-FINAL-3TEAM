## 1. 배경 — 왜 페르소나인가

4차까지의 결과물은 **「○○에 도움을 줄 수 있음」 한 가지 말투**였다(09-22 결과서 §6 「노잼」). 원인은 학습 정답 784개가
전부 식약처 승인 문구 말투였기 때문이고, 원래 기획의 보수안/균형안/공격안 중 보수안만 만들어 왔다.

- 보수/균형/공격 3안을 실제 데이터로 채우려 했으나, 공격안 재료로 찾은 **식약처 해설서 수정쌍 245건은 판정 J1 (b)로
  인코더 평가 전용**이 되어 쓸 수 없게 됐다(쓰면 누수).
- 조장 제안으로 **페르소나(대상 고객)를 입히는 방향**으로 바꿨다. 설계 문서의 「페르소나 팬아웃」과 같은 방향이고,
  D-27(페르소나에서 고민 · 증상 소구 제외)을 지킨다.
- 팀장 조건: **데이터 누수만 없으면 진행** (§6).

- 📌 판정 인코더로도 쟀지만 생성 문장의 거의 전부(원본 98/102)를 위반 후보로 잡아 **채점 도구로 쓸 수 없었다**
  (v7 결과서의 과다 예측과 같은 현상). 이후 채점에서 인코더를 뺐다.

## 3. 6차 — 2단 실험과 대체 표현 힌트

**2단**: 1단계(LoRA v4)가 위반을 지우고, 2단계(원본 3B)가 **원문을 보지 않고** 말투만 입힌다.

| | 결과 |
|---|--:|
| 페르소나 간 차이 | 0.59 |
| 지운 위반 낱말이 다시 나옴(재유입) | 0 |
| 고민 · 증상 소구 | 0 |

- 남은 문제: 페르소나 단어 끼워넣기(「간편 출근 전 하루 한 번…」), **완화 표현을 다시 세게**(「도움을 줄 수 있음」→「가능해요」),
  1단계가 못 지운 위반을 그대로 넘겨받음.

**대체 표현 힌트**: 외부 규칙 사전 [kadlint](https://github.com/feelyday/kadlint)(MIT · 규칙 299개 · 대체 표현 571개)의
대체 표현을 2단계 프롬프트에 「이런 결로」 참고로 넣었다.

- 잘 될 때는 좋았다 — 피부노화방지류 → 「탄력 있어 보이는 피부 케어」.
- 그러나 **조건 괄호까지 베끼고**(「(실증 보유 시)」), **없던 숫자를 지어냈다**(새 숫자 1→4건).
- → kadlint 는 학습 재료로 쓰지 않고 **채점용으로만** 쓰기로 했다(학습과 채점에 같이 쓰면 짜고 치는 판이 된다).
  ⬜ 팀 원천 등록 전이라 저장소에 복사하지 않았다.

**결론**: 3B 는 프롬프트만으로는 지시를 지키지 못한다 → 2단계를 따로 학습한다.

## 5. 8차 — 실제 광고로 끝까지 + 관문

### 5-1. 문제 발견

실제 광고 문구 31개(중복 제외)를 1단계(v4) → 2단계(페르소나 LoRA)로 돌렸다.

- 2단계는 **새 위반을 하나도 만들지 않았다**(kadlint 금지 패턴 신규 0/99).
- 🔴 그러나 **1단계가 위반을 못 지운 문장에 2단계가 말투를 입혀 그럴듯하게 포장했다** —
  질병명에 「도움」만 붙인 문장, 의약품 표현을 그대로 둔 문장, 원문 수치를 남긴 문장, 체험기를 그대로 둔 문장,
  글자가 깨진 문장. 예(직접 만든 문구로 재현): 「운동과 자기관리를 즐기는 20대에게, ○○질환 개선에 도움을 줄 수 있어요.」

### 5-2. 관문 (`stage_gate.py`)

2단계는 「적법한 문장」을 전제로 하므로 **전제가 서지 않는 문장은 2단계로 넘기지 않고 보류**한다.
막는 쪽으로 틀린다(D-09 래칫과 같은 방향).

| 규칙 | 내용 |
|---|---|
| 금지 사전 | `app/dictmatch.py`(판정 그래프 `match_dict` 와 같은 규칙 · D-99) · 단독판정 항목 452개 |
| 질병 · 의약품 | 질병명 · 치료 · 예방 · 완치 / 의약품 · 처방 · 약 |
| 수치 | 원문 숫자가 남음 (성분명 숫자 — Q10 · CO2 — 제외) |
| 체험기 · 그대로 · 깨짐 | 1인칭 과거 경험 / 원문과 같음 / 비정상 글자 |
| 자격 · 노화 · 대상 불명 | 특허 · 인증 표방(D-59) / 노화 주장 / 「건강기능식품에 도움」 |

- 2단계 결과도 같은 관문을 다시 지난다.
- **관문은 재판정이 아니다** — 판정 결과(위반 유형 · 근거 조문 · 위험도)를 내지 않는다. 원래 설계의 재판정(최종 문장을
  `/judge` 판정 코어에 다시 넣기, D-119)은 **로컬 DB 접속 불가로 미연결**이다.

## 9. 증명하는 것 / 증명하지 않는 것

- **증명하는 것**
  - 2단계 구조에서 **말투 단계는 주장 범위를 지키며 페르소나를 입힐 수 있다**(처음 보는 주제 · 페르소나 포함 55/57).
  - 「고칠 수 없음」을 정답에 넣으면 **위반을 그럴듯하게 포장하는 실패가 사라진다**.
  - **「사실 + 위반」이 섞인 문구에서 위반만 지우고 사실을 살릴 수 있다**(12~16차 · 살리기 40 에서 26/28 · 학습에 없는 원료).
  - **틀리면 멈추는 구조가 실제로 막는다** — 1단계가 낸 위반 문장(지어낸 제품명 · 지어낸 원료명 · 인정되지 않은 기능성 · 원문과 무관한 기능)을
    관문 · 후처리가 보류로 돌렸다. 실제 광고(학습에 없던 87)에서 위반 포장 **0**.
  - 후처리로 **학습 없이** 기계로 고칠 수 있는 실수(원료명 잘림 · 오타 · 지어낸 기능성 문구)를 고쳐 살릴 수 있다(15차 · 실제 광고 살림 3 → 5).
- **증명하지 않는 것**
  - **최종 문장의 적법성** — 재판정은 연결됐지만 팀 판정 코어가 인코더 전 규칙 판정이라 「통과」를 낼 수 없다(10-04 확인 ·
    단독판정 사전에서 질병어 14개 강등 · `소비자_기만` · 일반식품 기능성 주장을 놓친다). 정답 · 합성 데이터 · 정답표 v2 모두 Claude 초안이고
    법률 검토 전이다.
  - **실전 「살리기」 수준** — 실제 광고에서 살릴 수 있는 문구 중 살리는 비율은 아직 낮다(학습에 없던 87개 중 살릴 수 있는 20 → 살림 8).
    연습 문제(살리기 40 · 원료명 14)는 Claude 가 만든 문제라 학습 데이터와 말투가 비슷해 점수가 후하다.
  - **평가 표본** — 실제 광고 105개(학습에 없던 87) · 살릴 수 있는 것 20 — 1~2개 차이는 우연과 가르기 어렵다(v10 ↔ v11 · v10 ↔ v12 판단이 그렇다).
  - **v12 의 안전은 모델이 아니라 관문 · 후처리에 기대는 비중이 크다** — v12 는 기능성 주장을 더 적극적으로 쓴다(label_check 없이는 위반 포장 1).
  - **소구력** — 2단계는 안전하지만 단조롭다(「○○에게, 원래 주장」).
  - 보수/균형/공격 3안 — 이번 구조는 위험도 축이 아니라 대상 고객 축이다.
  - 기능성 주장의 전제(제품이 기능성을 인정받았는가) — 관문 · 모델 모두 제품 정보를 모른다. 조건(`mandatory_note`)으로 넘길 뿐이다.
