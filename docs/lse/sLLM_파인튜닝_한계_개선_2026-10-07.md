# 자체 sLLM 파인튜닝 — 한계와 개선할 점 (2026-10-07 · 이서은)

> 위반 문장 재생성(문장 고쳐 쓰기) 모델의 파인튜닝 요약 · 한계 · 개선 계획.
> 수치와 근거의 정본은 [자체 sLLM 결과서](자체_sLLM_결과서_제출본_2026-10-06.md)다 — 이 문서는 그중 판단에 필요한 것만 모았다.

## 1. 파인튜닝 요약

| 항목 | 내용 |
|---|---|
| 하는 일 | 위반 문장 + 판정 코어가 찾은 위반 유형 → **위반만 지운 문장**(+ 필수 병기) 또는 **「고칠 수 없음」** |
| 모델 | `Qwen2.5-3B-Instruct` + LoRA (r 8 · α 16 · q·k·v·o) — 1.5B 는 핵심 내용이 빠져 3B 로 올림 |
| 학습 | 3 epoch · lr 2e-4 · 최대 640 토큰 · bf16 · RTX 3080 10GB 1장 · 외부 API 없음 |
| 데이터 | 학습 1,815행(그중 고칠 수 없음 388) — 팀 골든에서 규칙으로 만든 쌍 · 공정위 의결서 실사례 39쌍(비공개 · 2배 반영) · 직접 작성 · 합성(정답은 공개 원천에서 규칙으로) · 화장품 |
| 출력 형식 | `핵심 주장: …` 한 줄 + JSON(`body` · `mandatory_note` · `placement` 또는 `infeasible`) |
| 버전 선택 기준 | 버전마다 **위반 포장(위반을 그럴듯하게 고쳐 내보냄)이 0인가**를 먼저 보고, 그다음 살림 · 지나친 거절을 봤다 (v1 → v12) |
| 모델 뒤 안전장치 | 후처리(원료명 복원 · 공식 문구 · 조건) → 관문(지어낸 낱말 · 질병 · 효과 수치 차단) → 재판정(판정 코어로 다시 검사) |

결과(학습에 없던 실제 광고 87건): **위반 포장 0** · 불가를 불가로 58 · 살릴 수 있는 20 중 살림 8 · 지나친 거절 4 · 보류 17.

## 2. 한계

### 2-1. 모델 자체

| 한계 | 내용 · 근거 |
|---|---|
| 살리는 비율이 낮다 | 살릴 수 있는 실제 광고 20개 중 **8개(40%)**. 나머지는 보류(사람 검토) — 안전 쪽으로 기울게 만든 결과다 |
| 안전의 상당 부분이 규칙 덕분 | v12 는 기능성 주장을 적극적으로 쓴다. 위반 포장 0 은 **관문 · 후처리가 막아서** 나온 수치다 — 모델만 떼어 쓰면 0이 아니다 |
| 후보가 1개뿐 | 팀 설계의 후보 3안(D-34) · 재판정 탈락 시 다시 만들기(D-126 K=2)가 아직 없다 — 탈락하면 바로 보류로 간다 |
| 속도 | 문장당 4~12초 · 앱에서 재판정 포함 10~20초 · 요청을 하나씩 처리한다(동시 사용자 대응 없음) |

### 2-2. 데이터 · 평가

| 한계 | 내용 · 근거 |
|---|---|
| 정답이 법률 검토 전 | 학습 정답 · 정답표는 Claude 초안 → 이서은 확인. 법률 전문가 검토는 받지 않았다. 정답표 v2(74개)는 사람 검토 대기 |
| 실제 광고 수치가 낙관적일 수 있다 | 10-05 에 정답표 v2 결과를 보고 관문 · 후처리를 보강했다 — 「학습에 없던 87개」는 **규칙을 조정할 때 본 문구**다. 10-06 부터는 그 문구로 조정하지 않는다 |
| 표본이 작다 | 살릴 수 있는 실제 광고가 20개라 1~2개 차이는 우연과 가르기 어렵다. 연습 문제(살리기 40 · 원료명 14)는 직접 만든 문제라 점수가 후하다 |

### 2-3. 앱에 붙였을 때 (10-07 실제 앱 시연에서 확인)

| 한계 | 내용 |
|---|---|
| 고쳐 쓸 문장이 적다 | 판정 코어가 인코더 없이 사전으로만 돌아(`encode 0.0 ms`), 많은 문장이 「보류 · 확신 부족」만 받고 **위반 유형이 붙지 않는다** → 고쳐 쓰기 버튼이 안 뜬다. 시연 세트 10개 중 앱에서 버튼이 뜬 것은 오미자청 · 다이어트 2개 |
| 화장품은 앱에서 아직 못 보인다 | 모델은 화장품 공식 문구 + 조건으로 고치지만(결과서 §1), 지금 판정 코어가 화장품 문장에 유형을 붙이지 않는다 |
| 「통과」를 낼 수 없다 | 재판정은 「위반 못 찾음(통과 아님)」까지만 말한다 — 판정기가 아는 위반만 찾기 때문 |
| 오탐 | 사전이 식약처 인정 기능성 문구를 `건강기능식품_오인` 으로 잡는 경우가 있다 — 제대로 고친 문장이 보류될 수 있다 (사전 개편 중) |
| 따로 띄우는 GPU 서버 | sLLM 은 GPU 가 있는 PC 에서 별도 프로세스로 띄워야 한다. 원격 환경에서는 바로 보여줄 수 없다 |

## 3. 개선할 점 (우선순위)

| # | 할 일 | 기대 효과 | 의존 |
|---|---|---|---|
| 1 | **정답표 v2 사람 검토 → 다시 측정** | 수치의 신뢰도 — 지금 수치가 낙관적일 수 있는 문제를 정리 | 팀원 검토 |
| 2 | **인코더 연결 뒤 재판정 다시 확인** | 위반 유형이 붙는 문장이 늘어 고쳐 쓰기 대상이 늘고, 재판정의 오탐이 줄어든다 | 판정 담당 · 사전 개편 |
| 3 | **재판정 탈락 시 다시 만들기(K=2) · 후보 3안** | 첫 후보가 막혀도 다른 표현을 시도 → 살림 비율 ↑ | 팀 판단(D-126 · D-34) |
| 4 | 관문이 막는 화장품 공식 표현 보정(염모 · 내수성 등) | 맞게 고친 화장품 문장이 보류되지 않게 | 1번 뒤 · 학습 정답과 직접 만든 문제로만 회귀 |
| 5 | 살리기 데이터 보강 — 지나친 거절 4건의 꼴(사실이 섞인 문구) | 안전을 유지하며 살림 ↑ | 위반 포장 0 유지가 조건 |
| 6 | 평가셋 키우기 — 정답표 원천을 판정 평가 원천과 분리 | 1~2개 차이를 가를 수 있는 크기 · 누수 걱정 없음 | D-175 팀장 판정 |
| 7 | 속도 · 동시 처리 — 배치 · 양자화(4bit) 검토 | 여러 사용자 대응 · VRAM 절감 | 품질이 떨어지지 않는지 다시 측정 |

### 10-08 반영

| 한 일 | 결과 |
|---|---|
| 관문에 「뜻 바뀜」 규칙 — 「대신 · 없이 · 무첨가 …」가 빠졌는데 대상은 남으면 보류 | 「국산 당면 대신 곤약면」 → 「국산 당면 곤약면」을 막는다 · 학습 정답 과잉 보류 늘지 않음(111) |
| 추론 프롬프트 실험 4종(멘토링) — 같은 모델 · 프롬프트만 바꿈 · 직접 만든 69문항 | **P1(학습 프롬프트 + 보존 규칙 한 줄) 채택**: 살림 49 → 54/57 · 포장 0 · 막음 12/12 · 뜻 바뀜 2 → 0 |
| 실제 광고 87 다시 잼(채택 뒤 한 번 · 보고 고치지 않음) | 포장 0 유지 · 살림 8 → 8 · 지나친 거절 4 → 4 · 불가 1건이 보류로(관문이 막음) — **안전은 그대로, 실제 광고에서 살림 개선은 없었다**(관계어가 든 실제 광고가 드묾) |
| 알게 된 것 | 예시(few-shot)를 넣으면 「고쳐라」 쪽으로 끌려 포장 1 · 학습과 다른 새 프롬프트는 포장 4 — **학습한 프롬프트 꼴에서 멀어지면 학습한 판단이 무너진다** |

### 10-08 베이스 4B 시험 학습 (라이선스)

Qwen2.5-3B 는 `qwen-research` 라이선스(이용 제한) · Qwen3-4B-Instruct-2507 은 `apache-2.0` — 4B 로 옮기자는 논의에 따라 v12 와 **같은 데이터 · 설정**으로 베이스만 바꿔 학습했다(`q4b-v12` · 68분 · 학습 최대 VRAM 9.6GB / 10GB).

| 평가 | 3B v12 (P1) | 4B q4b-v12 (P1) |
|---|--:|--:|
| 내장 평가 167 — 고칠/못 고칠 판단 | 160 | 161 |
| 직접 만든 69 — 살림 · 포장 · 막음 | 54/57 · 0 · 12/12 | 55/57 · 0 · 12/12 |
| **실제 광고 87 — 위반 포장** | **0** | 🔴 **3** |
| 실제 광고 87 — 불가를 불가로 · 살림 · 지나친 거절 · 보류 | 57 · 8 · 4 · 18 | 49 · 7 · 5 · 23 |
| 속도(69문항) | 451초 | 515초 |

→ **4B 는 이대로 채택하지 않는다.** 4B 는 고칠 수 없는 문구도 고쳐 쓰려 하는 경향이 있고(불가 57 → 49), 대부분은 관문이 막았지만 3건은 빠져나갔다(사례집 · 거짓_과장 1 · 소비자_기만 2).
🚨 이 3건을 보고 관문을 고치지 않는다(정답표 v2 · 팀장 전달 §3). 직접 만든 「고칠 수 없음」 문제(12개)는 4B 의 약점을 못 잡았다 — **직접 만든 불가 문제를 늘려** 그걸로 4B 를 보강(데이터 · 에폭)하는 것이 다음이다.

🚨 모든 개선은 **위반 포장 0** 을 깨지 않는 범위에서만 채택한다 — v7 처럼 포장이 1건이라도 나오면 탈락.
