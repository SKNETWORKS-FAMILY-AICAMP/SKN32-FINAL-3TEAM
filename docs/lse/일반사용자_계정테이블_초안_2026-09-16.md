# 일반 사용자(마케터·셀러) 계정 테이블 — 스키마 설계 초안

- **작성**: lse (2026-09-16)
- **상태**: 초안 · 팀장 승인 전 (`app/models.py`·`db/**`는 등급1 락)
- **배경**: D-66은 "일반 사용자 가입은 진입점 B 엔진과 함께 온다"며 계정 테이블을
  미뤄뒀다. 2026-09-16 한빈님이 지금 시점에 테이블을 만들자고 판단 — 이 문서는
  그 판단을 반영한 초안이다. **테이블 신설 여부·시점 결정은 한빈님 몫**이고,
  이 문서는 "만든다면 이런 모양"을 화면(login/signup/mypage)에 이미 그려둔
  필드 기준으로 제안하는 것.
- **전제**: `app/models.py`의 `AppAccount`(governor 전용) 패턴·`WorkDoc.owner_id`
  (D-129, 수명 키) 설계를 그대로 따른다 — 새 개념을 만들지 않는다.

## 왜 `app_account`를 그대로 못 쓰나

`app_account.role`은 `CHECK (role in ('governor'))`로 DB가 못 박아뒀다
(D-66 — "행동이 역할을 정한다", 역할을 늘리면 "진짜 마케터인가" 검증 문제가
생긴다는 이유). 일반 사용자를 여기 넣으려면 이 CHECK부터 풀어야 하는데,
governor(거버넌스 콘솔 로그인·2인 확인 서명)와 일반 사용자(셀프서비스 가입)는
**가입 경로·인증 방식·권한 범위가 완전히 다르다** — 같은 테이블에 role만
늘려 구분하면 나중에 "이 계정이 governor 서명 자격이 있는가"를 매번 role
분기로 검증해야 한다. 별도 테이블(`user_account`)로 가는 걸 제안한다.   

## 제안: `user_account` (신규 테이블)

가입 화면(`signup.html`)에 이미 그려둔 필드 그대로다 — 새 요구사항을 만들지 않았다.

```python
class UserAccount(Base):
    """일반 사용자(마케터·셀러) 계정 — 클라우드 에디션 셀프서비스 가입 (D-66 개정).

    🚨 governor(`AppAccount`)와 분리한다 — 가입 경로·인증 방식이 다르다
       (governor는 `admin-add` 주입, 이쪽은 이메일 인증 셀프가입).
    🔴 `pw_hash`는 `AppAccount`와 같은 PHC 포맷 강제 — argon2id 외 경로를
       DB가 막는다 (P1-7).
    🚨 약관·진단 면책 동의는 **가입 시점 타임스탬프로 남긴다** — 나중에
       "동의했다/안 했다" 분쟁이 생기면 이 열이 증거다. bool로만 두면
       "언제 동의했는지"가 사라진다.
    """

    __tablename__ = "user_account"

    id: Mapped[uuid.UUID] = _pk()
    email: Mapped[str] = mapped_column(String(120), unique=True, index=True)
    pw_hash: Mapped[str] = mapped_column(String(200))
    name: Mapped[str] = mapped_column(String(40))
    org: Mapped[str | None] = mapped_column(String(60))  # 마이페이지 "소속 조직"

    email_verified_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True))
    terms_agreed_at: Mapped[datetime] = mapped_column(DateTime(timezone=True))
    # signup.html 두번째 체크박스 — "진단은 법적 확정 판단이 아니다" 이해 동의
    diagnosis_disclaimer_agreed_at: Mapped[datetime] = mapped_column(DateTime(timezone=True))

    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
    last_login_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True))
    # 🚨 지우지 않고 끈다 — AppAccount와 같은 이유 (접속기록이 가리킬 행이 남아야 한다)
    disabled_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True))

    __table_args__ = (
        CheckConstraint("pw_hash LIKE '$argon2id$%'", name="ck_user_account_phc"),
    )
```

## 제안: `user_ad_preference` (신규 테이블, 1:1)

마이페이지 "광고 기본값" 폼(`mypage.html`)에 이미 그려둔 4개 필드. 별도
테이블로 뺀 이유 — **판정에 쓰이지 않는 참고용 기본값**이라서 계정 본체와
갱신 주기가 다르고(자주 바뀜), `user_account`를 무겁게 만들지 않으려는 것.

```python
class UserAdPreference(Base):
    """마이페이지 "광고 기본값" — 검수·카피생성 화면의 초기값일 뿐, 판정 입력이 아니다.

    🚨 `category_default`는 **참고용**이다 — 실제 판정 카테고리는 사용자가
       고르지 않고 우리가 판별한다 (D-82). 이 열을 판정 로직이 읽으면 안 된다.
    """

    __tablename__ = "user_ad_preference"

    id: Mapped[uuid.UUID] = _pk()
    user_id: Mapped[uuid.UUID] = mapped_column(
        UUID(as_uuid=True), ForeignKey("user_account.id"), unique=True, index=True
    )
    age_range: Mapped[str | None] = mapped_column(String(10))   # "10대".."전연령"
    sex: Mapped[str | None] = mapped_column(String(4))          # "여성"·"남성"·"무관"
    channel: Mapped[str | None] = mapped_column(String(10))     # "상세페이지"·"인스타"·"기사형"·"유튜브"
    category_default: Mapped[str | None] = mapped_column(String(10))  # "일반"·"식품"·"건기식"·"화장품"
    updated_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=func.now(), onupdate=func.now()
    )
```

## `work_doc.owner_id`를 여기 연결

D-129 주석이 예고해둔 자리 — `owner_id`는 지금 FK가 없다(비회원 `NULL` 허용).
`user_account`가 생기면:

```sql
ALTER TABLE work_doc
    ADD CONSTRAINT fk_work_doc_owner
        FOREIGN KEY (owner_id) REFERENCES user_account(id);
```

`owner_id IS NULL`(비회원 · 세션+만료로 정리, D-96)과 `owner_id`가 채워진
회원 문서가 공존하는 구조는 그대로 유지 — FK만 추가하고 nullable은 안 건드린다.

## 화면 쪽에서 이미 맞춰둔 것 (참고)

- `signup.html`: name·email·pw·pw2·약관동의·진단면책동의 — 위 컬럼과 1:1.
- `mypage.html` "프로필": name·email·org — `user_account` 갱신.
- `mypage.html` "광고 기본값": age·sex·channel·category — `user_ad_preference` 갱신.
- `login.html`/`mypage.html` "계정" 섹션 로그아웃: 테이블이 생기면 세션 방식
  결정(D-66이 에디션별로 갈랐던 부분 — governor 세션과 합칠지 별도로 둘지)이
  먼저 필요해서, 이 문서 범위 밖으로 남겨둔다.

## 이 문서가 안 정하는 것

- 세션/로그인 방식(JWT vs 서버 세션) — `app/auth.py`(팀장 소유) 판단 영역.
- 이메일 인증 발송 수단(SMTP·서드파티) — 별도 결정 필요.
- 비밀번호 재설정 흐름 — 이번 화면 골격엔 없어서 범위 밖.
