## 1. 🚨 AI Hub 이용정책 제4항 — D-71 이 놓친 조항

**확인한 화면**: <https://aihub.or.kr/intrcn/guid/usagepolicy.do?currMenu=151&topMenu=105>
(2026-08-31 · 브라우저로 직접 열어 전문 확인)

원문 두 조항:

> 제4항 — *"본 AI데이터는 **인공지능 학습모델의 학습용으로만** 사용할 수 있습니다."*
>
> 제5항 — *"제공 받은 AI데이터 등을 …승인을 받지 않은 다른 법인, 단체 또는 개인에게
> **열람하게 하거나** 제공, 양도, 대여, 판매하여서는 안됩니다."*

### D-71 은 뒤집히지 않습니다 — 축이 하나 더 있었습니다

| 축 | FAQ | 이용정책 | 결론 |
|---|---|---|:-:|
| 데이터 재배포 | 원칙 불가 | 제5항 제공·양도·대여·판매 금지 | ❌ `NOREDIST` **일치** |
| 모델·서비스 배포 | *"자유롭게 배포·활용 가능"* | 제7항 주어는 **「AI 데이터셋의 판매」** | ✅ **U4 유지** |
| 🚨 **학습 외 용도** | 언급 없음 | 🚨 **제4항 「학습용으로만」** | ❌ **새로 닫힘** |

★ **제7항의 주어를 정확히 읽는 것이 관건입니다** — *"AI 허브에서 제공하는 **AI 데이터셋의
판매 등** 상업적 이용"* 이므로 **데이터셋을 파는 것**이지 **데이터로 학습한 모델을 파는 것**이
아닙니다. FAQ 와 모순이 아니고, 그것이 `NOREDIST` 입니다.

🚨 **그러나 제4항은 FAQ 에 대응물이 없습니다.** *"학습모델의 학습용으로만"* 은 **RAG 인덱싱과
화면 인용을 덮지 않습니다** — 둘 다 학습이 아닙니다. 제5항의 *"열람하게 하거나"* 가 화면 인용을
한 번 더 막습니다.

### 반영할 용도 벡터 — AI Hub 6종

`aihub_71486` · `aihub_71723` · `aihub_558` · `aihub_71694` · `aihub_71843` · `aihub_review`

| | 현행 | **정정** |
|---|:-:|:-:|
| U1 학습 (`u.train`) | ok | ✅ ok |
| 🚨 **U2 원문색인 (`u.raw`)** | ok | ❌ **no** — 색인은 학습이 아니다 |
| 🚨 **U3 화면인용 (`u.cite`)** | ok | ❌ **no** — 제5항 「열람하게 하거나」 |
| U4 배포 (`u.deploy`) | ok | ✅ ok |

**실무 영향은 한 곳입니다** — `aihub_71723`(법률·규정 텍스트)을 **RAG 인덱스에 넣을 수 없습니다.**
다만 법령 본문은 **법제처 API(G3·제약 없음)로 이미 받으므로 대체됩니다.** 71723 은 학습용으로만 씁니다.
`aihub_71486`(측정 축)·`aihub_review`(세그먼트)는 애초에 학습·군집 용도라 **영향 없습니다** — D-74 성립.

⚠️ **국외 반출은 별도 합의 대상입니다**(이용정책 제3항). **AWS 는 서울 리전으로 고정**해야 하며,
D-78 ③의 반출 판정에 축이 하나 붙습니다.

### D-72 를 한 단계 정교하게 만듭니다

🚨 **FAQ 가 더 정확한 것이 아니라 둘 다 읽어야 합니다** — **FAQ 는 「막히지 않는 것」에 밝고
약관은 「막히는 것」에 밝습니다.** 한쪽만 보면 각각 **반대 방향으로** 틀립니다.

## 2. 식약처 저작권정책 — `mfds_press` 에 `BY` 가 빠져 있었습니다

**확인한 화면**: <https://www.mfds.go.kr/wpge/m_34/de010803l001.do>
**보도자료 게시판**: <https://www.mfds.go.kr/brd/m_99/list.do> (둘 다 직접 열어 확인)

- 저작권법 **제24조의2** — 공공저작물이므로 **별도 허락 없이 이용 가능**
- **제36조** — 번역·편곡·**개작 가능**
- 🚨 **제37조 — 출처 명시 의무** → **`constraints: ['BY']`** (현재 `[]`)
- 🚨 *"**공공누리가 부착되지 않은** 자료를 사용하려면 게시물 등록 부서 담당자와 **사전 협의**"*
  → **게시물마다 부착 여부가 다르므로 프래그먼트 단위 확인 사항** (D-18)

반영할 값 (`mfds_press`):

```js
url:'https://www.mfds.go.kr/brd/m_99/list.do',
evidenceUrl:'https://www.mfds.go.kr/wpge/m_34/de010803l001.do',
constraints:['BY'],
verified:true,
caution:'… 🚨 저작권정책상 공공누리가 부착되지 않은 게시물은 등록 부서와 사전 협의가 필요하다 — 프래그먼트마다 부착 여부를 확인한다 (D-18).'
```

## 3. 참고만 — D-99·D-100·D-101 과 겹칠 수 있는 제안 2건

이미 「판정 근거를 옆 파일로」(D-99) · 「ALIAS + 게이트 19」(D-100) · 「미확인 채점」(D-101)로
푸신 영역이라 **그대로 쓰지 마시고 겹치는지만 봐 주십시오.**

**① `evidence_url` 과 접근 `url` 의 분리** — 생성기가 `url` 하나를 두 필드에 넣고 있었습니다.
AI Hub 는 접근 URL 이 데이터셋 페이지이고 **판정 근거는 이용정책 페이지**라, 검토자가 링크를
열면 판정자가 본 화면이 나오지 않습니다. 🚨 **추정한 URL 은 빈 칸보다 나쁩니다** — 빈 칸은
*"미확인"* 이라 말하지만 추정값은 *"확인됨"* 이라고 거짓말합니다. (D-101 과 같은 문제의식으로 보입니다.)

**② 자체 산출 통계의 근거는 `derived_from`** — `self_sanction_stat` 이 G3 인 이유는 라이선스
페이지가 아니라 **원천(공정위 의결서·식약처 행정처분)이 전부 G3** 이기 때문입니다.

```yaml
self_sanction_stat:
  derived_from: [ftc_decisions, mfds_sanctions]
```

게이트로 *「파생 소스의 allow 집합은 모든 원천의 allow 집합에 포함된다」* 를 검사하면,
**원천 하나가 G2 로 내려갈 때 파생 통계도 자동으로 걸립니다.** URL 로 적으면 사람이 읽어야 압니다.
