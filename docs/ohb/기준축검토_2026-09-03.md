**D-69 제목이 그 자체로 답이다** — *「판정 무료 / 생성 유료」가 아니라 「sLLM을 쓰는가」*.

| | |
|---|---|
| **D-69 결정** | (d) **sLLM 을 쓰지 않는 것까지 무료 / sLLM 을 쓰면 유료** |

| **기각 이유** | *"대체 문구를 전부 유료로 밀면 무료 티어가 선행 도구보다 못해진다"* |

🚨 **규칙 기반 변환(R1~R3) · 병기 문구 3종 세트 · 주장 원장은 「생성」이지만 sLLM 이 없다.** D-69 기준으로 **무료 구간**이고, 그것이 8-3 절 **Phase 2 안전선과 정확히 겹친다.**

**어긋난 자리 셋**

| 어디 | 무엇 |
|---|---|
| 🚨 **기획서 7-6절 발표 문장** | *"무료 구간(판정)은 클라우드에 있습니다. 유료 구간(생성)은 GPU가 필요해서…"* — **우리 문서가 먼저 좁게 말했다** |

## 2. 내가 「판단 필요」라 했던 것 셋 — **둘은 이미 답이 있었다**

### ① 위험도 축 / 판정 상태 축 → **D-09 가 답을 갖고 있다**

내가 어제 든 근거는 *"순서형이라 MAE·QWK 가 무효가 된다"* 였다. **더 강한 근거가 이미 있다.**

> **D-09 · 안전 방향 단조성 — 위험도 래칫**
> *"코드가 하한을 걸고 인코더는 **최대 +1등급까지 올릴 수만** 있다."*

🚨 **래칫은 전순서(total order) 위에서만 성립한다.** 「판정 보류」와 「근거 불일치」는 **서로 비교할 수 없다** — 어느 쪽이 더 위험한지 정의되지 않는다. **순서가 없는 값을 래칫에 넣으면 `max()` 가 정의되지 않는다.**

**즉 이것은 「정해야 할 문제」가 아니라 「D-09 가 이미 금지한 것」이다.**

| 축 | 값 | 정하는 주체 | 근거 |
|---|---|---|---|
| **위험도** | 4단계 순서형 — 형사 리스크 / 과징금 / 업무정지 / 주의 | 코드 하한 + 인코더 +1 | **D-09** |
| **판정 상태** | 확정 / 보류 / 근거 불일치 | 그래프 (모델 아님) | D-83 · 3-3 인용 검증 |

관리자 3종 분포는 **위험도 4단계를 접은 뷰**다 — 새 축이 아니다.
**남은 것은 판단이 아니라 기록이다** — 사실원장에 한 줄 등재하면 끝난다.

### ③ `U-USER` 를 어디에 넣는가 → **이름부터 축을 잘못 말하고 있다**

> **D-15** — 게이트의 축은 **G0~G3(등급) × U1~U4(용도)** 다.

내가 붙인 이름 **`U-USER` 는 U 축(용도)처럼 보이는데 실제로는 G 축(등급)에 넣으려던 값**이다. 🚨 **D-99·D-100 이 경계한 「같은 기호, 다른 뜻」 그 형태다.**

**그리고 더 나은 자리가 이미 있다.**

> **D-73** — 🚨 **막는 지점을 구분한다** — 수집(`NOSTORE`) / 데이터 재배포(`NOREDIST`) / 산출물 공개(`PREAPPROVAL`) / 런타임(`QUERYLOG`)은 **각각 다른 축**이다.

사용자 업로드물의 문제를 한 줄로 쓰면 **「수집(=서비스 입력)은 해야 하고, 학습만 막아야 한다」**이다. 이것은 **등급 문제가 아니라 정확히 D-73 이 말한 「막는 지점」 문제다.**

| 안 | 형태 | 판정 |
|---|---|:-:|
| `U-USER` 등급 신설 | G 축에 값 추가 | ❌ 이름이 U 축을 참칭 · 판정매트릭스(소스 73종)와 1:1 대응이 깨진다 (D-99) |
| G1 로 처리 | 배제 | ❌ **G1 은 수집 자체 금지**인데 업로드물은 받아야 한다 |
| G0 로 처리 | 미확인 | ❌ **D-106** — G0 는 「확인 전」이지 「확인했더니 이렇다」가 아니다 |
| ★ **`NOTRAIN` 플래그** | **D-73 축의 다섯째** | ✅ 축이 맞고, 등급표를 건드리지 않고, 게이트가 한 줄이면 된다 |

**권고 — D-121 을 정정한다.** 등급 신설이 아니라 **D-73 축에 `NOTRAIN` 을 더한다.**
게이트는 게이트 17번과 같은 형태다 — **「`NOTRAIN` 이 붙은 저장 경로가 학습·색인 코드에서 참조되면 실패」**.
보관·파기는 **D-96**(동의는 기능이 아니라 데이터 수명을 가른다)이 이미 자리를 잡아 뒀다 — P1-6 만 인용한 것은 부족했다.

## 3. 새로 드러난 충돌 둘 — **여기가 진짜 판단이 필요한 자리다**

### ① D-120(입력 형태를 묻는다) vs **D-61 · D-82(묻지 않는다)**

> **D-61** — 사용자에게 **되묻지 않는다.** 되묻기는 *"세션 시작 시 제품 프로필 1회"* 로 한정한다.
> **D-82** — 카테고리를 사용자에게 묻지 않는다. 🚨 *"「선행 지식 요구」가 선행 도구들의 공통 실패다."*

D-120 은 **입력 형태를 사용자가 고르게** 한다. 문장만 보면 정면 충돌이다.

**갈리는 지점은 「누가 아는가」다.**

| | 카테고리 (D-82) | 입력 형태 (D-120) |
|---|---|---|
| 누가 아는가 | 🚨 **우리가 판별할 수 있다** — 사용자는 모를 수 있다 | **사용자만 안다** — 우리는 텍스트만 보고 알 수 없다 |
| 틀리면 | 우리 책임 (D-82 가 그렇게 정했다) | 판정 범위가 달라진다 |
| D-61 의 위험 | 자기 신고가 **통과 판정의 근거**가 된다 | 🚨 **아니다** — 입력 형태는 통과/불통과를 직접 가르지 않는다 |

★ **D-61 의 진짜 금지선은 「자기 신고가 미탐을 만드는 경로」다.** 입력 형태 선택은 **판정 대상의 경계**를 정할 뿐 **판정 결과를 유리하게 만들지 않는다** — 오히려 「긴 글」을 고르면 검사가 **늘어난다.**

**판단 필요 — 둘 중 하나를 골라야 한다.**

| 안 | 내용 | 대가 |
|---|---|---|
| **(가)** | D-120 을 유지하고, **D-61 의 예외 조건**을 명문화한다 — *"되묻지 않는 것은 「판정을 유리하게 가르는 전제」다. 판정 대상의 경계는 사용자만 알 수 있으므로 묻는다"* | 문장 하나. **지금 안 적으면 다음 사람이 D-61 위반으로 읽는다** |
| **(나)** | 묻지 않고 **자동 추정**(길이·개행·주제 일관성) | 🚨 D-120 이 이미 기각했다 — *"추정이 틀리면 조용히 틀린다"*. 그리고 **틀린 방향이 미탐(층 3 미적용)이라 안전 방향 단조성 위반** |

**권고 (가).** 다만 **안전한 기본값**을 함께 정한다 — 🚨 **모르면 「긴 글」로 본다.** 층 3 을 걸어 **검사를 더 하는 쪽**이 안전 방향이다 (D-09 의 정신).

### ② 관리자 「이의제기 심사」 화면 vs **D-76**

> **D-76** — 화면을 사용자·관리자로 분리한다. 🚨 **관리자는 구조화 값의 집계만 본다.**
> **보안점검 P1-4** — *"열람 경계를 화면에만 그었다. D-76 표에 「사용자 입력 문구 원문 ❌」이라 써 놓고 **로그로는 다 보이는 상태**다."*

내가 MVP **핵심**으로 남긴 관리자 화면 중 **`CL-A-088/089` 이의제기 심사**는 성질이 다르다 — **판정이 틀렸다는 주장을 심사하려면 그 문구 원문을 봐야 한다.**

**즉 이 화면은 D-76 의 예외를 요구하는 첫 화면이다.** 지금은 그 예외가 어디에도 정의돼 있지 않다.

**판단 필요**

| 안 | 내용 |
|---|---|
| (가) | **사용자가 이의제기 시 원문 열람에 동의**한 건만 원문을 연다 — **D-96**(동의가 데이터 수명을 가른다)의 자연스러운 확장 |
| (나) | 원문 대신 **판정 근거 스팬만** 연다 (주장 스팬 추출 결과) — D-76 을 안 깬다. 대신 심사 정확도가 떨어질 수 있다 |
| (다) | 이의제기 심사를 **부가**로 내린다 — 핵심 34 → 32 |

**권고 (가).** D-96 이 이미 *"동의는 기능이 아니라 데이터 수명을 가른다"* 로 같은 형태를 풀었다. **새 원칙을 만들지 않고 있는 것을 확장하는 쪽**이 이 프로젝트의 방식이다(D-108 이 쓴 방법).

## 4. 기준축이 답을 주지 않는 것 — 선례가 없다

**요구사항 ID 체계 이원화** (`REQ-U/A` 화면 단위 vs `REQ-N/T/I` 항목 단위).
D-01~D-121 어디에도 ID 체계에 대한 결정이 없다. **선례가 없으므로 이것은 새 결정(D-122 후보)이다.**
※ 팀원의 **05 시트가 이미 화면별 수용 기준**을 갖고 있다 — 화면은 수용 기준으로, ID 추적은 항목 단위로 가르는 쪽이 새로 만들 것이 가장 적다.

## 6. 이 검토가 말하는 것

**121건의 결정이 실제로 작동했다.** 오늘 만든 산출물을 그 축에 대보니 **어긋남 넷이 즉시 드러났고, 그중 둘은 내가 「새로 정해야 한다」고 오판한 것**이었다.

🚨 그리고 **가장 값어치 있는 발견은 ②다** — *"판정 무료 / 생성 유료"* 는 **우리 기획서가 먼저 좁게 말했고**, 내 산출물이 그것을 세 곳으로 늘렸다. **틀린 표현은 복제된다.** D-54 가 수치에 대해 말한 것이 **용어에도 그대로 성립한다.**
