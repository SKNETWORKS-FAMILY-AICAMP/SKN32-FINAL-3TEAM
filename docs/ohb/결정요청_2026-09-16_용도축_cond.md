## ② 판정 — 항목별

### 🔴 치명 · 축 혼동 — `cond` 한 칸이 **셋**을 지고 있다

`scripts/gen_registry.py:106-112`

```python
def use_vector(s):
    """매트릭스 u → use. cond/unknown 은 등급 상한에 걸어 fail-closed."""
    ...
    allow = 1 if v == "ok" else (1 if v == "cond" and s["grade"] == "G2" else 0)
    allow &= GRADE_CAP[s["grade"]][u]
```

`docs/03_데이터/_matrix/sources.json` 82건 전수 계산 — `cond` 를 든 원천 **19** · 축 **27**.

| 뜻 | 어디 | 원문 근거 |
|---|---|---|
| ① **법적 조건부** | G2 쪽 | `modu_web` 「승인이 수집 시점에 한 번이 아니라 **산출물을 공개할 때마다** 걸린다」 · `youtube_api` 「audited developer + analytics 유즈케이스에 **한해**」 · `google_trends` 「비공식 내부 엔드포인트 … **학내 프로토타입 한정**」 |
| ② **축 부재** | G3 쪽 | `mfds_casebook` U1 note — 「평가 홀드아웃 전용 … **U 축에 평가가 없어 `cond`**」 |

### `mfds_press_index.jsonl` 은 **원문 색인이 아니다**

클론 A 실측 (2026-09-03 생성 · 1,100,116 B):

**본문을 담는 칸이 없다.** `no`(게시물 번호) · `title`(제목) · `qs`(쿼리스트링) ·

4,349는 게시물 수이고 **우리가 받은 원문은 210개**다.

⛔ **그래서 앞서 「index 가 있으니 U2 를 쓰고 있다」고 한 것은 틀렸다.** U2 를 쓰고 있다는

`GRADE_CAP` 주석이 「G2 = 사실만 추출·**원문 미보관** → U2 구조적으로 불가」라 적으므로,

## ⑤ 판정 요청 — 셋

### (1) 규칙 — `cond` 는 전부 deny 🔴 **권고**

```python
- allow = 1 if v == "ok" else (1 if v == "cond" and s["grade"] == "G2" else 0)
+ allow = 1 if v == "ok" else 0
```

- 얻는 것: **fail-open 8축이 닫힌다**(수집 0건 · **비용 0**) · 등급별 우연한 분기가 사라진다 ·
  코드가 docstring 과 같아진다
- 떠안는 것: G2 5원천을 나중에 쓰려면 조건을 채워 `OK` 로 승격하거나 2인 확인을 거쳐야 한다
- G3 쪽은 **변화 없음** — 지금도 deny 다. `mfds_press` 파생물에 소급 영향 0

### (2) 값 — `raw` 를 `CD` → `OK` (두 원천) 🔴 **권고**

**새 판정이 아니라 D-132 의 미집행분이다.** 새 D 번호는 필요 없다고 본다.

- 고치는 자리: `docs/03_데이터/_matrix/data.js` (**생성물 아님** — 여기가 원천)
- 사슬: `build_matrix.py` → `gen_registry.py` → `extract_rationale.py` → `pytest -m gate`
- 🚨 **확인 필요** — `u` 값 변경이 `scripts/registry_review.yaml` 의 **2인 확인 재서명 대상인지.**
  등급(G3)은 안 바뀌고 용도축 한 칸만 바뀐다. `reviewed_by` 는 사람만 채운다 (D-66)

### (3) 축 신설 — U 에 `eval`(평가 전용) 또는 `reserved: holdout` ⬜ **초안만**

`mfds_casebook` 의 note 가 부재를 직접 적었다 — 「U 축에 평가가 없어 `cond`」.
축이 생기면 `{train: NO, eval: OK}` 로 **정확히** 표현되고, `cond` 에서 뜻 ②가 빠져나간다.
남는 `cond` 는 ①(진짜 조건부)뿐이고, 그때 조건 문구를 필드로 올린다.

🚨 **새 필드를 만들면 읽는 쪽을 같은 작업에서 만든다** (D-99) — 읽는 쪽은 **홀드아웃 분리 게이트**다.
이것 없이 필드만 만들면 아무도 안 읽는 칸이 하나 는다.

### (4) 곁가지 ⬜

- `u.commercial` 이 `AXIS` 에 없다 — 어디서 읽는지 재고, 아무도 안 읽으면 그 자체가 판정거리
- `_matrix/README.md` 의 「소스 73종」 → 82
- `mfds_press_index` 4,349(A) ↔ 4,344(B) · `kogl_badge` 107(A) ↔ 105(B) — **왜 갈렸는지 미측정**

## ⑤ 설계 결정을 건드리는 발견

**새 사실** — `cond` 가 세 뜻을 지고 있고, 그중 ②(축 부재)는 **U 축 체계의 한계**를 값으로
표현한 것이다. `mfds_casebook` 의 note 가 그것을 스스로 적었다.

**영향받는 결정** — **D-132**(값이 안 내려왔다) · **D-72**(fail-closed 가 fail-open) ·
**D-155**(평가 홀드아웃 — `mfds_press`·`mfds_casebook` 이 홀드아웃 재료로 지목돼 있다) ·
**D-226**(정본 클론 — 반례 후보) · D-40(30건 하한) · D-18 · D-16

★ **앞 문서 §6 #3 「평가 홀드아웃 — 후보 0」이 다시 열릴 수 있다.** `mfds_press` 의 `valueNote`
가 「★ 학습 출처(의결서)와 기관이 다르므로 **평가용 홀드아웃에 최적.** 편향이 독립적이다」이고,
`mfds_casebook` caution 이 「**`mfds_sanctions` 전량과 합쳐야 홀드아웃이 선다(R8)**」이다.
⛔ **다만 「후보 넷이 전부 닫혔다」(앞 문서 §5)의 그 넷에 이 둘이 포함되는지 안 읽었다** —
「없다」가 아니라 「안 봤다」다 (D-188).
