## §3 어느 기기에서든 수집 — 원장이 B 로 모이는가

수집 원장 `data/manifest.jsonl` 은 git 이 따라가므로 **줄은 이미 B 로 온다.** 막히는 곳이 넷이다.

### §3-a 동시 append → git 충돌 [합성 재현]

두 가지에서 각자 끝에 한 줄씩 붙이고 병합 → **CONFLICT**. `.gitattributes` 에 `m.jsonl merge=union` 을 넣고 같은 병합 → **충돌 없이 두 줄 다 남음.**
지금 `.gitattributes` 에 없다. 지금까지 안 터진 것은 **한 번에 한 기기만 수집하고 pull 뒤에 수집했기 때문**으로 보인다(추정).

- ⚠️ union 은 **append 전용 파일에만** 맞다. `derived_manifest.jsonl` 은 통째 재작성이라 union 을 걸면 안 된다 — 그쪽은 B 만 쓴다(D-226)
- 곁가지 — 수집하면 `registry.mark_collected()` 가 `scripts/registry_review.yaml` 의 `collected_at` 을 고친다(`collect/registry.py:212-241`). **git 추적 파일**이라 같은 소스를 두 기기가 받으면 여기서도 충돌한다. 다른 소스면 블록이 달라 보통 자동 병합된다(추정)

### §3-b 원장에 기기 칸이 없다 [컨테이너 실측]

20,399행의 칸은 두 모양뿐이다 — `bytes·fetched_at·path·rows·sha256·source_id·url` (20,270) · `+supersedes` (129).
`doctor` 가 스스로 적어 두었다: *「다른 클론에서 받았다」와 「유실됐다」는 원장으로 구분되지 않는다.*
경로는 20,399행 **전부 `\` 구분자**다 — 팀원 중 macOS·Linux 기기가 생기면 같은 파일이 두 이름이 된다(지금 팀 5인은 Windows · `gate.yml` 주석).

### §3-c 🔴🆕 raw 없는 기기에서 수집하면 판 규칙이 작동하지 않는다

`store.save_raw` (`collect/store.py:258-285`) 는 **그 기기에 같은 이름의 파일이 있을 때만** 판(`__c<날짜>`)을 만든다.

```
권소라 기기 (raw 없음)   page_0001.json 이 없다 → 원본 이름으로 저장 · 원장 행 { path: …\page_0001.json · sha N }
클론 B (raw 있음)        page_0001.json 이 이미 있다 · sha O
git pull 뒤 B            원장에 같은 경로 · 다른 sha 두 행 — 파일은 O 하나
```

- B 는 N 을 **받을 자리가 없다** — 원본 자리에 두면 규약 2(덮어쓰지 않음) 위반, 판 이름으로 두면 원장 행의 경로와 다르다
- `doctor` 는 이것을 🔴 훼손이 아니라 🟡 「팀 최신판 아님」으로 본다 — **조용하다**
- offset 페이징 원천(`mfds_sanctions` · `mfds_press` · `mfds_hf_ingredient_board` · D-149)은 받을 때마다 이 상태가 난다

## §5 ★ 설계 제안 — 「부족한 것을 자동으로 받는다」

### §5-1 핵심 — 내용 주소 저장소

**원장 둘이 이미 「경로 → sha256」을 들고 git 으로 돈다.** 없는 것은 **바이트를 sha256 으로 찾아올 곳** 하나다.

```
<공유 저장소>/objects/<sha256 앞 2자>/<sha256>      ← 파일 이름 = 내용의 해시
```

| 명령 (가칭) | 누가 · 어디서 | 하는 일 |
|---|---|---|
| `data-publish` | 팀장 · **클론 B 만** | 생성물(원천·표본은 git 이 옮긴다)을 저장소에 올린다 — **없는 sha 만** 올린다 · 올리기 전 `--check` 초록 + `--export-check` 초록이 아니면 **멈춘다** · 외부 전송이므로 실행 전 확인 |
| `data-sync` | 누구나 · **런처가 자동으로** | `derived_manifest.jsonl`(git) 과 디스크를 대조 → **없거나 sha 가 다른 파일만** 저장소에서 sha 로 받아 놓는다 → 받은 바이트를 sha 로 다시 검증 → 덮어쓸 파일은 먼저 `..\CopyLane_backup\<시각>\` 로 옮긴다 |
| `raw-collect-in` (3단계) | 팀장 · 클론 B | 팀원이 올린 raw 를 **원장에 이미 있는 행과 sha 로 대조**해 **기록된 경로 그대로** 놓는다 · 원장 행을 새로 붙이지 않는다 · B 에 다른 바이트가 있으면 **판 이름으로 두고 멈춘다 → `adopt`** (§3-c 를 닫는다) |

**왜 이 모양인가**

- 「**부족한 것만**」이 공짜다 — 파일 이름이 해시라 가진 것은 안 받는다. 53 MB 묶음을 매번 통째로 받지 않는다
- **판이 쌓여도 같은 내용은 한 번만** 저장된다 — 판 사이에 안 바뀐 파일이 대부분이다
- 무엇을 받을지는 **git 이 정한다** — 저장소에는 판정이 없다. 저장소가 오염돼도 sha 가 안 맞으면 **받지 않는다** (fail-closed · D-72)
- 파생물 배포(§2)와 raw 합류(§3)가 **같은 기계**다 — 두 번 만들지 않는다 (D-99)

### §5-2 자동으로 도는 자리

| 자리 | 동작 |
|---|---|
| 런처 메뉴를 열 때 | **대조만** 한다 — 「파생물 3개 부족 · 동기화하려면 44」 한 줄. 네트워크 없이 끝난다 |
| 파생물을 읽는 명령 앞 — `golden` `load` `chunk` `embed` `eval` `serve` `demo` | 부족하면 **먼저 `data-sync`** → 초록이 아니면 **그 명령을 멈춘다** |
| `onboard` 마지막 | `data-sync` 를 부른다 — 새 기기(권소라)가 한 번에 선다 |
| 클론 B | **자동 sync 를 하지 않는다** — B 가 방금 다시 만든 파일을 옛 판으로 되돌리면 안 된다 |

🚨 **git pull 은 자동으로 하지 않는다** — 사용자가 직접 친다(작업 규칙). 순서는 `git pull` → 런처.
　 런처는 「원장이 가리키는 것」을 채울 뿐 「원장이 최신인가」는 모른다 — 그것은 git 의 일이다.

## §6 ⬜ 판정 요청

### 판정 ① — 기기마다 「있어야 할 파생물」을 무엇으로 정하나 (§1 · §2-1 · F1 의 공통 뿌리)

**상황** — 검사가 모든 기기에 B 와 같은 151개를 요구해서 CI·클론 A·팀원이 항상 빨강이고, 반대로 게이트 10개는 파일이 없으면 초록이다.
**용어** — 「역할」 = 이 기기가 파생물을 **만드는 곳(정본)** 인지 **받는 곳(사본)** 인지 **아무것도 없는 곳(CI)** 인지.
「상태 규칙」 = 설정값 대신 **기기에 무엇이 있는가**로 검사 강도를 정하는 것.
**영향받는 결정** — D-226 2항(*「`check` 는 파생물을 안 읽는다」* — 이미 거짓 · F1) · D-89 · D-244(초안)

| **(나) ★ 역할 표시 + 상태 규칙** — 원천·표본 = 늘 필수 · 생성물 = 정본이거나 하나라도 있으면 전부 필수 · 원문캐시 = 정본에서만 필수(사본은 무시하고 sync 가 백업으로 치운다) · CI 는 git 5개만 | 설정 하나(`DATA_ROLE`)로 CI 5 · 사본 46 · 정본 151 이 한 규칙에 맞는다 · F1 게이트도 같은 규칙으로 skip → fail | 역할 표시가 틀리면 틀린다(§5-3 의 장치로 좁힌다) · 사본에서 생성물이 **전부** 사라지면 CI 와 구별이 안 된다 — sync 가 다시 채우므로 해가 작다 |

### §11-1 판정 ① — 기기 역할

**다시 쓴 추천** — **`.env` 의 `DATA_ROLE = canonical | replica` + 부류별 규칙.** 모양은 `COPYLANE_EDITION` 을 그대로 따른다.

| 부류 | `canonical` (클론 B) | `replica` (클론 A · 권소라 · 서버) | 역할 없음 (CI · `.env` 없는 곳) |
|---|---|---|---|
| 원천 · 표본 (git 5개) | 필수 · sha 대조 | 필수 · sha 대조 | 필수 · sha 대조 |
| 생성물 41 | 필수 · sha 대조 | 필수 · sha 대조 (없으면 `data-sync` 가 채운다) | 있는 것만 대조 · 없으면 「안 봤다」로 이름을 낸다 |
| 원문캐시 105 | 필수 · sha 대조 | **보지 않는다** — 옮기지 않는 부류다(D-244) | 보지 않는다 |

- **기본값은 「역할 없음」** — 위험한 쪽(`canonical`: 자동 받기를 끄고 올리기를 연다)은 **명시**여야 한다. `COPYLANE_EDITION` 이 `cloud` 를 기본값으로 안 둔 이유와 같다
- `.env.example` 에 `DATA_ROLE=replica` 를 둔다 → `onboard` 가 `.env` 를 만들 때 권소라 기기는 **저절로 사본**이다. 클론 B 만 손으로 `canonical` 로 바꾼다
- **모르는 값이면 안 뜬다** (D-220) — `canonnical` 같은 오타가 조용히 「역할 없음」이 되지 않게
- F1 게이트 10개도 같은 표를 쓴다 — `canonical`·`replica` 에서 파일이 없으면 **skip 이 아니라 fail**

**왜 「raw 가 있으면 정본」 같은 자동 추정이 아닌가** — 클론 A 도 raw 를 가졌다(클론A 인계 §4-2). 자동 추정은 A 를 정본으로 오판한다. 이 저장소가 이미 겪은 일이다.

**떠안는 것** — 클론 B 의 `.env` 가 사라지거나 값이 틀리면 B 가 사본처럼 동작해 **방금 만든 생성물을 저장소의 옛 판으로 되돌릴 수 있다.** 줄이는 장치 둘 — `data-sync` 는 덮기 전에 **항상 백업**하고, **raw 가 있는 기기에서 sync 가 생성물을 덮을 때는 한 번 묻는다**(클론 A 는 한 번 답하면 되고, B 는 거기서 알아챈다).

⚠️ **내가 틀릴 수 있는 곳** — 서버(배포)를 `replica` 로 묶었는데, 서버에는 `.env` 를 사람이 만든다(배포계획 §3). 서버에서 `data-sync` 가 공유 저장소에 닿을 수 있는지(드라이브를 서버에 붙이는 법)는 **안 봤다.** 안 되면 서버만 「묶음 한 번 올리기」로 따로 간다.

### §11-2 판정 ② — 공유 저장소

**평가 축** — ⓐ 권소라가 설치·설정할 것 ⓑ 우리가 짤 코드 ⓒ 공개 사고 위험 ⓓ 지금 규모(생성물 55 MB · raw 약 540~881 MB) ⓔ D-99(원장 두 벌) ⓕ 서버도 받을 수 있나

| 안 | ⓐ 팀원 설정 | ⓑ 코드 | ⓒ 공개 위험 | ⓓ 규모 | ⓔ 두 벌 | ⓕ 서버 |
|---|---|---|---|---|---|---|
| **(가) ★ 우리 도구 + Drive for desktop 폴더** | Drive 설치 · 공유 폴더 바로가기 · `.env` 에 경로 한 줄 | `data-publish`·`data-sync` — **폴더 복사 + sha 검증** (수백 줄) | 낮음 — 공유 대상 지정 | 충분 | ✅ 없음 | ⚠️ Linux 에 Drive 앱이 없다 → `rclone` 이 필요하거나 묶음 한 번 |
| (나) DVC + 로컬 폴더 원격(= Drive 폴더) | Drive + DVC 설치 | 적음 — 다만 **`derived_manifest` 와 `.dvc` 를 맞추는 코드** | 낮음 | 충분 | 🔴 원장 두 벌 | 같음 |
| (다) DVC + Google Drive 원격 직결 | GCP 프로젝트·OAuth 클라이언트 · 브라우저 로그인 | 적음 | 낮음 | 충분 | 🔴 | ✅ 서비스 계정 |
| (라) 비공개 GitHub + LFS | 저장소 초대 · `git lfs install` · 두 번째 클론 | 중간 | 🔴 **공개 origin 과 혼동** | 월 10 GiB 대역폭 — raw 합류까지 가면 빠듯 | ✅ | ✅ |
| (마) HF 비공개 데이터셋 | HF 계정 · 토큰 `setkey` | 중간(`huggingface_hub`) | 중간 — 저장소 공개 전환 한 번이면 공개 | 100 GB | ✅ | ✅ |

**추천 (가).** 이유 셋 —
1. **원장이 한 벌로 남는다.** DVC 는 좋은 도구지만 우리는 이미 원장·부류·마스킹 검사(`--export-check`)를 가진 원장을 git 에 둔다. DVC 를 얹으면 「무엇이 있어야 하나」의 정본이 둘이 된다 — 이 저장소가 가장 여러 번 겪은 사고의 모양이다 (D-99)
2. **팀원 쪽 설정이 가장 적다.** 인증 코드가 0 이고, 권소라는 폴더 하나를 붙이면 된다
3. **바꾸기 쉽다.** 우리 쪽 코드는 「경로에서 sha 로 꺼낸다」 하나라, 나중에 (마)나 서버용 `rclone` 으로 옮길 때 **읽기·쓰기 두 함수**만 바뀐다

🚨 **(가)를 고를 때 같이 정할 것** — D-78 ③ 표를 저장소에 그대로 건다: 저장소에는 **`redistributable: true` 인 소스에서 나온 것만**, 원문캐시·`quarantine`·`g2_norepub` 은 **올리기 전에 코드가 거부**한다. `data-publish` 는 외부 전송이므로 실행 전에 한 번 묻는다.
⬜ 사람이 확인할 것 — 팀이 공유 드라이브(Workspace)를 쓸 수 있는가, 아니면 팀장 개인 드라이브의 폴더를 공유하는가(용량이 팀장 15 GB 에서 나간다).

### §11-3 판정 ③ — 자동은 어디까지

**추천 (나) 그대로 — 파생물을 읽는 명령 앞에서 자동 받기 · 메뉴는 알리기만.** 탐색으로 더한 것 셋 —

- ★ **git 커밋이 데이터 판을 정한다.** `data-sync` 는 **지금 체크아웃된 `derived_manifest.jsonl`** 을 채운다. 사용자가 pull 을 잊으면 **그 커밋의 코드와 맞는 데이터**를 받는다 — 어긋나는 게 아니라 **맞는다.** 저장소는 올린 판을 지우지 않으므로 옛 커밋으로 돌아가도 그 판의 데이터가 선다
- 붙일 자리 — 메뉴(`_invoke`)가 아니라 **명령 함수 자체**다. `uv run python launcher.py load` 처럼 메뉴를 안 거치는 호출이 있다. 데코레이터 하나(`@needs_data`)를 `golden` `load` `chunk` `embed` `eval` `serve` `demo` `search-probe` 에 건다
- 🚨 **그 목록을 손으로 적지 않을 방법** — `derived_manifest.writers()` 가 이미 「어느 모듈이 어느 파생물을 만지는가」를 AST 로 안다. 게이트 하나로 「파생물을 읽는 모듈을 부르는 런처 명령에 `@needs_data` 가 없다」를 잡는다 (D-99 · D-117)

### §11-4 판정 ④ — 권소라가 수집한 raw 를 B 로

**탐색으로 추천이 바뀌었다.** §3-c(판 규칙이 그 기기 디스크에 달렸다)를 **B 에서 뒤처리하지 말고 수집하는 순간 막는다.**

★ **`save_raw` 가 디스크뿐 아니라 원장(git)도 본다** —

```
그 경로의 최신 원장 행이 있고
  ├ 원장의 identity_sha256(없으면 sha256) == 지금 받은 것  →  스킵 (규약 4 가 기기를 넘어 선다)
  └ 다르다                                                  →  판 이름(__c<날짜>)으로 저장 (규약 2 · D-143)
원장에 없다                                                  →  원본 이름으로 저장 (지금과 같다)
```

얻는 것 — ① 권소라가 이미 B 에 있는 것을 **다시 안 받는다**(원천에 부하 · 판 증식 둘 다 준다) ② B 로 올 때 **같은 경로·다른 바이트가 생기지 않는다** — 합류는 「기록된 경로에 그대로 놓기」만 하면 된다 ③ 판이 생기면 B 에서 **기존 `adopt`** 가 그대로 받는다 · 새 명령이 거의 없다

떠안는 것 — `save_raw` 는 수집기 전부가 지나는 자리라 **D-92(원본 무손상)·규약 2·4 의 뜻을 넓히는 판정**이다. 새 D 로 적는다. 테스트는 `test_store_edition.py` 옆에 둔다

**나머지 조각**

| 조각 | 추천 | 이유 |
|---|---|---|
| 원장 기기 칸 | 새 행에만 `device`(`.env` `DATA_DEVICE`, 없으면 호스트 이름) | 옛 행은 그대로 — 「없는 것과 비어 있는 것은 다르다」(`manifest_append` 주석의 규칙) |
| 소스 담당자 | `registry_review.yaml` 블록에 `collector:` — **사람이 쓰는 입력**이고 `require()` 가 이미 여기를 읽는다. 담당이 아닌 기기(`DATA_DEVICE`)의 `collect` 는 **거부** | 「같은 소스는 한 사람」(클론A 인계 §7-3)을 사람의 약속에서 코드로 (D-117). D-211 의 「소유는 승인권이 아니라 기본 담당」과 맞추려면 **거부 대신 경고 + `--force`** 도 가능 — ⬜ 이 강도가 판정이다 |
| raw 바이트 운반 | §5 의 같은 저장소 · **raw 는 올리기만 권소라, 받기는 B 만** | 팀원은 raw 가 필요 없다(`RAW_READERS`). 반대 방향 흐름을 만들지 않는다 |
| AI Hub | 저장소가 `NOREDIST` 소스의 raw 를 **거부** | 개인 승인 원문을 팀원 사이에 넘기는 것이 약관상 되는지 모른다 — 알기 전까지 막는 쪽 (D-71) |
