# 기기 사이 동등성 — 원천 없이 파생물만으로 (2026-09-17)

> 물으신 것: **「집 기기에서 데이터 작업을 하면 다른 기기나 팀원이 이어갈 수 있게 하려는데,
> 반드시 원천 데이터가 필요한가? 파생물만으로 가능한가?」**
>
> **됩니다.** 그리고 우연이 아니라 **게이트가 이미 그 길을 만들어 두었습니다.**

---

## 1. 왜 되는가 — 게이트가 층을 갈라 놨다

```python
RAW_READERS = {"collect", "preprocess"}      # tests/test_governance_layout.py:322
```

`data/raw` 를 읽을 수 있는 것은 그 둘뿐입니다. 실측 —

| 디렉터리 | raw 읽는 파일 | 판정 |
|---|---:|---|
| `collect/` | 9 | raw 를 **만드는** 쪽 |
| `preprocess/` | 18 | 추출기 — raw → derived |
| `scripts/` | 3 | 🔶 실제로는 `doctor.py` 하나(원장 대조용 · `RAW_EXCEPTIONS` 등록). 나머지 둘은 `use:{raw:…}` **축 이름**이 걸린 것 |
| `app/` | **0** | |
| `db/` | **0** | |

그리고 derived 는 **마스킹을 지난 층**입니다 (`test_derived_로_나가는_원문은_마스킹을_지난다`).
즉 **derived 는 설계상 공유 가능한 층**입니다.

| 단계 | 파생물만으로 |
|---|:-:|
| 16 `collect` · 19 `extract` · 20 `scan` | 🔴 **raw 필요** |
| 3 `doctor` · 4 `inventory` | 🔶 「없다」로 찍힌다 — 진단이 빨강일 뿐 고장이 아니다 |
| **21 `golden` · 22 `load` · 23 `chunk` · 24 `embed` · 25 `train` · 26 `eval` · 27 `serve`** | ✅ **전부 된다** |

**881 MB → 53 MB.**

## 2. 재배포는 지금 막히지 않는다 — 다만 **아직** 그렇다

실제로 수집된 13건(`collected_at` 찍힌 것) **전부 `redistributable: true`** 이고
`golden.jsonl`(2026-09-17 갱신 후 6,796행)도 전부 `true` 입니다. 남은 제약은 BY(출처표시) 6건 —
표시 의무이지 공유 금지가 아닙니다.

🚨 **재배포 불가 6건은 전부 AI Hub 이고 아직 안 받았습니다.**
`aihub_71486` · `aihub_71723` · `aihub_558` · `aihub_71694` · `aihub_71843` · `aihub_review_corpus`
— `GATED` + **`NOREDIST`** 입니다.

⛔ **그중 하나라도 받는 순간 이 절의 답이 바뀝니다.** 그때부터 derived 를 통째로 넘기면
안 되고, 행 단위 `redistributable` 로 걸러야 합니다 (D-71 전파 규칙).
지금 안전한 것은 구조가 안전해서가 아니라 **아직 안 받았기 때문**입니다.

## 3. 🔴 걸림돌이었던 것 — 파생물에는 원장이 없었다

```
data/manifest.jsonl    20,395행 · sha256 전부 있음 · raw 전용 · derived 경로 0행
```

그래서 「네가 받은 파생물이 내 것과 같은가」를 **물을 수단이 없었습니다.**
raw 는 sha256 이 있고 derived 는 없었습니다.

### 만들었습니다 — `scripts/derived_manifest.py`

```
uv run python launcher.py derived-manifest            # 표만 (쓰지 않는다)
uv run python launcher.py derived-manifest --write    # data/derived_manifest.jsonl
uv run python launcher.py derived-manifest --check    # 원장 ↔ 디스크 대조 · 다르면 종료코드 1
```

메뉴 **42. 파생물 원장**.

**만든 명령은 손으로 적지 않습니다** (D-99) — 어느 모듈이 어느 파생물에 쓰는지는
코드에 이미 있어서 AST 로 훑습니다. 문자열 `"data/derived/x.jsonl"`, 분절
`ROOT / "data" / "derived" / "x.jsonl"`, 함수 `store.derived_dir(".") / "x.jsonl"`,
f-string `f"law_{kind}.jsonl"` 네 꼴을 다 봅니다.

🔴 **쓰는 곳을 못 찾은 파생물이 있으면 멈춥니다** (D-72) — 분류 없는 파일이 묶음에
섞이면 재배포 가부를 모르는 채로 나갑니다.

## 4. 부류가 셋이다 — 이것이 「무엇을 git 에 넣는가」를 정한다

| 부류 | 뜻 | 어떻게 옮기나 |
|---|---|---|
| **원천** | 사람의 판정. **어떤 명령으로도 다시 안 나온다** | 🔴 **git** |
| **표본** | 명령으로 다시 나오지만 **다시 뽑으면 그 표본이 아니다** — 라벨·κ·평가 수치가 갈린다 | 🔴 **git** |
| 생성물 | 같은 입력에서 같은 것이 나온다 | 파일로 옮기고 **원장만 git** |

`.gitignore` 예외를 그 셋 중 앞의 둘에만 냈습니다.

```gitignore
!data/derived_manifest.jsonl
!data/derived/labels/**
!data/derived/*_labelsheet.jsonl
!data/derived/golden/split_manifest.json
```

⛔ **`!data/derived/**` 한 줄로 열지 않습니다.** 편하지만 53 MB 생성물이 전부 커밋
대상이 되고 매 재생성이 이력에 쌓입니다 (D-90). 게이트가 그 한 줄을 막습니다.

### 🔴 2026-09-17까지 이 예외가 없었습니다

예외가 `data/manifest.jsonl` **하나**였습니다. 그래서 —

```
data/derived/labels/오한빈.jsonl      248행 · 125,569 B   ← 09-17 에 붙인 라벨
```

이 파일이 **git 에도 원장에도 없었습니다.** 그 기기가 죽는 날 되돌릴 방법이 없었습니다.

### 🚨 fail-closed 가 바로 하나를 잡았고, 그것을 고쳤습니다

```
data/derived/casebook2021_labelsheet.jsonl   278행
  → 저장소 안에 만드는 코드가 없다        (2026-09-17 최초 실행)
```

일회용 전사 스크립트로 뽑은 것이었습니다. **만드는 코드가 없다는 것은 다시 만들 수
없다는 뜻**이라 그 파일은 「한 기기에만 사는 원천」이었습니다.

🔄 **`scripts/casebook2021_sheet.py` 로 커밋해 해결했습니다.** 재생성 결과가 기기 파일과
**바이트 동일**입니다 — 161,601 B · sha `999710e20ac3`. 그래서 부류가 「원천」에서
**「표본」**으로 내려갔고(다시 나온다), `UNWRITTEN` 은 **비었습니다.**

★ 이 목록이 비어 있는 것이 정상입니다. 이름이 늘면 「한 기기에만 사는 원천」이 늘었다는 뜻입니다.

🚨 **다만 원천 PDF 는 여전히 `data/raw/mfds_casebook_2021/` 에 없습니다** (실측).
   그러니 이 전사물이 그 원천에 대한 **유일한 기록**입니다 — ⬜ PDF 를 넣고 원장에 등록하는 것은
   남은 일이고, 그때까지 이 전사기를 지우지 않습니다.

## 6. 그래서 이렇게 돕니다

### 팀장 (raw 를 가진 기기)

```
uv run python launcher.py collect <소스>              # 16
uv run python launcher.py extract                    # 19
uv run python launcher.py golden --write              # 21
uv run python scripts/doctor.py --data --hash         # 🔴 raw 가 팀 최신판인가 (D-177)
uv run python launcher.py derived-manifest --write    # 42  ← 원장 갱신
git add data/derived_manifest.jsonl data/derived/labels data/derived/*_labelsheet.jsonl data/derived/golden/split_manifest.json
git commit
```

그리고 **생성물 묶음**(53 MB)을 공유 드라이브에 올립니다.
🚨 `data/raw` 881 MB 는 **올리지 않습니다** — 팀원은 필요 없습니다.

### 팀원 (raw 없는 기기)

```
git pull                                             # 코드 · 문서 · 원장 둘
uv run python launcher.py onboard                    # 2   패키지 · 훅 · .env 틀 · DB
uv run python launcher.py setkey LAW_OC_KEY          # 6   git 에 없다 (D-111)
# ── 공유 드라이브의 생성물 묶음을 data/derived 에 풀어 넣는다
uv run python launcher.py derived-manifest --check    # 42  🔴 여기서 같은지 확인한다
uv run python launcher.py load                       # 22  DB 적재
uv run python launcher.py chunk --dump                # 23
uv run python launcher.py embed                      # 24
uv run pytest -m gate
```

`--check` 가 **초록이면 팀장 기기와 파생물이 동일**합니다. 빨강이면 어느 파일이
없는지·sha256 이 다른지 이름으로 나옵니다.

🔶 `doctor`·`inventory` 는 raw 가 없어 「없다」로 찍힙니다. **정상입니다** —
기기 축과 팀 축이 다르다는 그 사실을 `preprocess/inventory.py` 가 이미 적어 두었습니다.

### 🔄 정정 — raw 쪽 sha256 대조는 **이미 있습니다**

⛔ 처음에 「원장에 sha256 이 20,395행 전부 있는데 대조하는 코드가 없다」고 적었습니다.
**틀렸습니다.** `inventory` 하나만 보고(「파일을 열지 않는다」) `doctor` 를 안 읽었습니다 (D-63).

```
uv run python scripts/doctor.py --data --hash
```

이것이 **세 축**으로 갈라 줍니다 — 제가 제안하려던 것보다 낫습니다.

| 축 | 묻는 것 |
|---|---|
| 🟡 **없다** | 원장에 있고 디스크에 없다 |
| 🔴 **훼손됐다** | 기록된 sha 어느 것과도 다르다 (규약 2 · D-92) |
| 🟡 **팀 최신판이 아니다** | 기록에는 있지만 **가장 나중 기록**과 다르다 (D-177) |

★ 가운데 축만 보면 **09-07 판을 들고 있어도 통과합니다** — 그 판도 원장에 있으니까요.
실측 주석이 그 자리를 이미 적어 뒀습니다: `mfds_hf_ingredient_board` 672개 중 **662개**가
팀 최신 기록과 다른데 `--hash` 는 0 을 냈고, 그래서 세 번째 축이 붙었습니다.
그리고 D-168 — `mfds_press` 처럼 `jsessionid` 가 박히는 원천은 **원문 해시로 못 가릅니다.**

🔶 **남은 것은 코드가 아니라 절차입니다** — `onboard` 는 끝에 `doctor --env` 만 부르고
`--data --hash` 는 아무도 자동으로 부르지 않습니다. 그래서 §6 의 순서에 넣었습니다.
