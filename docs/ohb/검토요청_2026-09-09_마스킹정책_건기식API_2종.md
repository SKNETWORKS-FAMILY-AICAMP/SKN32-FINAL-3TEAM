## 0. 왜 지금인가

두 소스는 **받아 두고 읽는 코드가 없었다.** 추출기를 붙이려면 `apply_policy` 가 정책을
요구하며 멈춘다(D-72 fail-closed). 그래서 정책이 선결이다.

## 1. 원천이 주는 필드

| | `mfds_hf_ingredient` (I-0040) | `mfds_hf_individual` (I-0050) |
|---|---|---|
| 문구 | `FNCLTY_CN` 기능성 내용 (703/873) | `PRIMARY_FNCLTY` 주된 기능성 (547/547) |
| 식별 | `HF_FNCLTY_MTRAL_RCOGN_NO` 인정번호 | 〃 |
| 원료 | `APLC_RAWMTRL_NM` | `RAWMTRL_NM` |
| 섭취 | `DAY_INTK_CN` | `DAY_INTK_LOW/HIGHLIMIT` · `WT_UNIT` |
| 주의 | `IFTKN_ATNT_MATR_CN` | 〃 |
| 🔴 개인·업체 | **`BSSH_NM` 업체명 873 · `ADDR` 주소 868 · `INDUTY_NM` 업종** | **없다 — 원천이 주지 않는다** |

## 2. 실측 (2026-09-09 · 전량)

**담을 필드만** 대상으로 `org`·`addr`·`person` 축을 돌렸다.

| 원천 | 대상 | org | addr | person |
|---|---:|:-:|:-:|:-:|
| `mfds_hf_ingredient` | 873행 × 5필드 | **0** | **0** | **0** |
| `mfds_hf_individual` | 547행 × 7필드 | **0** | **0** | **0** |

**담는 필드에서 축이 건드린 것이 한 건도 없다.** 문구 훼손 위험이 실측으로 0 이다.

## 3. 제안

### 3-1. `mfds_hf_ingredient` — 업체·주소·업종은 **열 단위로 안 담는다** (D-159)

`BSSH_NM`·`ADDR`·`INDUTY_NM` 은 별도 열이다. 마스킹으로 지우는 것이 아니라
**추출기가 애초에 담지 않는다.** `mfds_press` 에서 같은 판정을 했다 —
「마스킹은 셀 안에 섞여 들어오는 것에 대한 **두 번째 방어**지 첫 번째가 아니다」.

축은 **넷 다 켠다.** 실측 0 이라 켜도 잃는 것이 없고, 원천이 회차마다 필드를 바꿀 수 있다.

### 3-2. `mfds_hf_individual` — 개인·업체 축이 **원천에 없다**

그래도 정책을 비워 두지 않는다. 「불필요」인지 「안 적은 것」인지 구분이 안 되기 때문이다.
축은 **넷 다 켠다** (실측 0 · 방어).

## 4. 판정

```yaml
    담는 필드(기능성내용·원료명·인정번호·섭취량·주의사항)에 대해 네 축을 켠다.

  masking: >-
    원천이 업체명·주소를 주지 않는다 (필드 7개에 없다). 그래도 네 축을 켠다 — 방어다.
    실측 2026-09-09 전량 547행 × 7필드 — org 0 · addr 0 · person 0.
```
