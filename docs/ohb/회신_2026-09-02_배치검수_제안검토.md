## 0. 결론 먼저

**배치 검수를 채택합니다.** 그리고 **두 분이 그대로 만드시면 됩니다.**

크롤링·OCR·Creative Package 는 넣지 않습니다. 관리자 화면은 18개 중 3개를 씁니다.
이유는 아래에 전부 적었고, 근거가 되는 결정 번호를 함께 달았습니다.

## 1. 🚨 먼저 확인할 것 — 기획서가 두 벌입니다

제안서가 참조하는 *"Section 29 · 30 · 33"* · *"Create → Check → Adapt → Recheck → Design → Export"* ·
Phase 1~5 는 **우리 기획서에 없습니다.** 우리 것은 **9장 · Phase 0~4** 이고,
`Compliance Judge` · `Channel Agent` · `Layout Agent` · `Creative Package` · `Brief` · `Recheck` 는
저장소 전 문서에서 **0회** 나옵니다.

**그리고 진입점 A/B 가 정반대였습니다.**

| 제안서 | 우리 (기획서 2-5) |
|---|---|
| 진입점 A = **Brief 입력**(생성) | 진입점 A = **검수** |
| 진입점 B = URL | 진입점 B = **생성** |

같은 단어가 반대를 가리키면 **회의가 통하는 것처럼 보이면서 안 통합니다.**

- ⬜ **「CopyLane 고도화 기획서」 파일을 알려 주십시오.** 남아 있으면 두 벌이 계속 돕니다
- 앞으로 용어는 **저장소 문서 기준**입니다. 대응표는 D-105 에 있습니다

### 자주 쓸 대응

| 쓰시던 말 | 우리 말 |
|---|---|
| Compliance Judge | **판정 코어** |
| Revision Agent | **대체 문구 생성 · 재생성 루프** |
| Recheck | **재판정** (최대 K=2회) |
| Claim Checker | **주장 원장 게이트** |
| Channel Agent · Layout Agent | **출력 프로파일 · 템플릿** |
| Phase 1~5 | **Phase 0~4** (+ 날짜 게이트 9/2 · 9/11 · 9/28 · 10/13) |

🚨 **URL·CSV 는 「진입점」이 아닙니다.** 둘 다 **진입점 A(검수)의 입력 취득 방식**입니다.
진입점을 늘리면 *"코어 1개 + 진입점 2개"* 라는 심사용 설명이 무너집니다.

## 2. ✅ 채택 — 배치 검수

**제안서에서 가장 값이 큰 부분입니다.**

| 왜 채택하는가 | |
|---|---|
| 공수 | **판정 코어 위의 for-loop + 집계.** 새 모델 0 · 새 데이터 0 · 판정 코어 변경 0 |
| 시점 | 판정 코어(Phase 0)가 서는 순간 붙습니다 → **Phase 1** 에 배치했습니다 |
| 관리자 화면 | D-76 이 *"인구통계를 안 받으므로 볼 것이 적다"* 고 한 빈칸을 **이것이 메웁니다** |
| 리텐션 | 위험도 추이(8/15 12% → 9/1 9% → 9/15 7%)는 **정기 검수 프로세스**를 만듭니다 |
| 인력 | 🚨 **두 분이 지금 비어 있습니다** (D-94 — T5 피크는 6W). 배치 검수는 판정 코어만 있으면 되고 **화면·집계·리포트가 전부 관리자 UI 담당의 일**입니다 |

### 두 분이 만들 것

```
[Batch Parser]     CSV/엑셀 파싱 · 필수 컬럼 검증 · 행 분리
[Batch Controller] 판정 코어에 fan-out · 진행률
[집계]             위험도별 · 위법유형별 · 카테고리별
[리포트]           엑셀(원본 + 판정 컬럼) — PDF 요약은 여유 시 build_pdf.py 재활용
[관리자 화면]      배치 이력 · 위험도 추이
```

**제안서 §4.3 입력 포맷과 §4.4 출력 예시를 그대로 쓰십시오.** 잘 짜여 있습니다.

### 🚨 만들기 전에 정할 것 하나 — 배치 크기 상한

판정 1건의 원가와 응답시간이 **행 수만큼 곱해집니다.** 상한과 큐잉을 안 정하면
**데모에서 멈춥니다.** 200건이 몇 초인지는 Phase 0 계측(`timings`)이 나오면 바로 계산됩니다.
그 값을 보고 상한을 정하겠습니다 — 그때까지는 **50건으로 잡고 만드십시오.**

### DB 는 준비돼 있습니다

`app/models.py` 에 `batch_run` 테이블을 넣었습니다. `copy_sentence.origin` 에 `'batch'`,
`external_ref` 에 SKU 를 넣으면 됩니다.

> ★ **제안서가 스키마 결함을 하나 찾아 줬습니다.** `product_category` 를 문서에 뒀는데,
> 배치는 한 실행 안에서 SKU 마다 카테고리가 다릅니다(건기식·화장품 혼재).
> D-82 대로 **카테고리는 우리가 판별하는 것**이므로 **판정 결과**로 옮겼습니다.
> 지금이라 컬럼 이동으로 끝났습니다 — 배치를 만들 때 발견했으면 마이그레이션이었습니다.

## 3. ⚠️ 설계까지만 — 플랫폼 연동(URL 크롤링)

**§3.4 의 D-73 분리 논증은 정확합니다.** 크롤(네트워크)과 판정(네트워크 없음)을 가른 그림은
우리 제약을 제대로 읽으셨습니다. 그 부분은 결정 기록에 채택으로 남겼습니다.

**다만 구현은 하지 않습니다.**

`data_sources.yaml` 의 **편입 금지 목록(협상 불가)** 1·4번이 정확히 이것입니다.

```
{쿠팡·네이버·올리브영 리뷰 직접 크롤링, G1, 약관 위반 + robots 금지}
{이커머스 상세페이지 직접 크롤링,      G1, 약관 위반 + 광고주 저작물}
```

제안서가 말하는 것은 *"**우리** 스마트스토어 전 상품"* — **사용자 자신의 페이지**이고,
그건 코퍼스 수집이 아니라 **사용자 입력의 자동 취득**이라 다른 층입니다. 논리는 맞습니다.

🚨 **문제는 그 구분을 지킬 수단입니다.** URL 창에 남의 주소를 넣으면 그대로 긁힙니다.
*"내 페이지만 넣으세요"* 는 **강제할 수 없는 구분**이고, 같은 이유로 어제 이미지 힌트 기능을
기각했습니다(**D-104**). 소유 증명이 붙어야 성립하는데 그건 10주 밖입니다(D-68).

→ `copy_sentence.origin` 에 `'crawl'` **자리만** 두었습니다. 나중에 열 수 있습니다.

## 4. ❌ 기각 — 이유가 전부 기존 결정에 있습니다

| 제안 | 왜 안 되는가 |
|---|---|
| **Phase B — 이미지 OCR** | **D-104** (어제 확정) — 불완전한 OCR 은 *"검수했다"* 는 신뢰를 주면서 놓칩니다. 이미지 골든셋이 없어 **정확도를 주장할 수 없습니다**(유형별 최소 30건 · D-40) |
| **Creative Package · Image Agent · Layout Agent** | **D-93 제약 3** — *"이미지·레이아웃·영상까지 가면 10주가 아니라 다른 제품"* |
| **매출 통계** | 과금은 10주 범위 밖입니다. D-69 는 **경계만** 설계했습니다 |
| **커뮤니티** | D-68 · D-93 이 **명시적으로 뺀 것**입니다 — 콜드스타트가 있어 남이 와야 성립하고, 리텐션 해법으로 나쁩니다 |
| **기업회원 · 사업자등록증 · 인플루언서 인증** | D-68 은 **인구통계조차 받지 않기로** 했습니다. 신원 서류 보관은 다른 종류의 책임입니다 |
| **티켓 · SLA · 판정 이의제기** | 운영 조직이 있어야 성립합니다 |

> 기획서 8-3 이 *"v2 최대 리스크는 기술이 아니라 **범위**다. 다 했는데 깊은 게 하나도 없다가
> 파이널 프로젝트 최악의 평가"* 라고 못박은 자리입니다.

## 5. mockup 은 버리지 않습니다

`appv3.html` 은 **두 분이 화면을 만들 수 있다는 증거**이고, 18개 중 셋은 그대로 씁니다.

| mockup 메뉴 | 우리 쪽 |
|---|---|
| **판정 근거** | ★ **거버넌스 콘솔** — 2인 확인이 코드로 강제되는 것을 눈으로 보여주는 **유일한 화면**(D-76 1번) |
| **품질 통계** | 통계 화면 (D-76 2번 · **새 지표 금지**) |
| **승인 심사** | 소스 등급 2인 확인 (S0-14) |

**「판정 근거」가 특히 중요합니다.** 발표에서 *"거버넌스를 코드로 강제한다"* 를 증명하는 화면이
그것 하나입니다. 지금 mockup 의 형태를 그쪽으로 좁혀 주십시오.
