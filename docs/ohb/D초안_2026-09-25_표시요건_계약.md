# D 초안 — 표시 요건의 계약·층 3 반영 (D-289 ③·④) · 2026-09-25

> 🚨 **초안이다.** 계약(`app/contracts.py`)은 잠금 1급이고 팀원 화면(ksr · lse)이 읽는다 — W3 계약 판에 묶어 판정한다.
> 라벨 쪽(①·②)은 집행됐다. 이 문서는 판정기·계약 쪽 할 일만 적는다.

## 1. 지금 무엇이 틀리게 나가나

| # | 자리 | 지금 | 법 |
|:-:|---|---|---|
| 1 | `SubstBranch` (실증 분기 · B 에만) | 「No.1」에 「실증하면 R1 이하 가능」 · 인정 실증 자료 종류 | 입증 **그리고** 같은 광고에 조사대상·기관·기간 (고시 69549 4.나) |
| 2 | `Certificate` (A·C 에 증명서) | 표시만으로 풀리는 금지(고시 3.거 · 3.너)를 C 로 판정하면 「합법화 불가」 | 식품유형을 14포인트로 표시하면 적법 — 불가가 아니다 |
| 3 | 층 3 공존 규칙 | 표시 요건을 모른다 | 주장 곁에 밝힌 것이 **없으면** 표시 요건 불충족이 확정된다 |

## 2. 제안

| # | 무엇 | 모양 (제안) |
|:-:|---|---|
| ① | `SubstBranch` 에 칸 | `disclosure: list[str] = []` — 같은 광고에 밝혀야 할 것 (조사대상 · 조사기관 · 조사기간 …). 🚨 이름·목록은 라벨의 `표시요건` 과 같은 표에서 온다 — 두 곳에 적지 않는다 (D-99) |
| ② | `accepted_evidence` 완화 | 지금 `min_length=1`. **표시만으로 풀리는 것**(3.아 · 3.거 · 3.너)은 실증 자료가 없다 → `accepted_evidence` 와 `disclosure` 중 **하나 이상** 있으면 된다(검증기) |
| ③ | 증명서 가드 | 문장에 표시 요건이 있으면 `Certificate` 를 내지 않는다 — 검증기가 막는다(지금 「B 에는 증명서 금지」와 같은 자리) |
| ④ | 층 3 규칙 | 주장(1위 · 연구 인용 · 100% · 기능성) **곁에** 요구된 표기가 **없으면** → 확정 위반 + 지시(「같은 광고에 밝히세요」). **있으면** → 실증 분기 유지. 🔴 있음을 통과로 내리지 않는다 — 텍스트로는 그 조사·인용이 맞는지 모른다 (D-220) |
| ⑤ | 평가 대응 | 지시 문안이 `disclosure` 를 담는지 — 해설서 채택 행의 `표시요건`(81행)이 정답이 된다 |
