## ① `foodsafety_ad_monitor` — I0500 · **1층 판정라벨**

**과대광고 모니터링 적발 및 조치정보 (식품, 건식)**

| | |
|---|---|
| 요청 | `http://openapi.foodsafetykorea.go.kr/api/{keyId}/I0500/json/{start}/{end}` |
| 출력 필드 | 업체명 · **제품명** · 처분명 · 처분일 · 조사기관 · 기관연락처 · **위반법령** · **위반내용** · 업체유형 |
| 층 | 1층 판정라벨 |
| 제안 등급 | G3 (같은 계열 셋이 G3) — ⬜ 이용조건 확인 후 확정 |
| 제안 가치 | **A** |
| 총 건수 | ⬜ **미확인** — 안내 페이지의 「100+」는 샘플 표시분이다. 첫 호출의 `total_count` 로 잰다 |

**★ 이것이 `mfds_sanctions` 와 다른 점 — 모집단이 우리 축이다.**
`mfds_sanctions`(I0470)는 전수 5,370건 중 표시광고법이 57, 제8조가 30건이다. 즉 **0.56%**를
골라내야 한다. I0500 은 **「과대광고」 전용 서비스**라 모집단 자체가 다르다.

**마스킹** — `업체명` 이 온다. `대표자명` 필드는 **없다**(안내 페이지 기준).
기존 `org` 축으로 덮인다. ⬜ 전수 실측 후 `masking:` 기입.

🔴 **확인 항목 (2인 확인)**
1. ⬜ 식품안전나라 오픈API **이용조건 화면**을 열어 문구를 확인한다 — 같은 계열이 「제한없음」이라고
   해서 이것도 그렇다고 적으면 **지어내는 것**이다 (오늘 `aihub_558` 에서 같은 함정을 밟을 뻔했다)
2. ⬜ `total_count` 실측 — 30건 미만이면 D-40 으로 「측정 불가」다
3. ⬜ 위반내용에 **광고 문구가 인용**돼 있는지 표본 확인. `mfds_sanctions` 제8조 30건에서는
   따옴표 인용이 **5/30** 뿐이었다. 이 축이 값을 정한다
4. ⬜ `mfds_sanctions` 와의 겹침 — 같은 처분을 둘 다 담고 있으면 정본을 정한다 (D-153)

## ② `foodsafety_penalty_std` — I1660 · **4층 위험도**

**과징금부과기준** (식품안전관리 — 기준규격정보)

| | |
|---|---|
| 요청 | `http://openapi.foodsafetykorea.go.kr/api/{keyId}/I1660/json/{start}/{end}` |
| 출력 필드 | `DSPS_STDR_CD_NM` 처분기준명 · `LAWORD_CD_NM` 식품법령 · `BASIS_LAWORD` 근거법령 · **`VILT_TYPE_NM` 위반유형** · `LV_NO` 레벨 · `VALD_BGN_DT`/`VALD_END_DT` **유효기간** |
| 층 | **4층 위험도** |
| 제안 등급 | G3 — ⬜ 이용조건 확인 후 확정 |
| 제안 가치 | **A** |
| 호출 제한 | 500회/일 · 시간당 100회 (증분 파라미터 미사용 시) |

**★ 이것이 큰 이유 — 별표 파싱의 대조군이 된다.**
지금 4층은 **괘선 표 파싱**으로 서 있다. 오늘 D-98 을 개정하며 자동 감사를 붙였지만,
감사가 재는 것은 「줄었는가」이지 **「맞는가」가 아니다** — 기준선이 처음부터 틀렸으면 못 잡는다.
I1660 은 같은 값을 **구조화 레코드**로 준다. 둘을 대조하면 감사가 **실측 근거**를 얻는다.

현재 별표에서 뽑은 과징금·과태료 행 (2026-09-09):
```
005361 과징금의 부과기준 1행 · 과태료의 부과기준 8+1행
005668 과징금 산정기준 20행 · 과태료의 부과기준 10행
013453 과태료의 부과기준 9행
```

**★ `VALD_BGN_DT`/`VALD_END_DT` 가 현행 필터를 준다.** 별표에는 유효기간이 없어
「2026.7.1 개정 과징금 고시」 같은 것을 **개정일로 거를 수단이 없었다**(청크_스키마가
`effective_date` 를 필수로 적어 둔 자리다). 이 API 는 그것을 필드로 준다.

🔴 **확인 항목 (2인 확인)**
1. ⬜ 이용조건 화면 (①과 같다 — 한 번에 본다)
2. ⬜ `VILT_TYPE_NM` 의 값 집합이 우리 위법 유형 8종과 어떻게 대응하는지.
   🚨 `violation_t`(V0~V8) 대응표가 미판정인 것과 **같은 자리**다 (결정요청 ⑤)
3. ⬜ 별표 파싱값과 대조 — 어긋나면 어느 쪽이 맞는지 정한다 (D-54 단일 출처)

## 등재 순서 (D-15)

```
1. docs/03_데이터/_matrix/data.js 에 항목 둘을 만든다      ← 판정매트릭스가 원본
2. _matrix/README.md 대로 sources.json 을 갱신한다
3. scripts/gen_registry.py 의 ORDER·EXTRA 에 넣는다
4. scripts/registry_review.yaml 에 decided_by/at 을 적는다  ← reviewed_by 는 사람이
5. collect/endpoints.yaml 에 service_id 를 넣는다
6. uv run python launcher.py check
7. uv run python launcher.py collect foodsafety_ad_monitor --use U1 --pages 1
```

🚨 **7번 전에 `reviewed_by` 가 있어야 한다** — `registry.require()` 가 첫 줄에서 막는다 (D-66).

## 이 문서가 하지 않은 것

`caution` 안의 **다른 데이터셋** 라이선스를 이 데이터셋 것으로 옮길 뻔했다.
