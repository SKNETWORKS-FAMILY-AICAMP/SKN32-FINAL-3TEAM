## D-265 · **대체 문구는 검수가 내지 않는다** — 검수는 판정과 지시까지, 문구 생성은 진입점 B

- **상태**: 초안 (2026-09-23) · **판정: 팀장** — (나) 채택 · **D-125 개정 · D-264 개정** · D-181 집행
- **맥락**
  1. 진입점은 셋으로 갈라져 있다(D-181) — A 검수 · B 카피 생성 · C 광고 조립. **B 의 입력에는 위반 문장을 받는 칸이 없다**.
  2. 검수 화면의 흐름이 정해졌다(D-263 · 팀장) — 확신 부족 · 품목 미판별 · 분기 필요면 `hold` → 사용자가 다시 검수를 누르면 **분기 선택 화면** → 고른 선택지에 **조문을 그대로 인용한 설명**과 **등급 전·후**(「업무정지 위험 → 주의」)를 전제 표시와 함께 보여 준다. 사용자가 할 일이 여기서 정해진다 — 빼거나, 실증하거나, 인정 범위로 낮추거나.
  3. 대체 문구를 얹으면 **보증으로 읽힌다.** 응답에 「적법」을 쓰지 않기로 한 것(D-05)과 면책 문구가 한 줄로 무너진다. 틀린 제안은 제안이 없는 것보다 나쁘다 — 선행 도구가 「우수한」으로 고쳐 준 사례가 기획서 실측에 있다(플랫폼 A · 2026-08-30).
  4. 우리가 만든 문구를 우리 판정 코어가 재고 「통과」라 적으면, 그 통과는 판정기의 미탐과 같은 모양이다. 기획서 v3.7 이전 판의 시나리오 A 가 그렇게 틀렸다(D-59).
  5. 수정쌍은 한 원천 13개 표 245쌍뿐이다(D-264 트레이드오프) — 런타임 제안의 근거로는 얇다.
- **대안**: (가) 검수가 전제부 후보까지 낸다(D-264 원안) (나) ★ **검수는 판정·지시까지, 문구 생성은 진입점 B** (다) 후보를 별도 응답으로 내되 검수 화면에 같이 그린다
- **결정**: (나).

  | 검수가 주는 것 | 새로 쓰는 문장 | 이미 있는 값 |
  |---|---|---|
  | 뺄 구간 — 「이 구간을 빼면 R0」 | 없음 | `violations[].spans` |
  | 요건 안내 — 인정 기능성 / 실증 자료의 종류와 등급 변화 | 없음 (조문 인용) | 분기 · 기준 문안(D-263 ②) |
  | 생성으로 넘기는 이음새 | 없음 | 판별된 카테고리 · 허용·차단 키워드 |

  - `JudgeResponse.candidates` 는 **검수 경로에서 항상 빈 목록**이다. 검증기 둘(`_no_candidates_for_qualification` · `_outcome_matches_payload`)은 **고치지 않는다.**
  - **B 실증형의 「조건부 제안」은 요건 안내로 남고 문구는 빠진다.** 「자료를 갖추면 사용 가능합니다 · 필요한 자료: ○○」는 그대로다(기획서 1620행) — 없어지는 것은 문구뿐이다.
  - **B 실증형의 재생성 루프는 실증 분기(D-263)가 대신한다.** 「K 를 소진해 표현을 못 찾았다」가 아니라 「실증하면 이 등급까지 내려간다」를 보여 준다.
  - `Certificate`(A 자격형 · C 절대형 · D-32)는 **남는다** — 문구가 아니라 설명이다.
  - **차별점 ②(순환 검증)는 B 에서 유지된다** — 생성 후보는 자기 전제로 재판정되고 각색본은 `recheck` 를 단다(D-119).
  - **수정쌍 245의 자리** — 런타임 입력이 아니라 재료다. ① 금지 ↔ 허용 표현 치환 사전(생성의 허용 어휘 제약) ② 검수의 **코드 하한** 사전 보강 ③ 오프라인 평가(표 단위 홀드아웃 · 근접도).
  - **(가) 를 기각한 이유**: 맥락 3·4. 계약 검증기 둘을 푸는 대가로 D-59 의 집행이 사전 대조로 내려간다.
  - **(다) 를 기각한 이유**: 응답이 둘이어도 화면이 한 자리에 그리면 사용자에게는 (가)와 같다.
- **트레이드오프**:
  > 제안이 보증으로 읽히고 우리 출력이 우리 채점을 받는 문제를 풀기 위해 검수에서 문구 생성을 뺐고,
  > 그 덕분에 **판정 응답이 결정적이고 빠르며 D-59 를 계약이 그대로 집행**하는 대신,
  > 검수 화면이 「그래서 뭘 쓰라고」에 직접 답하지 않는다 — 답은 **생성으로 건너가는 길**이 맡고, 그 길은 아직 화면에 없다(§0 4).
- **개정하는 것**

  | 무엇 | 지금 | 개정 |

## 3. `gap2` — 탐색 결과

| 어디 | 뜻 |
|---|---|
| 기획서 1965행 | **인코더 예측이 코드 하한보다 2등급 이상 「낮은」** 비율 → 보류 트리거 |
| 기획서 2170행 (= 원장 D-127 표) | **코드 하한과 모델 예측이 2등급 이상 벌어짐** → 위험도는 하한 유지 · 전문가 검토 권고 |
| `app/contracts.py:53` 주석 · `tests/test_fixture_coverage.py` `KNOWN_GAPS` | **1·2위 격차 부족** — 유형 분류 상위 둘의 확신 차 |

- 앞 둘과 셋째는 **다른 것을 잰다.** 원장·기획서 뜻이 정본이고, 코드 주석이 어긋나 있다. 인코더를 붙이는 순간 둘 중 하나가 조용히 구현된다.
- **방향이 중요하다** — 모델이 하한보다 **높게** 보는 쪽은 D-09 래칫 + D-131 이 맡는다(`_ratchet`: `final > floor` 인데 `evidence_span` 이 없으면 계약이 거부). 그러니 **「1등급 차이에도 근거가 필요하다」는 이미 집행되고 있다.** `gap2` 가 맡는 것은 **모델이 훨씬 낮게 보는 큰 불일치**다 — 래칫이 하한을 유지하되 사람에게 보낸다.
- **문턱 2 의 출처가 없다** — 기획서에 수만 있고 `[측정]`·`[임의]` 태그가 없다. 판정 경로의 `[임의]` 다.
- 🔴 **지금 척도에서는 거의 안 걸린다.** 코드 하한은 R3 에 도달하지 못하고(차수를 안 보기 때문 · 원장 09-16 실측), R0~R2 안에서 「2등급 이상 낮음」이 성립하는 조합은 **하한 R2 · 모델 R0** 하나뿐이다.
- **권고** — ① 원장·기획서 뜻을 정본으로 하고 코드 주석·`KNOWN_GAPS` 를 고친다(1·2위 격차는 `low_conf` 가 덮는다) ② 문턱을 `PARAMS` 로 빼고 `[임의]` 를 박는다 ③ 인코더 harness(D-94)에서 τ 와 같이 잰 뒤 확정한다. **지금 1 로 내리지 않는다** — 보류 비율을 모르는 채 내리면 화면이 보류로 덮이고, 안전 구멍은 D-131 이 이미 막고 있다.
