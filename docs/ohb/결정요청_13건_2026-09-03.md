## A. 9/10 (harness 마감) 전 — 라벨·계약에 박히는 것

### 1. R3 · 위험도 값 개수 — 4단계인가, R0(없음) 포함 5값인가 ✅ **결정 — D-130 (5값 · 「특이사항 없음」) · D-131 (인코더 상향은 근거 스팬 조건부 · +1 상한 폐기)**

**문제 상황.** 오전에 사실원장 「판정 축」이 위험도를 **4단계 순서형(형사·과징금·업무정지·주의)** 으로 확정했다. 그런데 이 넷에는 **「적법 / 특이사항 없음」이 없다.** 골든셋은 주입 규약 3 으로 원본 문구를 `V0`(적법)로 함께 넣고, 7-2 화면 표에는 「특이사항 없음」 배지가 있고, DDL `risk_t` 는 이미 `R0~R4` 5값이며, 수집전처리 기획 4-6 ④는 「QWK 는 R0~R4 5점 척도」라고 적었다. 즉 **문서 절반은 5값, 절반은 4값**이다. D-09 래칫 `max(코드 하한, 인코더)` 에서 적법 문장의 하한이 정의되지 않고, 최솟값이 「주의」면 **모든 문장이 최소 주의로** 나가 경고 피로가 구조적으로 생긴다. harness(D-94)가 라벨을 고정하므로 9/10 을 넘기면 재학습이다.

### 2. R7 · 9/11 Phase 1 게이트 — 조건을 바꿀 것인가, 날짜를 옮길 것인가

**문제 상황.** 8-3 의 Phase 1 게이트(9/11)는 **「유형별 Recall ≥ 룰 baseline B + 0.15」** 이고 「못 넘으면 다음 Phase 착수 금지 · 예외 없음」이다. 그런데 harness 마감이 9/10, 인코더 학습은 3W(9/11~) 시작, D-124 가 walking skeleton 을 「모델도 판정 로직도 없이 스텁 배선」으로 재정의했다. **9/11 에는 인코더도 룰 baseline 도 없다.** 조건 그대로면 판정 불가 → Phase 2(규칙 변환·병기 문구 = 안전선·무료 구간) 착수가 막힌다. 같은 날인 주제 전환 데드라인(D-49·D-62)도 근거 없이 지나간다.

| 대안 | 얻는 것 | 잃는 것 |

## C. 구조 선택 — 한 번 정하면 되돌리기 비싼 것

### 8. P4 · 진입점 C 조립 완료 시 문서 판정(층 3)을 한 번 더 통과시킬 것인가

**문제 상황.** D-103 ① 「템플릿 생성기는 판정을 아예 모른다 — 승인 객체인지만 본다」. D-120 은 공존 규칙 R-D1(`[질병명] ∧ [섭취·사용] ∧ [호전]`)이 **문서 안에서만** 돈다고 정했다. 그런데 층 3 예시 세 문장(「어머니가 위암 진단」·「매일 양파즙」·「검사 결과 좋아짐」)은 **각각 단독으로는 승인**되고, C 에서 슬롯 셋에 꽂히면 R-D1 이 어디서도 돌지 않는다 — **승인 배지 셋을 단 질병 치료 표방 상세페이지**가 나간다. 승인 시점의 문서 경계와 조립 시점의 문서 경계가 다르다는 것을 설계가 못 봤다.

| 대안 | 얻는 것 | 잃는 것 |
|---|---|---|
| **(a) ★ D-103 ① 개정** — 「슬롯 채움은 판정을 모르고, **조립 완료는 문서 판정(층 3)을 받는다**」. 발동 시 제거 불가 「문서 수준 경고」 · 승인은 `(sentence_id, sha256)` 바인딩 | 배지 세탁 차단 · 판정 코어 하나(규칙 두 벌 안 생김) | C 가 판정 코어를 한 번 호출 — 「템플릿은 판정을 모른다」는 발표 문장을 「슬롯은 모른다」로 좁혀야 함 · 조립 완료 응답시간 +1 판정 |
| (b) 유지 — 위험을 문서로만 남김 | 구현 0 | 우리 제품이 **막으려는 부당광고를 우리 템플릿이 만들 수 있다** — 심사 질문 하나에 무너진다 |
| (c) 슬롯 채울 때마다 문서 전체 재판정 | 가장 안전 | 슬롯마다 판정 호출 — 비용·지연이 슬롯 수에 비례 |

**★ (a).** 마감 — 진입점 C 는 Phase 3(5W~)이라 **9/17 범위 확정 때**. 고칠 곳 — D-103 개정분 · 기획서 2-6 · 요구사항 C 화면 수용 기준.

### 9. D7 · raw 보관 — 착지 전 마스킹인가, G2 만 미보관인가

**문제 상황.** D-17 「업체명·상표·대표자명은 **등급 무관** 수집 직후 마스킹 · 원문 미보관」 ↔ 규약 2 「원본은 `raw/` 에 **무손상** 저장·덮어쓰기 금지」 ↔ D-92 「미보관은 **G2 만**」. 실제로 `ftc_decisions_body` 1,087건 **미마스킹 원문이 `data/raw/`** 에 있다(대표자명은 원천이 가려 줬지만 업체명·주소는 그대로). 셋이 서로 다르고 실물은 세 번째를 따르고 있다. 게다가 G2 「재실행은 재수집으로」인데 규약 4 「sha256 같으면 스킵」이라 재수집이 스킵된다.

| 대안 | 얻는 것 | 잃는 것 |
|---|---|---|
| (a) 착지 전 마스킹 — `raw/` 자체를 마스킹본으로 | D-17 을 글자대로 · 원문이 어디에도 없음 | `raw` sha256 이 원천과 달라져 **재현 검증(규약 4)이 약해짐** · 마스킹 오류(과잉·누락)를 **재수집 없이는 복구 불가** · 규약 2 「수집기는 파싱하지 않는다」와 충돌 |
| **(b) ★ D-92 대로** — G3 raw 는 무손상 보관하되 `RAW_READERS`(collect·preprocess)만 읽고 보관 기간을 둔다 · 마스킹본은 `derived/` · **D-17 문구를 「등급 무관 마스킹은 derived 이후 전 경로 · 원문 미보관은 G2」로 개정** | 실물과 일치 · 재현성 유지 · 마스킹 오류 복구 가능 · 게이트 17 이 이미 raw 소비를 막고 있음 | D-17 의 「원문 미보관」 문장이 좁아진다 — 명예 축 주장은 「학습·색인·화면에는 절대 안 들어간다」로 바꿔 말해야 함 |

**★ (b).** 스킵 조건은 어느 쪽이든 `sha256 동일 AND 파생물 존재` · `event=delete` 뒤 첫 fetch 강제. 마감 — 전처리 층 본격 착수 전(**2W 말**). 고칠 곳 — D-17 개정분 · 수집전처리 규약 2·4 · 집행계약 「G2 raw 삭제」.

### 10. O10 · 배치 검수 UI 위치

**문제 상황.** D-76 「관리자는 **구조화 값의 집계만** 본다 — 행 단위 나열·자유 텍스트 금지」인데, 기획서 7-1 관리자 화면 #4 에 **배치 검수**(CSV → 문장별 판정 → 엑셀 리포트 = 원문 행)가 있다. D-105 스스로 「URL·CSV 는 진입점 A 의 입력 취득 방식」이라 했다. 클라우드 에디션에서 우리 운영자가 사용자 원문 행 리포트를 만들고 열람하면 차별점 ④(원문을 밖으로 안 보낸다)가 관리자 화면에서 깨진다. 팀원 UI 산출물(관리자 77 화면)이 이 위에 있다.

| 대안 | 얻는 것 | 잃는 것 |
|---|---|---|
| (a) 배치 검수를 **사용자 화면(진입점 A)** 으로 이동, 관리자에는 `batch_run.summary` 집계만 | D-76·D-105 와 정합 · 에디션 구분 불필요 | 관리자 UI 담당(소성민·박수진) 산출물 이동 — 화면 재배치 하루 |
| **(b) ★ 관리자에 두되 온프레미스 에디션 전용 — 클라우드에서는 「비활성 + 사유」(D-107)** | 팀원 산출물 유지 · 열람 경계는 지켜짐(온프레미스는 고객 자신의 관리자) | 에디션 플래그 하나 · 클라우드 데모에서 배치 화면이 회색으로 보임 — 발표 시 「왜 비활성인가」를 차별점 ④로 설명 가능 |

**★ (b).** 마감 **9/8**(MVP 승인과 같이). 고칠 곳 — 기획서 7-1 · 요구사항 정의서 관리자 #4 「에디션」 열 · D-107 적용 목록.
