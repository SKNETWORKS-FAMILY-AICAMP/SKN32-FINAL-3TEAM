## 2. 🔴 PNG 에 C2PA 서명이 박혀 있다 — **D-218 의 진단이 틀렸다**

09-12 밤에 *「전송 경로가 PNG 를 다시 인코딩한다」* 라 적었다. **재인코딩이 아니다.**

    IHDR → caBX (5,758B) → IDAT × 68 → IEND      ← 기기 쪽
    IHDR →                 IDAT × 68 → IEND      ← 컨테이너 쪽

- **픽셀은 13장 전부 비트 단위로 동일**하다 (Pillow `tobytes()` 대조).
- 바이트 차는 **정확히 +5,770B** — 13장 전부 같은 수.
- `caBX` 안에 든 것: `com.anthropic.claude.provided` · `softwareAgent: Claude` ·
  *"Claude provided this file at the request of a user and may have created or modified the file contents."*
  · 서명자 **Anthropic Claude Content Signing**.

🔴 **재현성이 깨진다 — 실측했다.** 같은 PNG 를 두 번 썼더니 크기·픽셀은 같은데 **sha256 이 다르다**
(`286c3809…` / `c7c6ca2d…`). 매니페스트 UUID 셋이 매번 새로 생성된다.
★ 즉 **그림이 안 바뀌어도 기기에 쓰기만 하면 git 이 「수정됨」으로 잡는다** — **D-90(rebuild)과 부딪친다.**

🔒 **21장 전부가 이미 그렇다.** 원천 없는 8장도 열어 봤더니 전부 `caBX` 를 달고 있다 —
**오늘 새로 생긴 노출이 아니라 도면을 처음 넣을 때부터였다.**

### 2-1. ✅ 판정 끝 — **`D-222` · (a) 벗기지 않는다** (팀장 · 2026-09-13)

> 🔄 **위 「판정 대기」는 그날 안에 닫혔다.** 갈래 셋은 원장 §9 ④, 판정 본문은 **D-222**.

**왜 (a) 인가** — 이 저장소가 계속 해 온 일이 **출처를 밝히는 것**이다
(D-201·D-209 의 `[측정]`/`[문헌]`/`[관행]`/`[임의]`, D-219 의 `[실측]`/`[기획]`, D-63·D-188 의
*「안 본 것은 안 봤다고 말한다」*). 그 한가운데서 **AI 가 만들었다는 출처 표시만 능동적으로
지우는 것**은 앞의 셋과 어긋난다.
⛔ **내가 틀릴 수 있는 지점은 그대로 남는다** — 심사가 C2PA 를 안 읽으면 그 위험은 0 이고
(c)가 낫다. **심사 기준을 나는 모른다.**

**떠안은 것 — 숨기지 않는다.** `diagram` 을 한 번 돌리면 그림이 안 바뀌어도 13장이 diff 에
뜬다(매니페스트 UUID 가 매번 새로 난다). ★ **운영 규칙으로 산다 — 「그림이 바뀐 장만 넘긴다.」**
`assets/diagrams/README.md` 에 적었다.

🔄 **(b)는 닫지 않았다 — 조건부로 열려 있다.** **기기에서 뽑으면 `caBX` 가 안 붙는다**(실측).
⛔ 다만 글꼴이 있어야 하고(§7-1 · 지금 이 기기에 없다), 원천 없는 8장은 못 뽑으므로
**21장 중 13장만 깨끗한 어정쩡한 상태**가 된다. **그래서 (b)는 선택이지 판정이 아니다.**

✅ **게이트는 붙였고 범위를 바꿨다** — `tests/test_diagram_provenance.py`.
🗑 **종전 초안(게이트 5 + 음성 픽스처)은 폐기했다** — (b)/(c) 판정을 전제한 것이었다.
🚨 **PNG 에 `caBX` 가 있는지는 검사하지 않는다** — 기기에서 뽑은 장은 없는 것이 정상이라
**(b)를 막는다.** *「정상인 것을 빨갛게 만드는 게이트는 곧 꺼진다」* (D-170).
✅ 대신 **공개 문단이 살아 있는지**만 본다 (D-216 의 「가명 규칙 문단」과 같은 어법).
⛔ **문단이 맞는 말인지는 못 본다.** 사라지는 것만 잡는다.

⬜ **`dict_entry` 는 거두는 장치가 없다** — 지금 일치해서 안 건드렸다 (D-192).

★ **이 건이 「적재 수 리팩터를 발표 뒤로」 판정을 반쪽 뒤집었다.** 세는 법(`Tally`)은 여전히
뒤지만, **거두는 장치**는 없는 것이 드러났고 그건 지금 고쳤다. **재고 나서 판정이 바뀐 것**이다.

### 8-7. 🔴 `source` 표에도 고아 하나 — **판정 대기**

적재가 보낸 것 32, DB 33. 이름은 **`foodsafety_admin_measure`** —
09-09 에 **`not_adopted` 로 내린** 소스인데(사유: 웹 목록이 **대표자 실명을 평문으로** 준다)
`source` 표에는 **2인 확인 완료로 남아 있다.** 상세는 원장 ⑲.

⛔ **거두지 않았다** — 하위가 전부 CASCADE 다. 대신 `load_sources` 가 **이름을 낸다.**
🔴 **정정 — 「판정 대기」가 아니다.** 판정은 **09-09 에 이미 내려졌다(미채택)**.
`source` 표는 정본의 사본이니 정본이 미채택이면 사본에서도 없어야 한다 — **판정의 귀결**이다.
✅ **하위를 쟀다 — `fragment` 0 · `collect_manifest` 0 · `document` 0.**
CASCADE 위험은 **없었다**(내가 재지 않고 말했던 것도 정정). `source_use` 4 · `source_constraint` 1
은 소속 속성이라 같이 지워지는 게 맞다.

✅ **규칙을 좁혀 넣었다** — 하위 0 이면 거두고, 있으면 이름만 내고 멈춘다.
**안전한 자리에서는 판정이 저절로 반영되고, 위험한 자리에서만 사람을 부른다.**
🔴 **「정말 문제가 없나」로 둘이 더 나왔다** — FK 를 넷만 봤다(다섯째가 `supersedes`,
`ON DELETE SET NULL` 이라 **조용하다**. 실측 0행이라 안 걸리지만 **가드는 넣었다**), 그리고
행의 `note` 에 **저장소 어디에도 없는 조각 셋**이 있었다. **원장 ⑲ 로 옮겨 적었다.**
★ 그중 하나가 결정적이다 — *「RSS 경로는 업체명이 없다 = 개인정보가 구조적으로 빠진 경로」*.
**미채택 사유가 개인정보인데 개인정보 없는 경로가 있다**는 뜻이라, 재채택 검토는 거기서 시작한다.

⬜ **미실행** — 옮겨 적었으니 다음 `load` 가 거둔다.

### 8-8. 「이미 거둔 것들은?」 — FK 21건 전수 대조

`ON DELETE SET NULL` 은 하나뿐(`source.supersedes` · 실측 0행)이고 나머지 20 은 CASCADE.
거두는 자리 셋을 다 대조했다 — **golden 은 `surface_of`·`sent_id` 를 적재가 안 채워서 NULL,
embed 는 `chunk_embedding` 하나(의도됨), `product_fact` 는 가리키는 FK 가 0.** 셋 다 ✅.

🔴 **그 과정에서 내 가드 하나가 「실패할 수 없는 단언」인 게 드러났다** — `sweep_golden` 이
`cur.rowcount` 로 CASCADE 를 잡으려 했는데, DELETE 명령 태그는 **CASCADE 로 지워진 행을
안 센다.** 전후 `count(*)` 로 고쳤다. 상세는 원장 ⑳.

🔶 **FK 밖 참조 하나** — `judgment.evidence` JSONB 안의 `chunk_id`. `chunk` 를 거둬도 안 막힌다.
지금 0행이라 무해하고 안 막았다 (D-192).
