## 2. 🔴 PNG 에 C2PA 서명이 박혀 있다 — **D-218 의 진단이 틀렸다**

09-12 밤에 *「전송 경로가 PNG 를 다시 인코딩한다」* 라 적었다. **재인코딩이 아니다.**

    IHDR → caBX (5,758B) → IDAT × 68 → IEND      ← 기기 쪽
    IHDR →                 IDAT × 68 → IEND      ← 컨테이너 쪽

- **픽셀은 13장 전부 비트 단위로 동일**하다 (Pillow `tobytes()` 대조).
- 바이트 차는 **정확히 +5,770B** — 13장 전부 같은 수.
- `caBX` 안에 든 것: `com.anthropic.claude.provided` · `softwareAgent: Claude` ·
  *"Claude provided this file at the request of a user and may have created or modified the file contents."*
  · 서명자 **Anthropic Claude Content Signing**.

🔴 **재현성이 깨진다 — 실측했다.** 같은 PNG 를 두 번 썼더니 크기·픽셀은 같은데 **sha256 이 다르다**
(`286c3809…` / `c7c6ca2d…`). 매니페스트 UUID 셋이 매번 새로 생성된다.
★ 즉 **그림이 안 바뀌어도 기기에 쓰기만 하면 git 이 「수정됨」으로 잡는다** — **D-90(rebuild)과 부딪친다.**

🔒 **21장 전부가 이미 그렇다.** 원천 없는 8장도 열어 봤더니 전부 `caBX` 를 달고 있다 —
**오늘 새로 생긴 노출이 아니라 도면을 처음 넣을 때부터였다.**

> ⬜ **판정 대기 — 사람 몫이다** (공개 범위). 갈래 셋과 내 권고는 **원장 §9 ④**.
> 내 권고는 **(a) 벗기지 않고 문서화**다. (c) 벗기기는 *출처 표시를 능동적으로 지우는 행위*라
> 부트캠프 심사에서 「AI 사용을 숨겼다」로 읽힐 수 있다.
> ⛔ **내가 틀릴 수 있는 지점** — 심사가 C2PA 를 읽지 않는다면 그 위험은 0 이고 (c)가 낫다.
> **심사 기준을 나는 모른다.**

⬜ **게이트 초안을 만들어 뒀고 커밋하지 않았다** — `tests/test_diagram_provenance.py`
(게이트 5 + 음성 픽스처 1). 지금 붙이면 **21장 전부에서 빨갛다.** 판정 뒤에 범위를 맞춰 붙인다.

## 8. 🔴 이서은 제보 — **빈 DB 에서 마이그레이션이 안 돈다** (D-221)

새로 클론한 기기에서 `db-up` + `alembic upgrade head` 가 무조건 죽는다.

    cannot drop type violation_t because other objects depend on it
    DETAIL: column violation of table violation_article depends on type violation_t

### 8-1. 제보한 진단이 맞다 — 그리고 원인은 `0003` 이 아니라 `0001` 이다

`0001` 은 `db/schema.sql` 을 읽는데 **그 파일은 정본이라 계속 움직인다.**
그래서 새 DB 는 **끝난 모양에서 시작하고**, `0003` 이 ⑥에서 만들려는 `violation_article` 을
**이미 갖고 있다.** 그 표가 `violation_t` 를 붙잡는다.
⛔ 옛 DB(0002 시점)에는 그 표가 없었다 — **그래서 여태 아무도 안 밟았다.**

### 8-2. 실측 — 컨테이너에 PostgreSQL 16 + pgvector 를 세우고 **실제 alembic** 으로 돌렸다

| | 결과 |
|---|---|
| 고치기 전 | 🔴 `0003` 에서 죽는다 — **제보와 글자까지 같은 오류** |
| 체인 전체에서 막는 문장 | **딱 하나** — `DROP TYPE violation_t` |
| 고친 뒤 · 빈 DB | ✅ `0001 → … → 0013` 끝까지 |
| 고친 뒤 · 옛 경로 | ✅ 통과 (`DO` 블록이 아무것도 안 한다) |
| 끝 모양 | ✅ 두 DB 가 같다 (타입 값·열 타입·뷰 정의·표 수) |

### 8-3. 고친 것 · 세운 것

- `db/migrations/0003_golden_labels.sql` — `violation_article` 을 잠깐 `text` 로 뗐다 되건다.
  **있을 때만** 한다 (`to_regclass`). 🔴 **0007 의 「돈 마이그레이션을 고치지 않는다」를 어긴다** —
  안 고치면 새 DB 가 아예 못 서기 때문이고, 끝 모양은 양쪽 같다(실측). 판정은 **D-221**.
- 🆕 `scripts/db_fresh_check.py` + `launcher.py db-fresh` (메뉴 **39**) —
  **옆에 임시 DB 를 만들어 `upgrade head` 를 돌리고 지운다.** 음성 확인까지 했다.
  ★ **정적 검사로는 못 잡는다** — 어느 표가 어느 타입을 붙잡는지는 PostgreSQL 만 안다.

### 8-4. ✅ 이서은 DB — **`0011` 에 stamp 했고, 구멍 하나가 남아 있다**

`schema.sql` 은 런타임 층을 안 담으므로 그 부분만 새 DB 에 없다. 상세는 D-221 덧붙임.

✅ **고치는 방법은 `0014` 다 — 절차가 아니다.**

### 8-5. 🆕 `onboard` 를 실행·판정으로 올렸다
