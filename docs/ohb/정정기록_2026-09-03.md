## 0. 수정 방법 세 가지 — 무엇을 어디에 쓰는가

기준축(설계결정기록)이 방법도 이미 정해 뒀다. **어긋남의 종류에 따라 손대는 자리가 다르다.**

| 종류 | 방법 | 근거 · 선례 |
|---|---|---|
| **① 표현이 결정을 어겼다** | **본문을 고친다. 새 번호를 주지 않는다.** 결정을 바꾸는 것이 아니라 **결정대로 되돌리는 것**이다 | — |
| **② 결정 자체가 틀렸다** | 🚨 **원 결정을 「대체됨」으로 남기고 새 번호를 준다.** 지우지 않는다 | 기록 규칙 0.2 · **D-97→D-98(같은 날 뒤집힘)** · D-37→D-36 · D-45→D-70 |
| **③ 결정은 맞는데 경계가 모호하다** | **본문에 「★ 개정분」을 붙인다.** 번호는 그대로 | **D-93** 이 같은 날 개정분 ①~⑤ 를 붙인 선례 |

★ **셋을 섞으면 안 된다.** ②를 ①로 처리하면(본문만 조용히 고치면) **뒤집힌 이력이 사라진다** — 그 이력 자체가 근거라고 기록 규칙 0.2 가 적어 뒀다.

## 1. ② 로 처리 — 결정이 틀렸다

### D-121 → **D-122** · 등급이 아니라 `NOTRAIN`

**문제 의식은 살고 자리가 바뀌었다.** D-121 을 「대체됨」으로 남기고 **왜 틀렸는가** 절을 본문에 붙였다.

| 왜 틀렸는가 | |
|---|---|
| 이름 | `U-USER` 는 **U 축(용도)처럼 보이면서 G 축(등급)에 넣으려던 값**이다 — D-99·D-100 이 경계한 「같은 기호, 다른 뜻」 |
| `G1` 로? | **G1 은 수집 자체 금지**인데 업로드물은 받아야 한다 |
| `G0` 로? | **D-106** — G0 는 「확인 전」이지 「확인했더니 이렇다」가 아니다 |
| 새 등급? | 업로드물은 **소스가 아니다.** 판정매트릭스↔레지스트리 **1:1 대응이 깨진다** |

**D-122 결정** — 문제를 한 줄로 쓰면 「**수집(서비스 입력)은 해야 하고 학습만 막아야 한다**」이고, 그것은 **D-73 이 세운 「막는 지점」 축**이다. `NOSTORE` · `NOREDIST` · `PREAPPROVAL` · `QUERYLOG` 에 이어 **`NOTRAIN` 이 빠진 다섯째**다.

> ★ **등급표를 건드리지 않는다.** `G0~G3 × U1~U4` 는 그대로고 플래그가 하나 는다.
> 게이트는 한 줄 — 「`NOTRAIN` 저장 경로가 학습·색인 코드에서 참조되면 실패」 (게이트 17번과 같은 형태).

## 2. ① 로 처리 — 표현이 결정을 어겼다

### 🚨 과금 경계 — 「판정 무료 / 생성 유료」 → 「sLLM 을 쓰는가」 (D-69)

**D-69 가 그 표현을 대안 (c)로 놓고 명시적으로 기각했다.** 기각 이유까지 적혀 있다 — *"대체 문구를 전부 유료로 밀면 무료 티어가 선행 도구보다 못해진다."*

| 고친 자리 | 전 | 후 |
|---|---|---|
| **기획서 7-6 발표 문장** | *"무료 구간(판정) / 유료 구간(생성)"* | *"무료 구간은 **GPU 없이 도는 데까지**. 판정과 **규칙 기반 시정**까지 무료, **sLLM 이 도는 순간부터** 유료"* |
| 기획서 양식 대응표 3번 | 이원 과금(판정 무료 / 생성 유료) | 경계는 **「sLLM 을 쓰는가」**(D-69) |
| 요구사항 REQ-N-002 | 판정 원가 / 생성 원가 | **sLLM 을 쓰는 경로 / 쓰지 않는 경로**의 원가 |
| 요구사항 07·08 시트 | 〃 | 〃 |

🚨 **어긋남의 출처는 우리 기획서였다.** 7-6 이 *"GPU가 필요해서"* 라고 이유를 댄 순간 **이미 sLLM 축을 말하고 있었는데** 이름만 「생성」으로 줄여 불렀다. 내 산출물이 그 축약을 세 곳으로 복제했다.

> ★ **정정이 발표를 더 세게 만든다.** 규칙 기반 변환 · 병기 문구 · 주장 원장은 「생성」이지만 sLLM 이 없어 **무료 구간**이고, 그것이 **Phase 2 안전선과 정확히 겹친다.** 무료 티어가 선행 도구보다 넓다는 것이 D-69 의 원래 논거다.

### 「위법 판정」 → 「위험 판정 결과」 (D-05)

**D-05** — 산출물은 「위법 판정」이 아니라 **「심의 통과 가능성 진단」**이다. `REQ-N-009` 를 고쳤다.
요구사항서는 **구현자가 그대로 화면 문구로 옮기는 문서**라 더 위험하다.

### 범위 밖 60화면의 처리 — `REQ-N-032` 신설 (D-107)

**D-107** — 범위 밖 기능은 지우지 않고 **「비활성 + 사유」**로 남긴다. 범위만 갈라 놓고 처리 요구사항이 없었다.

## 3. ③ 으로 처리 — 경계가 모호했다

### D-120 개정분 ① — D-61·D-82 와의 경계

D-120(입력 형태를 묻는다)이 D-61(되묻지 않는다) · D-82(선행 지식 요구가 선행 도구의 공통 실패)와 **문장만 보면 충돌**한다. **번호는 그대로 두고 경계를 본문에 적었다.**

| | 카테고리 (D-82) | 입력 형태 (D-120) |
|---|---|---|
| 누가 아는가 | **우리가 판별할 수 있다** | **사용자만 안다** |
| 판정 결과를 가르는가 | 가른다 | **가르지 않는다** — 대상의 **경계**를 정할 뿐 |
| 자기 신고가 미탐을 만드는가 | 만든다 → D-61 이 금지 | 🚨 **반대다** — 「긴 글」을 고르면 검사가 **늘어난다** |

★ **D-61 의 진짜 금지선은 「자기 신고가 통과 판정의 근거가 되는 경로」다.**
🚨 **안전한 기본값을 함께 못박았다 — 모르면 「긴 글」로 본다.** 검사를 더 하는 쪽이 안전 방향이다 (D-09 의 정신).

## 4. 원장 등재 — 판단이 아니라 기록이었던 것

### 사실원장 「판정 축」 신설 — **D-09 가 이미 정해 뒀다**

> 위험도 래칫은 `max(코드 하한, 인코더 예측)` 이라 **전순서 위에서만 성립**한다.
> 「판정 보류」와 「근거 불일치」는 **서로 비교할 수 없어** `max()` 가 정의되지 않는다.

| 축 | 값 | 정하는 주체 |
|---|---|---|
| **위험도** | 4단계 순서형 — 형사 리스크 / 과징금 / 업무정지 / 주의 | 코드 하한 + 인코더 **최대 +1** |
| **판정 상태** | 확정 / 보류 / 근거 불일치 | 그래프 (모델 아님) |

- 관리자 3종 분포는 **위험도 4단계를 접은 뷰**다 — 새 축이 아니다.
- 사용자 배지 5종은 **두 축을 섞은 것**이다 — 나눠 표시한다.
- 측정은 위험도만 **MAE·QWK**. 상태는 분기이므로 지표 대상이 아니다.

### 사실원장 「산출물 규모」 · 「제약 플래그」

진입점 3 · 화면 118 · 기능 803 · 비기능 32 · **MVP 34/27/60** 을 등재했다 (D-54).
제약 플래그에 **`NOTRAIN`** 을 더했다 (D-122).

### 산출물현황 표

요구사항 정의서 · WBS · 팀 역할분담표 **3종을 등재**했다. 🚨 **위치가 `dist/`(gitignore)라는 사실을 표에 그대로 적었다** — 미결을 감추지 않는다.

## 5. 기획서 버전 — v3.9 → **v4.0**

**개정 규칙 그대로다** — *"PDF 발행이 버전을 고정하는 사건이다. 발행 후 수정은 새 버전에서 한다."*
v3.9 PDF 는 **얼어붙은 발행물이므로 지우지 않는다.** 제출본은 그대로 두고 원본이 v4.0 이 됐다.

**함께 정리한 잔재** — 2-6절 「두 진입점」 → 「세 진입점」(그 절이 바로 진입점 C 를 설명한다) · 3-6절 조각 12.

> 🚨 **판단 필요** — v4.0 PDF 를 다시 뽑아 **재제출할 것인가.**
> 과금 문장은 **발표 논거**라 **중간 발표(9/15) 전에는 반드시 고쳐진 판이어야 한다.** 재제출이 불가하면 **발표에서 정정된 문장을 쓴다.**
