**사람이 필요한 자리는 원천이 라벨을 뭉쳐 놓은 곳뿐입니다.**

## 5. 어떻게 채우나 — 🚨 **번호 하나만 적습니다**

받으신 `<이름>.csv` 를 **엑셀로 그냥 여시면 됩니다.** 한글이 안 깨집니다.

| 행 | 문구 | 후보유형 | **유형번호** | 붙인이 | 붙인날 | 지문 |
|---|---|---|---|---|---|---|
| 1 | 장의 운동을 촉진하여 변비에 효과가 있습니다 | 거짓_과장 / 소비자_기만 | **1** | 권소라 | 2026-09-10 | b84e7a… |
| 2 | 균주특허 획득 | 거짓_과장 / 소비자_기만 | **8** | 권소라 | 2026-09-10 | f55d91… |
| 3 | 아침을 거르시는 분 | 거짓_과장 / 소비자_기만 | | 권소라 | | 42aacc… |

**채우는 칸은 `유형번호` 하나입니다.** §3 을 위에서부터 읽다가 걸린 번호를 적습니다.

- 둘이 맞으면 쉼표로 — `1,5`
- 모르겠으면 **비웁니다.** 3행이 그렇습니다 — **빈칸은 실패가 아니라 판단입니다**
- `붙인날` 은 비워 두면 가져올 때 채워집니다

🚨 **`후보유형` 밖의 번호를 적어도 됩니다.** 1행이 그렇습니다 — 원천이 「거짓ㆍ과장ㆍ기만」으로
묶어 놨지만 실제로는 질병 표방입니다. **원천의 분류가 아니라 문구를 봅니다.**

### ⛔ 하면 안 되는 것

- 🔴 **`문구` 열과 `지문` 열을 고치는 것** — 문구가 키입니다. 고치면 가져오기가 **멈춥니다**
- `행` 열을 지우거나 정렬로 섞는 것
- 모르는 것을 「일단」 채우는 것 — **빈칸이 낫습니다**
- 서로 상의해서 맞추는 것 — **독립으로** 붙여야 κ 가 뜻을 갖습니다
- 🔴 **라벨링 중에 `extract ... --sheet` 를 돌리는 것** (팀장에게만 해당)

### 🚨 시트 원본을 직접 고치지 않습니다

JSONL(`data/derived/mfds_*_labelsheet.jsonl`)을 편집기로 열어 고치던 방식은 그만둡니다.
대괄호를 빠뜨려 그 줄이 JSON 이 아니게 되거나, 유형 이름을 한 글자 틀려 **조용히 다른 라벨**이
되던 자리입니다. **CSV 의 번호 한 칸만** 채웁니다.

★ 참고 — `--sheet` 를 다시 돌리면 원본 시트 자리(`data/derived/mfds_*_labelsheet.jsonl`)의
채운 라벨은 이어받습니다. 다만 **여러분의 CSV 는 그 보호를 못 받습니다.** 그래서
「라벨링 중에는 아무도 `--sheet` 를 돌리지 않는다」가 규칙입니다.

겹치는 부분이 있어야 κ 가 나옵니다. 다 끝나면:

```
uv run python scripts/label_merge.py data/derived/labels/*.jsonl

```
  κ ≥ 0.8   ✅ 「우리 라벨은 재현된다」— 그대로 씁니다
  0.6~0.8   🟡 갈린 항목을 셋째 사람이 봅니다

🚨 **갈린 항목은 다수결로 덮지 않습니다.** 두 사람이 갈렸다는 것은 그 항목이 경계라는

### 🔄 취합 도구가 2026-09-10 에 바뀌었습니다

- **한 사람만 채운 항목은 취합에 안 들어갑니다.** 종전에는 들어갔습니다 — 겹치지 않은 라벨이
  「두 사람이 합의한 것」으로 산출에 섞였습니다. 2인 확인이 이 프로젝트의 뼈대인데(D-66)
  그 자리가 비어 있었습니다.
- **κ 가 `nan` 으로 나올 수 있습니다.** 전원이 같은 한 라벨만 찍으면 정보량이 0 이라
  κ 가 정의되지 않습니다. 종전에는 **1.0(완전 합의)** 으로 나왔습니다 —
  가장 정보 없는 라벨링이 가장 좋아 보였습니다.
