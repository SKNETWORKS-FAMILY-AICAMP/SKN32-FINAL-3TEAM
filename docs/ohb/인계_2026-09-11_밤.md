### 🔴 런처 — 「보기만 한다」는 버튼이 파생물을 덮어썼다

메뉴가 `@app.command()` 함수를 **파이썬에서 직접** 불렀다. Typer 는 기본값 자리에
`typer.Option(False, "--write")` 를 그대로 남기는데, **객체는 참이다.**

```
메뉴 17 「골든셋 — 보기만 한다」 → golden() → write=<OptionInfo> → if write: 항상 참
```

`_invoke()` 가 `subprocess` 로 **자기 CLI 를 다시 부르게** 고쳤다 — **경로가 하나면 갈릴 자리가 없다.**

### 🔄 런처 사용법이 바뀌었다

```
uv run python launcher.py          # 메뉴
  숫자만 입력.  0 = 뒤로(첫 단계면 메뉴로) · 메뉴에서 0 = 종료
  ⚠ 표시 = 확인을 묻는다 (기본값은 「안 함」)
  → 표시 = 값을 묻는다 (번호로 고르거나 직접 입력)
흐름  1 설치 → 7 DB → 16 수집 → 19 추출 → 21 골든셋 → 22 적재 → 23 청킹 → 24 임베딩 → 32 게이트
처음이면 2 새 기기 안내
```

## 7. ⬜ D-189 초안 (미등재)

**인덱스 행**

```
| D-189 | 🔴 **메뉴는 CLI 를 거쳐 부른다 — 호출 경로가 둘이면 기본값이 갈린다** (D-99 의 실물) | 런처 | 확정 (09-11) |
```

**본문 뼈대**

- **무엇이 있었나** — 메뉴가 `@app.command()` 함수를 파이썬에서 직접 불렀다. Typer 는 기본값
  자리에 `typer.Option(False, "--write")` 를 남기고 **객체는 참**이라 `if write:` 가 항상 참.
  「보기만 한다」 버튼이 매번 `--write` 를 실행했고 **기존 분할이 덮어써졌다.**
- **부류가 둘** — 증상은 **D-162**(에러처럼 보이지 않는 에러), 원인은 **D-99**(두 벌이 되면 갈린다).
  두 벌이 되면 갈리는 것은 스키마만이 아니다. **기본값도 갈린다.**
- **대안** — (A) 메뉴에서 기본값 명시: 인자가 늘 때마다 두 벌을 손으로 맞춘다 → D-99 재발
  · (B) 본체를 순수 함수로 분리: 정석이고 D-51 방향이나 **33개를 한꺼번에 건드린다**
  · **(★) 메뉴가 `subprocess` 로 자기 CLI 를 부른다 — 경로가 하나**
- **맞바꾼 것** — 프로세스 기동 ≈0.3초 · 스택트레이스 대신 종료코드.
  **느린 것은 고칠 수 있지만, 갈린 것은 갈린 줄을 모른다.**
- **B 를 버린 것이 아니다** — ★ 는 B 로 갈 때까지 경로를 묶어 두는 장치이고, 그때 `_invoke()` 만 지운다.
- **게이트 — 없다. 임포트 시 자가검사는 있다** — `_check_menu()` 가 번호 중복과 「묻는 표에는
  있는데 메뉴에 없는 이름」을 `SystemExit` 로 세운다. 게이트가 아니라 **오타 방지**다(D-170).
- **곁가지** — `DANGER`/`DANGER_IF` 확인(기본값 「안 함」) · `0 = 뒤로` ·
  확인 문구에서 **「되돌리기 어렵다」를 뺐다**(`db-down`·`setup` 에는 사실이 아니었다).
- **연관** — D-99 · D-162 · D-51 · D-170 · D-167
