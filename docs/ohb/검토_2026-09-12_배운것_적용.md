## 2. 🔴 진짜 갭 다섯

### ⑥ 개선을 말하기 전에 오차를 잰다 — **가장 급하다**

**소음대를 잰 적이 없다.** D-176 이 「seed 가 아니라 입력 지문」까지 갔지만,
**같은 입력으로 세 번 돌려 폭을 재는 절차**는 없다.

🚨 **지금이 마지막 창이다.** T2 인코더가 3W 에 시작하고 팀원 4인이 `(모델, 하이퍼파라미터)`
하나씩 받는다(D-94). **소음대를 모르면 누구 설정이 좋은지 말할 수 없다** — F1 0.03 차이가
개선인지 잡음인지 가를 수 없다.

증거가 이미 있다 — 원장에 **`거짓_과장 F1 0.027`** 같은 수가 있는데 **0 과 구별되는 수인지 모른다.**

### ⑩ 자기가 만든 시험지 밖으로 — **발표 자료가 된다**

    평가 공백 4종    건기식_오인 · 의약품_오인 · 질병_예방치료_표방 · 후기_체험기_기만
                     🔴 어느 단위로도 평가 데이터가 없다
    주입 틀 다양성    T1 · T7a · T7b 가 고유 틀 3종 (2%)

골든셋 1,910 중 **902 가 주입**이고, 그 주입이 「타사 제품보다」라는 **말버릇 3종**이다.
자기가 만든 시험지다.

### ⑳ 폐기를 「이미 만들어졌을지 모르는 자리」에 — **가장 위험하다**

**브랜치가 6개고 팀원 4인이 각자 화면·BFF 를 만들고 있다.** 그런데 이 폐기들이 **문서에만** 있다.

| | 폐기·제약 | 화면 담당이 이미 만들었을 수 있는 것 |
|---|---|---|
| D-182 | 제재 수치를 **금액으로 환산하지 않는다** | 과징금 표시 |
| Q4 | 매출 지표를 화면에 둘 것인가 — **D-182 와 충돌** | 매출 대시보드 |
| D-180 | 인플루언서 매칭은 **범위 밖** | 매칭 화면 |
| D-183 | 광고와 무관한 제재는 적재하지 않는다 | 제재 목록 |

그리고 **화면설계서 수정 8건이 초안만 있고 팀원에게 안 갔다.**

✅ **실측 (2026-09-12)** — `app/contracts.py` 에 `금액`·`매출`·`과징금`·`fine`·`penalty`·
`revenue`·`amount`·`sales` 가 **0건**이다. **계약이 이미 벽이다** — BFF 가 부를 필드가 없으니
화면이 못 만든다.

🔴 **그런데 「왜 없는지」가 계약 어디에도 없다.** 화면 담당은 못 만드는 것만 알고 이유를 모르니
**「필드 추가해 주세요」라고 요청할 수 있다.** 그때 이유를 아는 사람이 없으면 들어간다.
⑳이 말하는 정확히 그 모양이다 — **없다는 사실은 저항이 아니고, 없는 이유가 저항이다.**

⚠️ 참고 — `db/schema.sql:205` 의 `sanction_rule.sanction_value NUMERIC` · `unit`(일/원/배)은
**원천이 준 값**이라 D-182 와 충돌하지 않는다. D-182 가 금지한 것은 **우리가 환산하는 것**이다.

### ① 안전은 바닥이다 — **바닥이 아직 안 깔렸다**

D-09 래칫이 `assess_risk = max(코드 하한, 인코더 예측)` 로 설계돼 있고
**발표 차별점 ②가 그것을 말한다.** 그런데 —

    sanction_rule        0행     ← 코드 하한을 만드는 표
    violation_article    0행     ← 근거 조문

**지금은 `max(없음, 예측)` = 예측이다.** → `docs/ohb/sanction_rule_초안_2026-09-12.md`
(별표7 72행 중 **광고 4행을 실측으로 찾았다**)

### ⑧ 예측하고 나서 잰다 — **2026-09-12 에 이것 때문에 틀렸다**

「게시판 662 재수집이 178/177 을 가른다」를 **예측 없이** 최우선으로 올렸다.
*"재수집하면 662개가 새 판으로 저장될 것이다"* 를 먼저 한 줄 적었으면,
**「저장 0」이 나온 순간 예측이 틀렸다는 걸 알고 왜 틀렸는지 물었을 것**이다.

★ 형식은 이미 있다 — 인계 §0.5 가 **「나와야 하는 수」**를 적는다. **실행 전으로 옮기기만 하면 된다.**

## 3. 손볼 여지 셋

**② 이름이 정의보다 위험하다** — D-178 이 「수 + 게이트 조건」인데, 09-12 에
**「팀 최신판이 아닌 662」**가 이름 때문에 오독됐다(실은 「갈린 이력이 있다」).

**⑦ 분모를 섞지 않는다** — 09-11 에 「좁음 39 + 넓음 10 = 49」를 한 덩이로 묶었다.
**방향이 반대인 둘**이다. `hf_display_claims` 에 대조 칸이 있으니 분모를 함께 적으면 된다.

**⑭ 줄 권리가 없는 것을 주지 않는다** — DISCLAIMER 6-1 이 *"우리 프로젝트의 용도를 전제로 한
판정"* 으로 **이미 적용**했다. 남은 것은 LICENSE(10/16)를 쓸 때 **코드와 데이터·산출물을
나눠 적는 것** — K-MHaS CC BY-SA 파급과 AI Hub NOREDIST 가 ⑭가 경고하는 그 모양이다.

**⑱ 안 읽어도 틀리지 않게** — 09-11 에 정확히 실패했다. `pre-commit install` 을 안 친 사람의
커밋에 **아무 검사도 안 걸렸다.** README 에 적혀 있었는데도. CI 가 그 처방이었다 —
**읽어야 지켜지던 규칙을 구조로 옮긴 것.**

**④ 무효일 때 티를 낸다** — D-176 · D-40 · `-rs` 가 이 방향이다.
🔴 남은 갭: **CI 초록불이 「7개를 안 봤다」를 배지에서 말하지 않는다.** 로그에는 있다.
발표에서 「CI 통과」라고 하면 ②번 함정이다.

**⑨ 측정 도구도 측정 대상** — 세 번 겪었다(`doctor --hash` 0 · gitleaks 무탐 ·

**⑰ 「이건 축소가 아니다」를 같은 자리에** — 형식은 이미 있다(대안 표 · 무엇과 맞바꿨나).
갭: **폐기 계열(D-180·D-183)에 그 칸이 있는지 안 맞춰 봤다.**

## 5. 발표(09-15)까지 — 권고 순서

| | 무엇 | 시간 | 왜 |
|:-:|---|---|---|
| 1 | **⑩ 실제 문구 20건** | 30분 | 발표 결과 파트가 지금 「목표」뿐이다. **20건이면 실측 한 장**이 생긴다 |

| 3 | **⑳ 폐기를 계약에** | 1시간 | 팀원이 이미 만들고 있을 수 있다 |
| 4 | **⑥ 무변화 3회** | 30분 | T2 시작 전이 마지막 창이다 |

### ⑩ 을 실제로 하는 법 — 절차와 기록 자리

🚨 **수집이 아니다.** 사람이 화면에서 눈으로 읽어 손으로 넣는다 — 크롤링이 아니므로
`registry.require()` 도 robots 도 안 걸린다. **저장도 하지 않는다**(문장만 쓰고 버린다).

```
1. 쿠팡·네이버·올리브영에서 건기식/화장품 상세페이지 문구 20건을 눈으로 고른다
   🚨 업체명·제품명은 적지 않는다 (D-17 · D-159) — 문장만 옮긴다
2. docs/ohb/현장확인_2026-09-1X.md 에 표로 적는다
     | # | 문구(마스킹) | 내가 예측한 판정 | 시스템 판정 | 근거 조문 | 맞나 |
   🚨 **내 예측을 먼저 적는다** (D-191 초안)
3. uv run python launcher.py serve  →  POST /judge 로 20건을 넣는다
   ⚠️ /judge 가 지금 501 이면 그 사실이 결과다 — 「아직 답을 못 낸다」를 그대로 적는다
4. 맞은 수가 아니라 **골든셋이 못 보여 준 것**을 적는다
```

★ **맞은 비율은 20건으로 못 잰다**(D-40). 이 20건의 값어치는 정확도가 아니라
**「골든셋 밖에 무엇이 있나」**다. 발표에 쓸 문장은 *"정확도 X%"* 가 아니라
*"20건을 넣어 보니 우리 시험지에 없는 유형이 N 개 나왔다"* 다.

### ⑥ 을 실제로 하는 법

```
uv run python launcher.py golden --write     # 1회
uv run python launcher.py golden --write     # 2회
uv run python launcher.py golden --write     # 3회
```

지금은 산출물 수가 결정론적이라 **셋이 같아야 정상**이고, 다르면 그 자체가 발견이다.
🚨 진짜 소음대는 **T2 학습이 들어간 뒤**에 나온다 — 그때 같은 설정으로 3회다.
지금 돌리는 것은 **전처리 단계가 결정론적인지**를 먼저 못 박는 것이다.

## 6. 안 한 것

- **② 를 D-178 개정으로 올릴지** — 초안을 안 썼다. 넷째 축(「갈린 이력」)을 doctor 가
  이름으로 구분하는 것과 함께 가야 해서, **doctor 네 번째 갈래와 한 건으로 묶는 것이 맞다.**
- **⑨ 를 `doctor`·`scan` 에 거는 것** — 「통과만 하는 게이트는 게이트가 아니다」를
  그 둘에 적용하려면 **일부러 실패시키는 입력**이 필요하다. 설계 안 했다.
- **⑰ 폐기 계열에 「축소가 아니다」 칸이 있는지** — D-180·D-183 본문을 안 맞춰 봤다.
