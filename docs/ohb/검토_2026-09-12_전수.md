#### F-2 · 대칭을 검사한다는 게이트가 **같은 인자를 두 번 부른다** (격자 6)

`tests/test_retrieve.py:365-369`

```python
for a, b in ((vec, lex), (lex, vec)):   # 🚨 넣는 순서가 바뀌어도 같아야 한다
    out = rt.fuse(a if a is vec else vec, b if b is lex else lex, limit=1)
```

두 번째 바퀴에서 `a is lex` 이므로 `a if a is vec else vec` → **`vec`**, 같은 이유로
`b` → **`lex`**. **두 바퀴 모두 `fuse(vec, lex)` 다.** 재현 —

```
게이트가 fuse() 에 넘기는 인자쌍: [(['VEC'], ['LEX']), (['VEC'], ['LEX'])]
두 번이 같은가: True
```

⛔ 주석이 단언하는 「순서 무관」은 **한 번도 검사되지 않는다.**
🚨 이 게이트는 09-12 오후에 *"한쪽만 보는 대칭 검사는 반대쪽을 못 잡는다 (D-170)"* 를
고치려고 새로 쓴 바로 그 검사다. **고친 게이트가 같은 병을 다른 모양으로 앓는다.**

⚠️ 한 가지 더 — `fuse(lex, vec)` 로 진짜 바꿔 부르면 **어휘 결과가 `rank_vector` 로 집계된다.**
인자 위치가 갈래를 정하므로 「순서 무관」은 애초에 성립하지 않는 단언이다.
고칠 것은 루프가 아니라 **단언 자체**다 — 재야 하는 것은 *「한 `chunk_id` 가 양쪽에 있을 때
두 점수가 다 실리는가」*이고, 그건 이미 위 세 줄이 재고 있다.

#### F-3 · `ck_chunk_tokens ≤ 512` 가 **재는 축과 쓰는 축이 다르다** (격자 7)

| | 무엇을 재나 |
|---|---|
| `token_count` (`scripts/embed.py:107`) | `_tokens(model, r["text"])` — **`text` 만** |
| 모델에 실제로 들어가는 것 (`embed.py:69-78`) | `embed_input()` = `context` + `\n` + `text` |
| `chunk.tsv` (`db/schema.sql:192`) | `coalesce(context,'') || ' ' || text` |

0008 이 `context` 를 만들면서 **재는 문자열과 쓰는 문자열이 갈렸다.** 그런데 두 곳이
아직 갈리기 전 이야기를 한다 —

- `db/schema.sql` — `COMMENT ON CONSTRAINT ck_chunk_tokens ... '리랭커 bge-reranker-v2-m3 의 512 토큰 상한에 맞춘다'`
- `app/retrieve.py:32-34` — *"`ck_chunk_tokens` 가 그 리랭커의 상한에 맞춰져 있어 **자리는 준비돼 있다**"*

⛔ 리랭커에 넣을 문자열이 `context+text` 라면 자리는 준비돼 있지 않다. `context` 는
「조 제목 + 항 본문」이고 항 본문은 그 자체로 700자까지 갈 수 있다.

⬜ **안 쟀다** — `context` 토큰 분포도, KURE-v1 의 `max_seq_length` 도 안 봤다.
그러므로 **「지금 초과한다」고 말하지 않는다.** 말하는 것은 *「CHECK 가 지키는 값이
쓰이는 값이 아니다」* 하나다. 리랭커 모델 선정(남은 것 #5)이 이 칸을 정하는 자리다.

## ⑤ 설계 결정을 건드리는 발견

### ⑤-1 · F-1 (`part` 미배선)

**새 사실** — 쪼갠 청크 121개가 「잘렸다」는 표시 없이 DB·응답·`citation()` 을 지난다.

**영향받는 결정** — **D-158**(청킹 단위는 인용 단위) · **D-100**(부분 인용 금지) ·
**D-72**(없음이 성공으로 집계되지 않게).
⛔ D-158 은 *"임의 길이로 자르지 않는다"* 로 서 있는데, `_split_long()` 은 700자에서
**임의 길이로 자른다.** 예외를 `part` 가 표시하기로 했고 그 표시가 안 산다.

| 대안 | 얻는 것 | 떠안는 것 |
|---|---|---|
| ① `chunk.part` 열을 더한다 (0011) | `citation()` 이 「제18조 (1/3)」을 낼 수 있다. 121개가 스스로 말한다 | 마이그레이션 하나 + 뷰 재생성 + `CHUNK_COLS`·`_SELECT`·`Hit`·`SearchHit` 넷. **재적재 필요** |
| ② 쪼갠 청크는 `citation()` 이 **`None`** 을 낸다 | 열 없이 오늘 막힌다. 「틀린 인용보다 없는 인용」이 이 함수의 원칙이다 | 121개가 **근거 없이** 검색에만 걸린다. 무엇이 잘렸는지는 여전히 아무 데도 안 남는다 |
| ③ 그대로 둔다 | 0 | D-100 이 다른 문으로 뚫린 채 발표에 간다 |

★ ①과 ②는 배타적이지 않다 — **②를 오늘, ①을 리랭커 판정과 같은 판에** 두는 것이 맞아 보인다.
🚨 다만 ②도 「①/N」을 만들려면 `part` 를 알아야 하므로, **②만으로는 열 없이 못 한다** —
`chunk_id` 접미사 `#{i}` 로 「i>0 이면 조각」은 알 수 있으나 **`i=0` 인 첫 조각은 구별이 안 된다.**
그러므로 실질적으로 **①이 전제**다. 이 판단이 내가 틀릴 수 있는 지점이다.
