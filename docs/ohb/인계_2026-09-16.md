### 예산의 단위 — 요청당이다 (확정)

D-77 L3 원문의 소계를 더하면 닫힌다:

```
50 + 100 + 20 + 300 + 500 + 150 = 1,120 ms  ≈  판정 소계 1.1 초
```

각 단계가 **한 번씩** 더해져 소계가 된다. 그리고 「문장 분할」이 같은 표 안에 있다 —
요청당 한 번 일어나는 단계다. → **`BM25 + 벡터 검색 < 300ms` 는 요청 1건의 배분이다.**

그러면 문장 수별로 —

| 문장 수 | `search` × N (어림) | 300ms 배분 대비 |
|--:|--:|--:|
| 1 | 193 ms | ✅ |
| 2 | 387 ms | 🔴 1.3배 |
| 4 | 773 ms | 🔴 2.6배 |

`split` 이 스텁이라 지금은 문장 하나만 돈다 (D-127). **증상이 안 보이는 것뿐이고, `split` 을
세우는 순간 드러난다.** 그래서 배치 인코딩은 `split` 보다 나중이 아니라 **같은 작업**이어야 한다.

다만 **판정 목표 `p95 < 3초`** 는 여유가 크다. D-77 자신이 「배분은 총합이 아니라 최적화
대상을 정하기 위한 것」이라고 쓴다 — 배분 초과는 실패가 아니라 1순위 표시다.
