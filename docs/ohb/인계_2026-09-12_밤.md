## 1. 🔴 무엇을 고쳤나 — 치명 둘

### ① `part` — 만들어 놓고 아무도 안 읽던 값 (D-199)

`preprocess/chunk.py` 는 700자 초과 조문을 문장 경계로 쪼개며 `part = "1/3"` 을 만든다.
docstring 이 그 이유를 *"잘렸다는 사실을 데이터가 들고 있어야 화면이 「제N조 (1/3)」이라
말할 수 있다"* 라 적어 두었다. **그 값은 DB 에 열조차 없었다.**

    chunk.py:159   만든다 → CHUNK_COLS 없음 → chunk 테이블 없음 → _SELECT 없음 → 화면 없음

⛔ 그래서 `citation()` 이 3분의 1짜리 조각에 **「제18조」**를 달았다. 좌표로는 맞지만
**전문이 아니고**, 받는 쪽은 그 차이를 알 방법이 없다.
🚨 기획서 5-6 이 *"인용 검증은 「존재」가 아니라 「일치」까지"* 라 못 박은 자리가 정확히 여기다.
그리고 `citation()` 은 **바로 그 부분 인용을 막으려고** 쓴 함수다 (D-100) —
**막으려던 것이 다른 문으로 들어왔다.**

★ **`citation()` 은 순수하게 뒀다.** 「제18조 (1/3)」로 섞으면 판정 결과의 조문 집합과
대조하는 코드가 괄호를 벗겨야 한다. **좌표는 좌표대로, 「일부다」는 옆 칸으로.**
0011 이 `part_no`·`part_total` 을 세우고 `_SELECT` → `Hit` → `SearchHit` 까지 이었다.

⬜ **크기는 모른다** — 쪼갠 121개 중 `citation()` 이 실제로 값을 내는 것이 몇인지 안 셌다.
별표는 애초에 `None` 이므로 121 전부는 아니다.

### ② 대칭을 검사한다는 게이트가 같은 인자를 두 번 불렀다 (D-203)

```python
for a, b in ((vec, lex), (lex, vec)):
    rt.fuse(a if a is vec else vec, b if b is lex else lex, limit=1)
```

두 바퀴 모두 `fuse(vec, lex)` 로 접힌다. 🚨 **이 게이트는 09-12 오후에
*"한쪽만 보는 대칭 검사는 반대쪽을 못 잡는다"*(D-170)를 고치려고 새로 쓴 것이다** —
고친 게이트가 같은 병을 다른 모양으로 앓았다.

⛔ 그리고 **단언 자체가 틀렸다.** `fuse()` 는 인자 위치가 갈래를 정하므로 바꿔 부르면
어휘 결과가 `rank_vector` 로 집계되는 것이 **맞는 동작**이다. 루프가 아니라 **재는 것**을
바꿨고, 「인자 위치가 갈래를 정한다」를 별도 게이트로 못 박았다.

### 🔄 같은 날 밤 — D-201 을 D-205 로 고쳤다

⑤의 처방 자체가 틀린 방향이었다. **D-201 은 부분 대체됨(→ D-205)** 이다 —
`[임의]` 오기 정정과 출처 태그 집계처는 살아 있고, **`[설계]` 의 정의**와
「기획서 개정이다」 한 문장이 대체된다. `[설계]` 는 「문서가 고정했다」가 아니라
**「설계 문서가 놓은 잠정값이고, 바꾸는 조건이 같이 적혀 있다」**이다.
🔴 **조건 칸이 비면 그것은 `[설계]` 가 아니라 `[임의]` 다.**

**사소 넷** — 어휘 갈래 상태 칸 신설(`no_terms`) · `counts` 키에 분모 박기(`_pool`/`_top`) ·
`Σ 1/(60+순위)` 의 상수 복제 제거 · 「같은 문자열」 → 「같은 토큰열」 정정. 앞 둘이 D-202 다.
