## 1. 이미 정해져 있던 것 — 회의가 다시 도달한 자리 다섯

### ① 「합법 문장이 여럿 모이면 불법」 → **D-83 층 3 · 규칙 R-D1** ★

회의가 든 예와 기획서 2-4 ②의 예가 **같은 구조**다.

```
"저희 어머니가 위암 진단을 받으셨습니다."      <- 단독: 적법
"매일 이 양파즙을 드셨습니다."                  <- 단독: 적법
"지금은 검사 결과가 좋아지셨어요."              <- 단독: 적법
```

이미 정해진 처리 방식 —

```
R-D1   [질병명 언급] ∧ [제품 섭취·사용 서술] ∧ [호전·개선 서술]  ->  문서 수준 플래그
```

| 원칙 | 내용 |
|---|---|
| **인코더가 아니라 코드** | 문장별 판정 결과의 **집합 연산**. 주장 원장(5-8절)이 문서 전체의 주장을 이미 모은다 |
| 🚨 **「위법 판정」이 아니라 「문서 수준 경고」** | 진짜 개인 후기일 수 있다. 문장별 판정과 **층을 분리**해 표시하고 **Abstention + 전문가 검토 권고**로 낸다 |
| **범위 선** | 규칙은 **R-D1 하나로 시작**한다. 유형 확대는 **9/17 범위 확정(D-65)**에서 판단한다 |

> **회의가 새 문제를 발견한 것이 아니라, 이미 답이 있는 문제를 다시 만난 것이다.** 설계할 것은 UI 쪽뿐이다.

### ② 「이미지 안 내용은 멀티모달로도 판별 불가 · 환각 시 법적 리스크」 → **D-104**

기획서 2-4 ②가 **더 강한 근거로 이미 기각**했다 —

| 형태 | 기존 판단 |
|---|---|
| 판정에 반영 | ❌ 이미지 골든셋이 없어 **정확도를 주장할 수 없다**(유형별 30건) |
| **참고용 힌트로 표시** | 🚨 **가장 나쁘다** — 화면에 경고가 뜨면 사용자는 **검수받았다고 느낀다.** 「힌트는 판정이 아니다」를 강제할 수단이 UI 문구뿐이다 |
| 생성 보조 | ⬜ 설계만 |

그리고 기존 문서는 회의가 아직 짚지 않은 것을 짚어 뒀다 — **글자가 한 자도 없어도 성립하는 위반**(흰 가운·청진기 의료인 연출, 체험 전후 사진, 알약 소품). **사용자에게 이미지 속 문구를 입력하게 해도 안 잡힌다 — 적을 글자가 없다.**

### ③ 「대량 문구 검수」 → **D-105 배치 검수 · Phase 1**

CSV 일괄 판정 → 엑셀 리포트가 이미 Phase 1 범위에 있다.

### ④ 「생성과 템플릿은 진입점이 다르다」 → **D-103 이 이미 그렇게 갈랐다**

> *"생성기는 문구만 만들고, **매체를 아는 것은 템플릿뿐이다.**"*

회의 결론이 D-103 의 문장과 같다. **진입점 3원화의 근거는 이미 문서 안에 있다** — 다만 기획서 **2-5절이 아직 「이원화」**라고 쓰여 있어 본문이 결정을 따라가지 못했다(아래 3-①).

### ⑤ 「각 화면별 단락을 나눠 이미지·글 위치를 우리가 지정」 → **UI v6.7 섹션 템플릿 9종이 이미 실물**

후킹 · 공감 · 소구점 3분할 · 물품설명 · 성분함량 · 사용법 · 후기 · 배송 · **필수표기(삭제 불가 · 최종 고정)**.
슬롯별 이미지 업로드 + 대체 텍스트까지 들어가 있다. **회의가 정한 방식이 이미 만들어져 있다.**

## 2. 🚨 회의록 안의 모순 하나 — 이미지 판정 범위

같은 회의록에 서로 반대되는 문장이 있다.

| 문장 | 뜻 | OCR |
|---|---|:-:|
| *"**이미지가 아닌 문구만** 검수한다는 명시"* | 이미지를 **아예 안 본다** | 불필요 |
| *"**이미지 안 문구만** 판정을 해준다는 고지가 필요하다"* | 이미지 속 글자는 **본다** | **필요** |

🚨 **둘은 다른 제품이다.** 뒤쪽을 택하면 OCR 이 판정 경로에 들어오고, 그 순간 D-104 가 기각한 **「힌트 표시」와 구분이 안 된다** — 이미지에서 뽑은 글자만 판정하면 사용자는 **이미지 전체를 검수받았다고 느낀다.** 그것이 D-104 가 *"가장 나쁘다"* 고 적은 형태다.

**제안 — 앞쪽으로 확정한다.**

> **입력은 텍스트만 받는다. 이미지는 배치용으로만 업로드되고 판정 대상이 아니다.**
> 산출물에 **「이미지 내 문구 미검수」**를 제거 불가능하게 단다 (기획서 2-4 ④가 이미 정한 문구).

## 3. 새로 정해야 할 것 셋 — D-119 ~ D-121 후보

### D-119 (후보) · 진입점을 3원으로 개정한다

기획서 2-5절은 **이원**(A 검수 · B 생성)인데 D-103 이 템플릿을 생성기 밖으로 뺐다. 본문이 결정을 따라가지 못한 상태다.

```
                    +------------------------+
                    |    공용 판정 코어      |   <- 단일 진실 원천
                    +---+--------+-------+---+
                        ^        ^       ^
                 API    |        | 내부  | 내부
        [A 판정]        [B 생성]        [C 템플릿]
        이미 쓴 문구    세그먼트→문구    승인된 문구 → 지면 배치
        방어재          공격재           🚨 매체를 아는 유일한 층
```

★ **C 가 매체를 아는 유일한 층**이라는 것이 핵심이다. SNS·블로그·배너·상세페이지의 규격·고지 위치는 **생성기가 아니라 템플릿이 갖는다.** 그래서 매체를 늘려도 생성기는 그대로다.

🚨 **다만 「판정 코어는 하나」는 유지된다.** 2-5절의 발표 문장(*"하나를 만들어 두 번 씁니다"*)은 **"세 번 씁니다"** 로 바뀔 뿐 구조는 같다.

### D-120 (후보) · 입력 형태를 3종으로 나눈다 — **이것이 회의의 진짜 새 결정이다**

회의는 *"입력 템플릿을 별도로 나눈다"* 고 정했다. **UI 편의가 아니라 판정 의미가 달라서 옳다** —

| 입력 형태 | 문서 경계 | 판정 단위 | **층 3 (공존 규칙 R-D1)** | 산출 |
|---|:-:|---|:-:|---|
| **단순 광고문구** | 문서 1개 | 문장 | 문장이 하나면 발동하지 않음 | 문장 판정 |
| **대량 · 단일문구 여러 개** | 🚨 **문서 N개** | 문장 각각 독립 | ❌ **적용하지 않는다** | 문장별 판정 + 엑셀 리포트 (D-105) |
| **대량 · 긴 글 (한 내용)** | 문서 1개 | 문장 + **문서** | ✅ **적용한다** → 문서 수준 경고 + Abstention | 문장 판정 + 문서 플래그 |

🚨 **두 대량 입력의 차이는 「문서 경계」다.** 층 3은 **한 문서 안에서만** 돈다.
서로 다른 광고물 100건을 한 문서로 보고 공존 규칙을 걸면 **오탐이 쏟아진다** — 「질병명」은 1번 문구에, 「호전 서술」은 57번 문구에 있는데 R-D1 이 발동한다.

> **그래서 입력 화면을 나누는 것은 편의가 아니라 계약이다** — 사용자가 고른 입력 형태가 **문서 경계를 선언**한다.
> 이 한 줄이 없으면 구현자가 층 3을 어디까지 돌릴지 알 수 없다.

★ 회의가 정한 UI(긴 글 + 단순 문구는 같은 화면, 단일 문구 여러 개는 「추가」 버튼으로 분리)가 이 계약과 정확히 맞는다. **추가 버튼이 곧 문서 경계다.**

### D-121 (후보) · 사용자 업로드물은 등급 체계 밖이므로 별도 축을 만든다

회의의 저작권 우려는 실재하지만 **자리가 다르다.**

| 우려 | 실제 성격 |
|---|---|
| *"이미지를 받아오면 내부에 저장돼 저작권 문제"* | 사용자가 올린 이미지는 **사용자의 저작물이거나 사용자가 권리를 확보한 것**이다. 우리의 저작권 침해가 아니라 **이용 허락 범위**와 **보관**의 문제다 |
| *"대량 문구를 파일로 받으면 저작권 문제"* | 같다. 다만 **파일은 판정 후 원문을 파기**하면 문제가 사라진다 |

🚨 **진짜 위험은 다른 데 있다 — 학습이다.**

우리 등급 체계(G0~G3 × U1~U4)는 **수집 소스**를 대상으로 만들었다. **사용자 업로드물은 이 축에 존재하지 않는다.** 게이트 17번이 `data/raw/` 를 지키고 있지만, 사용자 업로드물이 다른 경로로 들어오면 **어느 게이트도 막지 않는다.**

**제안 — 이미 있는 축으로 새 축을 묶는다** (D-108 이 쓴 방법과 같다).

- 사용자 제공 콘텐츠에 **`U-USER` 등급**을 두고 **전 용도 `deny`** 로 정의한다 (G0 와 같은 fail-closed).
- 학습·색인·재배포가 **정의상 불가능**해지므로 규칙을 새로 늘리지 않아도 게이트가 자동으로 막는다.
- 보관은 **P1-6**(입력 문구 보관 정책 · 보안점검 미해결)에 얹는다 — **구조화 값은 남기고 원문만 파기**하는 분리가 이미 설계돼 있다.
- 약관에 **이용 허락 범위**(판정·생성 목적 한정 · 학습 미사용)를 명시한다. 🚨 **「학습에 쓰지 않는다」는 우리가 실제로 지킬 수 있는 약속이다** — 게이트가 강제하기 때문이다. 이건 발표에서 쓸 수 있다.

## 4. 🚨 범위를 늘리는 것 하나 — 기사형

회의는 광고 종류를 **SNS · 블로그 · 배너 · 기사 · 상세페이지 5종**으로 잡았다. 그런데 —

| | |
|---|---|
| **기획서 8-2** | 「기사형·인스타·유튜브 템플릿」은 **향후 과제**다 |
| **D-93 개정분 ①** | 기사형은 **설계만** 해 뒀고 *"규제 축이 다르다"* 고 적혀 있다 |
| **UI v6.7** | 포맷 7종에 **기사형이 없다** |

🚨 **기사형은 판정 축이 하나 더 필요하다.** 기존 위법 유형은 *"무엇을 주장했는가"* 인데 기사형은 *"형식이 독자를 오인시키는가"* 다. **축이 다르다.**
그리고 `ftc_decisions` 의 기사형 제재 사례가 **30건 미만이면 D-40 대로 「측정 불가」**다. **9/17 범위 확정(D-65)에 걸리는 사안이다.**

★ **반대로 지표는 가장 깨끗하다.** 「광고」 표시 유무는 **이진 판정**이라 코드로 100% 검증된다 — *"기사형 출력의 표시 누락률 = 0"* 이 **확률 지표가 아니라 구조적 보장**으로 나온다.

**제안 — 두 갈래로 갈라서 넣는다.**

| 무엇 | 판단 |
|---|---|
| **기사형 「생성」 + 「광고」 표시 구조적 강제** | ✅ **넣는다.** 템플릿 슬롯에 코드가 표시를 주입하면 되고, 지표가 이진이라 깨끗하다 |
| **기사형 「판정」 (형식 오인 축)** | ⏸ **9/17 실측 후.** 제재 사례 30건 미만이면 「측정 불가」로 명시하고 넣지 않는다 |

**먼저 할 일 — `scripts/collect.py report` 로 기사형 제재 사례 건수를 센다.** 반나절이면 답이 나온다.

## 5. Canva MCP · 자체 편집 환경

회의 결론(*"우선 생성에 집중"*)이 맞다. 근거를 붙인다 —

- **자체 편집 환경은 이미 있다.** UI v6.7 의 섹션 에디터가 슬롯 배치·줌·순서 변경·이미지 업로드까지 돌아간다. **새로 만들 것이 아니라 붙이면 된다.**
- **드래그 자유 배치는 넣지 않는다.** 자유 배치를 허용하면 **필수 표기 위치 고정(REQ-N-012)과 크기 하한(REQ-N-011)을 강제할 수 없다.** 슬롯 안에서의 조정까지만 연다 — 🚨 **이건 기능 제약이 아니라 안전 설계다.**
- **Canva MCP 연동은 Phase 5 이후.** 외부 편집기로 내보내는 순간 **우리가 강제한 고지가 편집될 수 있고**, 그러면 판정 게이트가 무의미해진다. 연동한다면 **「내보내면 판정 보증이 끝난다」는 고지**가 함께 가야 한다.
