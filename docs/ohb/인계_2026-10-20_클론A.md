## §3 이 판에서 확인한 사실 (코드 · 도구 — 다음 세션이 다시 재지 않아도 되는 것)

- 판정 그래프 순서 — `split` → `classify`(받은 품목만) → `retrieve` → `match_dict` → `encode` → 법별 노드 → `merge_laws` → `judge`(사전 C 칸만 확정 · 나머지 후보) → `assess_risk` → `premise_branches` → `doc_rules`(인코더 쪽 판정 · 질문) → `references` → 종착
- 위험도 = max(사전 하한, 인코더 하한)은 집행됨 · 단 인코더 하한은 기록에 **R1 까지**(`ENCODER_RECORD_MAX`)이고 주장 가드를 지나야 붙는다 · 판정(확정 / 보류)은 별개 규칙(보충 5 결정 1 「더 나쁜 쪽」)
- 인코더만으로 답 없이 확정하는 경로 — 절대형 C(τ 0.699) · 식품 3호 · 건기식 비인정 4.나(τ 0.693) · 품목을 알 때만 · 거짓 · 과장 신뢰 규칙(`_encoder_trusted`)은 부르는 곳 없음(보충 20 결정 3)
- 질문 흐름 — 한 번에 하나 · 답을 들고 다시 판정 · 사실 → 실증 이어 묻기 · 갈래 결과 max · 답 셋(예 R0 · 아니오 확정 · 해당 없음 걷음) — 팀장 제안(답을 모아 종합)은 이미 설계다 · 막히는 것은 질문이 서는 범위
- 문서 · 코드 드리프트(사소) — `graph.py` 머리말 23 ~ 24 · `SentEncoding` 172 · `encode` 1116 · `judged_by` 4135 「판정은 인코더를 읽지 않는다」 · `guidance` 3900(걷은 `_substantiated`) · `_enc_confirmed` 3601 「[판정 대기]」(보충 7 결정 10 채택됨) · `_enc_disease` 는 `인정_기능성` 이 `FACT_TEXTS` 에 없어 늘 None
- 사본 기기 동기화 명령의 성격 — `load` · `embed` 는 그 기기 DB 만 바꾼다(공유물 쓰기 없음) · `chunk`(`--dump` 없이)는 미리보기라 사본에서 필요 없다 · `--dump` 는 `only_canonical` 로 사본에서 막힘 · `embed` 는 전 행을 다시 임베딩해 덮어쓰고(`ON CONFLICT DO UPDATE`) 파일에 없는 청크를 지운다 → **data-sync 다음에만** · `load` 도 파일에서 사라진 사전 · 골든 행을 거둔다 · `judgment`(이력)는 건드리지 않는다
- data-sync 범위 — 파생물 원장의 `data/derived/` 245 개만(코드 · 템플릿 무관)
- `load` 의 「`mfds_cosmetic_sanction` 1」 — `data/manifest.jsonl` 25,548 행(권소라 기기 · 09-22 · 행정처분.xlsx)의 수집 원장 줄 · 원천이 attribution 없음(G3)으로 `source` 에 못 들어가 FK 때문에 넣지 않음(D-149 · D-220) · 판정 무관
- 동기화의 축 일곱과 맞추는 명령 — 코드(git) · 패키지(`uv sync`) · 파생물(`data-sync`) · 모델(드라이브 → `model_lock check` → `setting`) · `.env`(`setkey` · `setting`) · 스키마(`migrate`) · DB 내용(`load` → `embed`) · 최종 대조는 `eval_graph` 수를 원장 최신 절과(`check` 는 DB 내용을 보지 않는다)

## §7 틀렸던 것

1. 사본 동기화 순서에 `chunk` 를 넣었다 — `--dump` 없는 `chunk` 는 미리보기라 사본에는 필요 없다(`load` → `embed` 가 맞다)

3. 두 eval 실행에 같은 `--out` 경로를 권해 조건부 결과 파일이 무조건부로 덮였다(뒤에 `_cond` 로 다시 돌림)
