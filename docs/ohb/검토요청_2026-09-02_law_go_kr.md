## 1. 🚨 먼저 — 판정 근거 URL 을 교체해야 합니다

현재 레지스트리는 이렇습니다.

```yaml
evidence_url: "https://open.law.go.kr/LSO/openApi/guideList.do"
evidence_is_access: true      # 🚨 이 플래그가 문제를 말하고 있다
```

**확인 항목 4** — 근거 URL 은 「**그 조건을 말하는 페이지**」여야 합니다. 그런데 `guideList.do` 는 **API 목록 페이지**입니다. 실제로 열어 보면 서비스 종류·신청 방법만 있고 **이용조건·저작권 문구가 한 줄도 없습니다.**

이대로 서명하면 `kcia_guideline` 과 같은 자리에 섭니다 — 「근거가 재현되지 않는다」로 나중에 서명이 무너집니다. `mfds_production` 이 2026-09-02 에 KDI 재게시 페이지 → 식약처 저작권정책으로 교체한 것과 같은 정정입니다.

### 교체할 근거 URL

```
https://www.law.go.kr/LSW/lawPetitionForm.do?menuId=13&subMenuId=79
국가법령정보센터 > 그밖의 정보 > 법적효력/저작권
```

**원문 (2026-09-02 확인)**

> 국가법령정보센터에서 제공하는 법령정보 중 「저작권법」제7조(보호받지 못하는 저작물)에 해당하는 정보 및 법제처가 저작재산권의 전부를 보유한 저작물의 경우에는 **별도의 이용허락 없이 자유이용이 가능**합니다.
>
> 「공공데이터의 제공 및 이용 활성화에 관한 법률」에 근거하여 국가법령정보센터에서 제공하는 법령정보는 누구에게나 개방되어 있으며, 제공된 법령정보는 **영리 목적의 이용을 포함하여 자유로운 활용이 보장**됩니다.

「제한 없음」이 아니라 **「영리 목적 포함 자유 활용 보장」이라고 명시**돼 있습니다. 상업 축이 문장으로 확인되는 몇 안 되는 소스입니다.

법적 근거도 두 겹입니다 — **저작권법 제7조**(법령·고시·판결은 보호받지 못하는 저작물) + **공공데이터법**. 공공누리 배지에 기대지 않으므로 **D-110 의 유형 판정(제1유형이냐)이 필요 없습니다.**

## 3. 🚨 검토자가 따져 주셔야 할 것 — 셋

### ⓐ 「제3자 권리」 단서 — 프래그먼트 축입니다 (D-18)

> ※ 단, 정보공개법 제9조의 비공개대상정보와 **저작권법 및 그 밖의 다른 법령에서 보호하고 있는 제3자의 권리가 포함**된 것으로 해당 법령에 따른 정당한 이용허락을 받지 아니한 정보는 제공대상에서 제외됩니다.(공공데이터법 제17조)

법령 본문은 저작권법 제7조로 깨끗합니다. 문제는 **판례·재결례**입니다 — 본문에 제3자 저작물(광고 문안, 도표, 인용문)이 실릴 수 있습니다. `ftc_decisions` 가 「의결서 안 `<그림 N>` 광고 캡처는 G1」로 처리한 것과 **같은 구조**입니다.

→ **제안**: `fragment_note` 를 답니다 — *"법령·고시 본문은 G3. 판례·재결례 본문에 인용된 제3자 저작물(광고 문안·도표·이미지)은 미추출."*

### ⓑ 🚨 「법적 효력이 없다」 — 제품 고지 의무

> 국가법령정보센터에서 제공되는 법령정보는 **법적 효력이 없으므로, 참고자료로 활용**하시기 바랍니다. (…) 효력은 **관보** 등에 있습니다.

우리 제품은 3층을 **RAG 근거로 화면에 인용**합니다(U3). 사용자는 그것을 판단 근거로 봅니다. 이 고지가 `DISCLAIMER.md` 와 인용 UI 에 반영돼야 합니다 — 이용조건 위반은 아니지만 **제품 책임 축**입니다.

### ⓒ 🚨🚨 「위조·변조」 형사처벌 조항 — 설계 제약입니다

> 특히, 다음과 같은 사항은 **형사처벌**을 받을 수 있으니 유의하여 주시기 바랍니다.
> ▣ 법령정보를 **위조·변조하여 제공**하거나 근거자료로 제출하는 행위

**이 문장이 이 검토의 가장 중요한 발견입니다.**

CopyLane 은 LLM 이 법령 조문을 인용해 판정 근거를 제시하는 제품입니다. **모델이 조문을 요약·재작성·환각하면 「법령정보를 변조하여 제공」의 외형이 됩니다.** 이용조건이 아니라 형사 축이고, 제약 플래그로 표현되지 않습니다.

→ **제안 — 이건 서명 사항이 아니라 설계결정 사항입니다**:
- 3층 법령 원문은 **생성 경로에 넣지 않는다.** 모델은 **조문 ID 만 고르고**, 화면에 뜨는 문장은 **수집한 원문을 그대로** 출력한다
- 인용에는 항상 **원문 링크 + 「법적 효력은 관보에 있다」** 고지를 붙인다
- 요약이 필요하면 **원문과 요약을 분리 표기**한다

## 4. 동반 확인 — `ftc_decisions_api` 는 이 건과 묶여 있습니다 (D-113)

2026-09-02 확인: data.go.kr **15103246 의 API 유형이 LINK** 이고, `linkUrl` 이 가리키는 곳이 **법제처**입니다.

```
GET https://www.data.go.kr/tcs/dss/selectApiLinkUrl.do?publicDataPk=15103246
→ linkUrl: https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=cmtListGuide#ftc
요청  https://www.law.go.kr/DRF/lawSearch.do?OC=..&target=ftc&type=XML
```

🚨 **서명이 덮는 곳과 실제로 부르는 곳이 갈립니다.** `ftc_decisions_api` 는 이미 서명돼 있는데(권소라, 2026-09-02) 그 서명의 근거는 data.go.kr 「이용허락범위 제한 없음」입니다. 실제 호출은 법제처이고 **키도 `LAW_OC_KEY` 하나를 공유**합니다.

→ **제안**: `ftc_decisions_api` 에 `evidence_url` 을 하나 더 달거나(§1 의 법적효력/저작권 페이지), 최소한 `note` 에 「호출처는 법제처 · `law_go_kr` 과 동일 경로」를 적습니다. **재서명이 필요한지는 검토자 판단**입니다.

## 5. 남는 미확인 (판정을 막지는 않습니다)

- **[별표] 조회 가능 여부** — 레지스트리 `note` 에 있는 그대로 미확인입니다. 조회가 안 되면 시행령 별표를 본문 HTML 파싱으로 받아야 하고 **수집 경로가 갈립니다**(수집리스트 S2-04). 이용조건 문제가 아니라 수집 방법 문제라 서명과 무관합니다.
- **API 응답 형식** — HTML/XML 뿐이고 JSON 이 없습니다. `collect/law_api.py` 가 이미 있어 `openapi.py` 의 제약(D-113 ④)과는 별개입니다.
