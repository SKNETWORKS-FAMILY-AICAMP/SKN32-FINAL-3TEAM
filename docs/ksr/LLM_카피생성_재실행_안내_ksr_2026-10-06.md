## 4. 엔진이 사는지 먼저 확인

아래를 `try_judge.py` 로 저장해 돌린다(저장소 루트에서 · `PYTHONPATH` 를 저장소 루트로).

```python
import logging; logging.disable(logging.CRITICAL)
from app.api import judge
from app.contracts import JudgeRequest, ProductContext, Category

cases = [
    ("세안 후 산뜻하게 마무리하는 촉촉 수분크림", Category.화장품, False),
    ("지친 피부를 재생시키는 수분크림", Category.화장품, False),
    ("출근 전 우유에 바로 부어 즐기는 아침곡간 그래놀라", Category.식품, False),
    ("면역력을 채워 주는 그래놀라", Category.식품, False),
    ("출근 전 하루 한 캡슐, 유산균 증식 및 유해균 억제·배변활동 원활·장 건강에 도움을 줄 수 있음", Category.건기식, True),
]
for text, cat, rec in cases:
    r = judge(JudgeRequest(text=text, product=ProductContext(category=cat, has_recognized_function=rec)))
    d = r.model_dump(mode="json")
    print(cat.value, "|", text[:30])
    print("  outcome:", d["outcome"], "| branches:", [b["premise"] + ":" + b["outcome"] for b in d["branches"]])
    for s in d["sentences"]:
        print("  ", s["verdict"], s["hold_reason"], s["violations"], (s.get("risk") or {}).get("final"))
```

## 5. 실험을 다시 돌린다

### 5-1. 후보는 그대로 쓴다

- 10-03 로그의 후보(모델이 돌려준 원문)를 그대로 다시 판정한다. GPT 를 새로 부르면 후보가 달라져서 「엔진이 바뀐 효과」와 「후보가 바뀐 효과」가 섞인다.
- 로그가 없으면 결과 문서의 표(실행 1~6 · 최소 입력 2회)에 적힌 문구를 옮겨 쓴다.
- GPT 를 다시 부르는 실행은 5-1 이 끝난 뒤에 따로 한다.

### 5-2. 품목을 넘긴다

- 기획의 분기가 정해져 있으므로 판정 요청에 품목을 넣는다(`ProductContext(category=…)`).
- 품목을 안 넘기면 후보마다 전제 6개 분기가 붙고 사유가 「품목 미확정」으로 바뀐다. 비교가 복잡해질 뿐이다.
- 건강기능식품 · 인증 예 분기는 `has_recognized_function=True` 로 넘긴다.

| 기획의 분기 | 넘길 품목 | 인정 여부 |
|---|---|---|
| 식품 · 인증 아니오 / 예 | `Category.식품` | False |
| 건기식 · 인증 예 | `Category.건기식` | True |
| 건기식 · 인증 아니오 | 기획대로 `Category.식품` (안내 후 식품 분기) | False |
| 화장품 · 인증 아니오 / 예 | `Category.화장품` | False / True |

### 5-3. 「탈락」을 무엇으로 볼지 먼저 정한다

10-03 스크립트는 판정엔진을 「탈락 판정용」으로 썼다. 지금 응답에서는 아래 셋이 서로 다른 뜻이니 **셋을 따로 센다.**

| 구분 | 응답에서 | 뜻 |
|---|---|---|
| (가) 유형 붙은 문장 | `violations` 가 비지 않음 | 엔진이 위반 후보를 봤다 — 탈락 |
| (나) 조용한 보류 | `verdict=hold` · `hold_reason=low_conf` · `violations` 빔 | 엔진이 못 봤다 — 통과가 아니다. 지금은 「보관」으로 넘길 수밖에 없다 |
| (다) 통과 | `outcome=pass` | 지금은 나오지 않는다 |

- 서은님 쪽 재판정도 「위반 유형이 붙은 보류」를 탈락으로 처리한다(10-04 공유). 같은 기준을 쓰면 두 쪽 결과를 나란히 볼 수 있다.
- 스크립트가 응답의 칸 이름에 기대고 있으면 오류가 날 수 있다. 그사이 응답에 `branches` · `category_source` · `certificate` 가 채워지기 시작했고, 품목을 넘기면 `category_source` 가 `user_selected` 로 온다.

### 5-4. 프로바이오틱스는 두 번 센다

- 인정 문구가 든 후보는 (가)에 걸려 **전부 탈락**으로 나올 가능성이 크다(4번 표의 5번).
- 이건 후보가 나쁜 것이 아니라 엔진의 오탐이다. 그래서 ① 문구 전체를 판정한 결과 ② 인정 문구를 뺀 앞부분만 판정한 결과를 둘 다 적는다.
