## 캡처별 상세

### 01 🔴 오류 — 검수 결과에서 다크 모드를 누르면 원문 오류

- **캡처**: `1015_01a_오류_검수결과_다크모드전.png`(누르기 전) · `1015_01b_오류_검수결과에서_다크모드_405.png`(누른 뒤)
- **장면**: 검수 결과가 나온 화면에서 상단의 달(다크 모드) 버튼을 누름
- **원래 이렇게 보여야**: 같은 검수 결과가 어두운 색으로 다시 보임
- **실제**: 흰 화면에 `{"detail":"Method Not Allowed"}`만 보이고 검수 결과가 사라짐
- **원인**: 다크 모드 버튼(`_topnav.html` → `POST /u/theme`)은 「지금 주소」로 되돌아가요. 그런데 검수 결과 화면의 주소 `/u/judge`는 폼을 보낼 때만(POST) 열리는 주소예요. 되돌아갈 때는 주소를 그냥 여는 것(GET)이라 405가 나요(`app/routers/user.py` `user_theme`).
- **같은 문제가 나는 곳**: 고쳐 쓰기 결과(`/u/review/rewrite`) · AI 광고 초안 판정(`/u/compose/judge`). 결과 화면에서 새로 고침을 해도 「양식 다시 제출」 확인 창이 떠요.
- **고칠 방향**: 다크 모드는 폼 대신 쿠키만 바꾸고 그 자리에서 색만 바꾸기. 또는 결과 주소일 때 되돌아갈 곳을 입력 화면(`/u/review`)으로 바꾸기. 405가 날 때 원문 대신 안내 화면 보여 주기.

### 02 🔴 오류 — 개발용 머리줄과 꼬리말이 모든 화면에 보임

- **캡처**: `1015_02_오류_개발용_머리줄_꼬리말_노출.png`
- **장면**: 로그인 전후 상관없이 랜딩을 뺀 모든 사용자 화면
- **원래 이렇게 보여야**: 상단에는 서비스 메뉴(copylane 소개 · 검수 및 카피생성 · AI 광고 생성 · 매칭)만 있어야 해요
- **실제**
  - 맨 위에 밑줄 링크 「CopyLane · 사용자 · **관리자** · **API**」가 한 줄 더 있음 → 로고가 두 번 보이고, 이용자가 관리자 로그인과 API 문서(`/docs`)로 바로 갈 수 있음
  - 맨 아래 꼬리말 「판정 근거를 조문으로 돌려준다 · 이 화면은 **골든 픽스처로 그린다 (D-124)**」는 실제 판정 화면인데 가짜 예시라고 말함
- **원인**: 사용자 화면 틀(`user/_base.html`)이 개발용 공통 틀(`app/templates/base.html` 33~45행)의 `<header>` · `<footer>`를 그대로 물려받아요
- **고칠 방향**: 사용자 화면에서 공통 틀의 머리줄 · 꼬리말 블록을 비우기

### 03 🔴 오류·안내 — 광고 기본값 「저장」이 저장되지 않음

- **캡처**: `1015_03a_오류_광고기본값_저장안됨.png` · `1015_03b_안내_사용방법이_실제화면과_다름.png`
- **장면**: 마이페이지 › 광고 기본값에서 성별 · 광고 물품을 고르고 「저장」
- **원래 이렇게 보여야**: 저장되고, 카피 생성 · AI 광고 생성 화면에 그 값이 미리 골라져 있어야 해요. 사용방법 STEP 1이 그렇게 안내해요.
- **실제**
  - 저장 뒤 「🚨 아직 저장되지 않았어요. 광고 기본값을 담을 표가 아직 없어서 (팀장 승인 대기)…」가 뜸
  - 카피 생성 화면은 여전히 「화장품 · 성별 전체」
  - 같은 탭에 「⬜ 실제 판정 카테고리는 우리가 판별해요 — 사용자에게 묻지 않아요 (D-82)」라고 적혀 있는데, 검수 화면은 「이 제품은 어떤 유형인가요?」를 물어요(서로 모순)
- **원인**: 기본값을 저장할 DB 표가 없어요(`mypage.html` defaults 탭)
- **사용방법(03b)과 실제가 다른 곳**

  | 사용방법에 적힌 것 | 실제 |
  |---|---|
  | STEP 1 「나이 · 성별 · 매체 · 광고물품을 저장하면 자동으로 채워져요」 | 나이 칸이 없고 저장도 안 됨 |
  | STEP 2 ① 「상단 메뉴에서 검수」 | 검수는 왼쪽 메뉴에 있음 |
  | STEP 2 ② 「검수하기를 누르세요 · 카테고리와 광고 정보를 함께 입력」 | 버튼 이름은 「검수」 · 카테고리 입력 칸 없음 |
  | STEP 2 ⑤ 「이 문구로 질문하기」 | 그런 버튼 없음 |
  | STEP 3 ② ③ 「지향 키워드 생성 → 선택한 키워드로 카피 생성」 | 키워드 단계 없음 · 「이 내용으로 카피 생성」 한 번 |
  | STEP 4 「생성 이력에서 카피와 광고 결과 확인」 | 이력은 검수만 남음 · 생성 이력 없음 |
- **고칠 방향**: 표가 생기기 전까지 「저장」 버튼을 숨기거나 「준비 중」으로 표시하기. 사용방법을 지금 화면 기준으로 다시 쓰기.

### 04 🔴 동선 — AI 광고 생성에서 품목을 고르라는데 고를 칸이 없음

- **캡처**: `1015_04_동선_AI광고_품목선택필요인데_고를칸없음.png`
- **장면**: AI 광고 생성에 「하루 종일 촉촉한 보습 크림 / 아토피 피부도 진정시켜 줍니다」를 넣고 「판정 받고 템플릿 만들기」
- **원래 이렇게 보여야**: 「보류 · 품목 선택 필요」라면 품목을 고르는 칸이 있어야 해요(검수 화면처럼)
- **실제**: 「템플릿을 만들지 않았어요」 · 「보류 · 품목 선택 필요」만 뜨고 화면 어디에도 품목을 고를 곳이 없어요(라디오는 광고 종류 3개뿐). 문구를 고치는 것 말고는 진행할 방법이 없어요.
- **덧붙여**: 「⛔ 재검증이 확정이 아니라서 … 섹션이 빈 채로 남아요 (D-63)」라고 하는데 템플릿은 아예 안 만들어짐(문구가 결과와 다름)
- **원인**: AI 광고 생성 폼에 품목 입력이 없어요(10-14 시나리오 테스트 때 보고한 것과 같은 문제)
- **고칠 방향**: AI 광고 생성에도 품목 고르기를 넣거나, 카피 생성에서 넘어온 경우 그 품목을 이어받기

### 05 🟠 안내 — 대시보드 「최근 검수 이력」 빈 문구가 낡음

- **캡처**: `1015_05_안내_대시보드_빈이력_낡은문구.png`(가입 직후)
- **원래 이렇게 보여야**: 「아직 검수한 문구가 없어요. 이력을 남기려면 마이페이지 › 계정에서 ① 검수 이력 보관을 켜 주세요」처럼 지금 동작에 맞는 안내
- **실제**: 「검수 결과를 판정 이력으로 저장하는 기능이 붙으면 여기에 나와요. 지금은 각 화면 아래의 골든 픽스처로…」
- **원인**: `index.html` 108행 문구가 이력 저장 기능(10-13)을 붙이기 전 그대로예요
- **덧붙여**: 이력 보관 동의는 기본으로 꺼져 있어요. 가입 직후 검수하면 이력이 안 남는데, 이 사실은 검수 화면 아래 작은 글씨에만 나와요. 가입 화면은 「검수 · 카피생성 기록을 모아 볼 수 있어요」라고 하는데, 카피생성은 이력에 남지 않아요.

### 06 🟠 동선 — 비밀번호 찾기와 계정 끄기가 막다른 길

- **캡처**: `1015_06a_동선_비밀번호찾기_관리자문의.png` · `1015_06b_동선_고객센터_로그인필요.png` · `1015_06c_동선_계정끄기_팀에문의.png`
- **원래 이렇게 보여야**: 「관리자에게 문의」라면 연락 방법(메일 주소 등)이 있거나, 로그인 없이 쓸 수 있는 문의 창구가 있어야 해요
- **실제**
  - 비밀번호 찾기: 「서비스 관리자에게 문의해 주세요」 — 방법 없음
  - 고객센터: 「문의는 로그인한 회원만 접수할 수 있어요」
  - 계정 끄기: 「되돌리려면 팀에 문의해 주세요」 — 끈 계정은 로그인이 안 돼 고객센터를 못 씀
- **고칠 방향**: 연락용 메일 주소를 적거나, 로그인 전 문의 양식을 열기

### 07 🟠 오류 — 로그아웃 후 뒤로 가기를 누르면 개인 화면이 보임

- **캡처**: `1015_07_오류_로그아웃후_뒤로가기_개인화면.png`
- **장면**: 이력 화면에서 로그아웃 → 랜딩으로 이동 → 브라우저 「뒤로」
- **원래 이렇게 보여야**: 로그인 화면으로 가거나 「로그인이 필요해요」
- **실제**: 이름(점검계정) · 검수 이력 문구가 그대로 보여요(브라우저에 저장된 화면). 공용 PC에서 다음 사람이 볼 수 있어요.
- **원인**: 로그인 화면들에 `Cache-Control: no-store` 응답 헤더가 없어요(저장소 전체에 `no-store` 없음)
- **고칠 방향**: 로그인한 이용자에게 보내는 응답에 `Cache-Control: no-store` 붙이기
