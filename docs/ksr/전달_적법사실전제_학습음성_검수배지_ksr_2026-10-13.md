# 전달 — 「적법(사실 전제)」 학습 음성 · 검수 화면 배지 (2026-10-13 · ksr)

> 팀장 요청(10-13 오후) 세 가지 중 **1 · 3 번**의 변경 기록이다. 2 번(GPT 정상 문구 353 행 검수)은 저장소 밖에 있어 끝에 위치와 지문만 적는다.

## 핵심 요약

1. **학습 스크립트가 「적법」과 「적법(사실 전제)」를 둘 다 음성으로 읽는다.** 조건부 · 애매 표시 · 검수 전 행은 그대로 뺀다.
2. **검수본은 저장소 밖에 있다 — `--legit` 로 파일을 가리킨다.** 파일이 없으면 멈춘다.
3. **검수 화면 배지 — 인증 여부만 묻는 문구는 「인증 여부 선택 필요」다.** 그 밖의 분기 보류는 「유형 선택 필요」 그대로다.
4. 🚨 **학습은 돌리지 않았다.** 스크립트의 읽는 규칙만 바꿨다. D-330 은 아직 설계결정기록에 없어 요청 문구를 기준으로 맞췄다.

## 1. 학습 스크립트 — `docs/ksr/llm_copy/train_encoder_legit.py`

| 항목 | 종전 | 지금 |
|---|---|---|
| 음성으로 읽는 판독 값(`HUMAN_LEGIT`) | 「적법」 | 「적법」 · **「적법(사실 전제)」** |
| 빼는 행 | 검수 전 · 애매 표시 · 그 밖의 판독 | 그대로 (조건부 포함) |
| 검수본 위치 | 저장소의 판독용 파일 고정 | **`--legit 경로`** (기본값은 종전 경로) |
| 출력 | 더한 행 수 | 더한 행 수 + **판독별 수** |

실행 예 —

```bash
uv run python docs/ksr/llm_copy/train_encoder_legit.py --legit "<공유 드라이브에서 받은 900행 검수본.csv>"
```

### 1-1. 900 행 검수본에 새 규칙을 적용하면

검수본(sha256 `f3bfec90…` · 10-11 판)의 「판독(사람)」 · 「애매표시」 칸만 세었다.

| 묶음 | 행 | 학습 음성 |
|---|--:|:-:|
| 적법 | 505 | 예 |
| 적법(사실 전제) | 321 | **예 (이번에 추가)** |
| 조건부 | 28 | 아니오 |
| 애매 표시 | 46 | 아니오 |
| 합 | 900 | **826** |

- 「적법(사실 전제)」는 모두 348 행인데 그중 27 행에 애매 표시가 붙어 있어 321 행이 들어간다.
- 🚨 dev · 학습 문구와 글자가 겹치는 행은 스크립트가 더 뺀다. 그 수는 학습을 돌려야 나온다 — 돌리지 않았다.

## 2. 검수 화면 배지 — `app/templates/user/review.html`

| 분기 구성 | 화면이 묻는 것 | 배지(고르기 전) |

- 색(노랑) · 고른 뒤의 배지는 바꾸지 않았다.
- 시험 — `tests/test_user_screens.py` `test_검수_배지는_인증_여부만_물을_때_인증_여부_선택_필요다`. 픽스처 15(인증만) → 새 문구 · 03 · 21 → 종전 문구.
