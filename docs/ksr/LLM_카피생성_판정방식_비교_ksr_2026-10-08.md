### 3-3. ③ LLM 판정

- **두 모델 모두 위반 30개를 전부 잡았고, 대조 5개와 오늘 정상 353개는 하나도 걸지 않았다.** 인정 · 심사 문구 그 자체도 허용으로 봤다.
- 합성 정상 900개에서는 처음에 `gpt-5.6-luna` 가 79개, `gpt-6-luna` 가 114개를 걸었다. 사유를 읽어 보니 거의 전부 「제품 정보에 없는 수치」였다(예: 「400g 한 봉, 지퍼로 여닫기.」 — 제품 정보에 400g 이 없다).
  - 이것은 시험 설계 탓이다. 합성 900개에는 제품명 · 유형만 있고 용량 · 포장 정보를 주지 않았다. LLM 은 준 기준(「제품 정보에 없는 수치는 위반」)대로 건 것이다.
  - 그래서 걸린 문구만 「문구 속 용량 · 포장 · 원료는 제품 정보에 있는 사실」이라고 알려 주고 다시 물었다. **`gpt-5.6-luna` 는 79개 → 0개, `gpt-6-luna` 는 114개 → 2개**로 줄었다.
  - 남은 것(`gpt-6-luna`): 「끝에서부터 말아 올리면 남김없이 쓸 수 있어요」 — ‘남김없이’는 내용물을 전부 사용할 수 있다고 단정하는 표현입니다.
  - 남은 것(`gpt-6-luna`): 「바른 뒤 면양말을 신고 자면 이불에 묻지 않아요」 — 양말을 신고 자면 이불에 묻지 않는다고 보장하지만 이를 뒷받침하는 제품 정보가 없습니다.
  - 🚨 처음에 안 걸린 문구는 다시 묻지 않았다. 다시 물으면 걸릴 가능성은 낮다고 보지만 확인한 것은 아니다.
- 「입력에 없는 수치를 건다」는 것은 실제 흐름에서는 **맞는 동작**이다 — 코드 필터의 `number` 검사와 같은 일을 한다.

| 장점 | 단점 |
|---|---|
| 이 시험에서 위반을 전부 잡고 정상을 버리지 않았다 | GPT 호출이 든다 — 비용 · 시간 · 외부 전송 |
| 왜 위반인지 한 줄로 말해 준다 — 이용자에게 보여 줄 수 있다 | 같은 문구에 답이 달라질 수 있다(이번에는 한 번씩만 물었다) |
| 낱말이 바뀌어도 뜻을 읽는다(비방 · 「건강에 도움」) | 생성한 모델이 자기 문구를 봐주는 쪽으로 기울 수 있다 — 이번 시험으로는 가려지지 않는다 |
| 문장이 깨진 것도 짚는다(3-4) | 서비스 경로에서 GPT 를 쓰려면 팀장 판정(D-78 ②)이 필요하다 |

- 비용 — 문구 1,306개에 모델마다 70회 호출(20개씩 묶음). 토큰은 `gpt-5.6-luna` 입력 65,151 · 출력 72,783, `gpt-6-luna` 입력 65,151 · 출력 86,436. 문구 하나에 입력 50 · 출력 55~65 토큰쯤이다.
- 시간 — 재질문 때 `gpt-5.6-luna` 가 79개를 21초, `gpt-6-luna` 가 114개를 34초에 답했다(동시에 4개씩). 한 라운드 20개면 호출 한 번이다.

### 3-4. 덤 — 문장이 깨진 것을 잡나

LLM 에는 위반과 별개로 「문장이 깨졌거나 낱말이 틀려 그대로 쓰기 어려운가」도 답하게 했다. ① · ② 에는 이것을 보는 단계가 없다.

| | 문장이 깨진 10개 | 고정 문구가 이어진 8개 | 오늘 정상 353개 | 합성 900개 |
|---|:-:|:-:|:-:|:-:|
| `gpt-5.6-luna` | 9 짚음 | 1 짚음 | 3 잘못 짚음 | 1 잘못 짚음 |
| `gpt-6-luna` | 10 짚음 | 1 짚음 | 0 잘못 짚음 | 1 잘못 짚음 |

- 깨진 문장은 거의 다 짚는다. 「하루 한 알로 [인정 문구]」처럼 문법은 맞는데 뜻이 이어지는 8개는 거의 못 짚는다 — 이쪽은 앞선 문서 6-2 의 코드 필터(자리표시자 위치 검사)가 맡아야 한다.

## 4. 조합 — 무엇을 붙이면 무엇이 달라지나

| 붙인 것 | ① 대비 위반 | ① 대비 정상 | 읽는 법 |
|---|---|---|---|
| ① + ② 지금 문턱 | 놓침 3 → 0 | 버림 0 → 1,000 / 1,253 | 위반은 다 잡지만 쓸 문구가 안 남는다 |
| ① + ② 0.7~0.9 | 놓침 3 그대로 | 버림 0 → 10~304 | 놓친 3개는 인코더 확률이 0.55 안팎이라 문턱을 올리면 같이 놓친다. 얻는 것 없이 정상만 버린다 |
| ① + ③ | 놓침 3 → 0 | 버림 0 → 0~2 | ① 이 놓친 3개를 ③ 이 잡는다. 정상은 거의 안 버린다 |
| ① + ② + ③ (하나라도) | 놓침 0 | 버림 1,000 / 1,253 | ② 가 들어가는 순간 정상이 버려진다 |
| ① + (② ∧ ③) | 놓침 0 | 버림 0~2 | ① + ③ 과 수치가 같다 — 인코더가 한 일이 없다 |

- **③ 만 써도 위반 30개를 다 잡는다. 그래도 ① 을 앞에 두는 이유** — ① 은 GPT 호출 없이 먼저 걸러 ③ 에 보낼 문구를 줄이고, 매번 같은 결과를 내고, ③ 이 틀렸을 때의 두 번째 방어선이 된다.
- **두 모델을 다 쓸 필요는 없어 보인다.** 위반 · 대조 · 오늘 정상에서 두 모델의 답이 전부 같았다. 「둘 다 걸 때만」은 호출만 두 배다.
- **② 는 지금 판에서는 빼는 쪽이 낫다.** 다시 학습된 판이 오면 같은 시험으로 다시 잰다.

## 5. 한계

- **위반 문구 30개는 직접 쓴 뻔한 문구다.** 「당뇨를 예방」「국내 최고, 판매 1위」 같은 것이라 어떤 방식이든 잘 잡는다. 실제 광고의 미묘한 위반(돌려 말하기 · 암시 · 후기 형식)은 넣지 못했다. ③ 의 30 / 30 을 「위반을 다 잡는다」로 읽으면 안 된다.
- **정상 문구의 정답은 사람이 확정한 것이 아니다.** 오늘 353개는 정리 보조가 읽은 것이고, 합성 900개는 위반 요소 없이 쓰려고 한 것이다(애매 표시 46개 포함).
- **③ 은 한 번씩만 물었다.** 같은 문구를 다시 물으면 답이 달라질 수 있다. 얼마나 흔들리는지 재지 않았다.
- **생성한 모델과 판정한 모델이 같다.** 오늘 정상 353개는 이 두 모델이 만든 문구다. 자기 문구에 후한지는 다른 회사 모델로 판정해 봐야 안다.
- **① 의 수치는 유리하게 나왔을 수 있다.** 금지 낱말 목록이 이 위반 문구들을 본 뒤 다듬어졌을 수 있다.
- 합성 900개의 보정(3-3)은 걸린 문구만 다시 물은 것이다.
