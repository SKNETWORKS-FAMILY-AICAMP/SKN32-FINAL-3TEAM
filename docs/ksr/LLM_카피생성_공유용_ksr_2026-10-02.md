# LLM(GPT) 카피 생성 — 설계 요약 (공유용)

- 작성: 권소라(ksr) · 2026-10-02
- 상태: 기획 초안. 저장소에는 올리지 않았다.
- 한 줄 요약: **GPT 로 후보를 많이 뽑고, 코드와 판정엔진으로 걸러, 남은 것 3개만 보여 준다.**

---

## 1. 왜 하나

1. 규칙 조립만으로는 문구가 딱딱하고 틀이 반복된다.
2. GPT 로 말투가 부드럽고 다양한 후보를 만든다.
3. 창의성은 **후보 단계에서만** 허용한다. 이용자에게 나가는 문구는 전부 걸러진 것뿐이다.

## 2. 이용자가 하는 일

1. **분기를 고른다** — 품목(식품 / 건강기능식품 / 화장품) + 인증·기능 여부(예 / 아니오).
2. **제품 내용을 입력한다** — 분기에 맞는 칸만 보인다. 여기 적힌 것이 「제품 사실」의 전부다.
3. **후보 3개를 받는다.**

이 아래(3~5번)는 내부 파이프라인이고 이용자에게 보이지 않는다.

## 3. 내부 흐름

1. GPT 가 후보 **20개**를 만든다 (1회 호출).
2. **코드 필터**가 판정 전에 거른다 (4번).
3. **판정엔진**이 남은 후보를 분기 기준으로 한 문장씩 판정한다. 팀장님 판정 코어를 그대로 쓴다.
4. 통과한 문구는 **보관**한다.
5. 보관분이 **3개 이상이면** 서로 가장 다른 3개를 골라 출력하고 끝낸다.
6. **3개 미만이면** 보관분과 겹치지 않는 20개를 새로 만들어 1~5 를 반복한다.
7. 자동 반복은 **3회(최대 60 후보)** 까지다.

## 4. 코드 필터 — 판정 전에 거르는 것

판정엔진은 법 위반만 본다. **입력에 없는 사실을 지어낸 문장**은 위반이 아니라서 엔진이 못 잡는다. 그래서 코드가 먼저 거른다.

| # | 검사 | 탈락 조건 |
|:-:|---|---|
| 1 | 형식 · 중복 | 길이 범위 밖 · 보관분이나 이전 후보와 거의 같음 |
| 2 | 수치 | 후보의 숫자(%, 배, 시간, mg 등)가 입력에 없음 |
| 3 | 인증·시험 | 「인증 · 특허 · 임상 · 테스트 완료」 등이 입력에 없음 |
| 4 | 성분 | 입력에 없는 성분 이름이 나옴 |
| 5 | 비교·최상급 | 최고 · 유일 · 1위 · 타사 대비 |
| 6 | 분기별 금지어 | 판정 사전 + 분기 규칙의 금지 낱말 |
| 7 | 고정 문구 | 인정·심사 문구가 변형되거나 빠짐 |

예시 — 화장품 · 인증 아니오 · 입력: 「촉촉 수분크림」 · 크림 · 「끈적임 없이 산뜻」 · 히알루론산

| 후보 | 결과 |
|---|---|
| 끈적임 없이 산뜻하게 스며드는 촉촉 수분크림 | 판정으로 넘김 |
| 히알루론산 5% 함유, 72시간 보습 | 탈락 — 수치가 입력에 없다 |
| 세라마이드가 피부 장벽을 채워 줍니다 | 탈락 — 성분이 입력에 없다 |
| 피부과 테스트를 마친 순한 크림 | 탈락 — 시험 사실이 입력에 없다 |
| 지친 피부를 재생시키는 수분크림 | 탈락 — 금지어 「재생」 |

## 5. 다시 만들 때의 규칙

1. 보관한 통과 문구는 그대로 두고 **부족분만** 새로 만든다.
2. 프롬프트에 「보관 문구와 겹치지 않게」를 넣는다.
3. 탈락 정보는 **사유 유형과 건수만** 넘긴다 (예: 「입력에 없는 수치 6건 · 금지어 2건」).
4. **탈락 문구 원문은 넘기지 않는다** — 넣으면 그 표현이 생성에 영향을 준다.

## 6. 3개를 못 채웠을 때

1. 3회 안에 못 채우면 **탐색 실패**로 끝낸다. 기준을 낮추거나 억지로 채우지 않는다.
2. 찾은 것은 그대로 보여 주고 선택지를 준다.

   ```
   3개 중 n개를 찾았습니다.
   [더 탐색하기]   [이대로 쓰기]   [입력 고치기]
   ```

3. **더 탐색하기** — 보관분을 들고 3회를 한 번 더 돈다. 누를 수 있는 횟수는 미정이다.
4. **0개일 때**는 「입력 고치기」를 앞에 둔다 — 입력이 분기 규칙과 부딪혔을 가능성이 크다. 탈락 사유 상위 몇 가지를 같이 보여 준다.

## 7. 분기별 규칙

| # | 분기 | 규칙 |
|:-:|---|---|
| 1 | 식품 · 인증 아니오 | 기능성·효능 표현 금지 · 질병 표현 금지 |
| 2 | 식품 · 인증 예 (HACCP 등) | 1번 + 인증 **사실만** 언급. 인증은 효능을 열어 주지 않는다 |
| 3 | 건기식 · 인증 예 (기능성 인정) | 인정 기능성 문구는 **글자 그대로**. 그 외 효능 금지 |
| 4 | 건기식 · 인증 아니오 | 「일반식품으로 생성합니다」 안내 후 1번으로 진행 |
| 5 | 화장품 · 인증 아니오 (일반) | 의약품 오인 금지(치료·재생 등) · 기능성 효능 금지(미백·주름·자외선 등) |
| 6 | 화장품 · 인증 예 (기능성 심사·보고) | 심사·보고된 효능 범위만. 치료·의약품 표현은 여전히 불가 |

## 8. 프롬프트 원칙

1. **금지 목록보다 허용 범위를 먼저 준다** — 분기마다 「쓸 수 있는 것」을 적는다.
2. **각도를 지정해서 뽑는다** — 사용 장면 · 감각 · 원료 이야기 등 각도별로 몇 개씩.
3. **고정 문구는 GPT 가 쓰지 않는다** — 인정·심사 문구는 자리표시자로 받고 코드가 끼운다.
4. **「광고」 표시와 필수 병기는 코드가 붙인다.**
5. 분기별로 좋은 예 · 나쁜 예(이유 포함)를 넣는다. 예시는 직접 쓴 것만 쓴다.

## 9. 알아 둘 한계

1. **「통과」는 「위반을 못 찾았다」는 뜻이다.** 판정엔진은 자기가 아는 표현만 잡는다.
2. **화장품은 판정 사전이 비어 있다.** 사전 547 항목 중 화장품법 근거가 0건이고, 화장품 단골 낱말 41개 중 19개가 없다.
3. 그래서 화장품 분기는 **프롬프트와 코드 필터가 실질 방어선**이다.
4. 화면에는 「검수 통과」가 아니라 **「후보」** 로 낸다.

## 10. 아직 안 된 것

1. 판정엔진을 문장 단위로 부르는 배선 — 생성 그래프의 해당 노드가 아직 비어 있다 (팀장님 일정).
2. 「더 탐색」 횟수 상한 — 상의해서 정한다.
3. GPT 모델 선택 — 2~3개로 같은 입력을 돌려 보고 고른다.
4. 화장품 지침의 판정 사전 편입 — 팀장님께 요청 예정.
5. 프롬프트 평가용 시험 입력 — 분기별 5~10개.
