### ② 게시판형 4종 수집 — 방식이 (나)로 정해지면

1. **STATUS 를 `manual` 로** — `register` 는 `hold` 를 거부하고 `manual` 은 통과시킨다(`collect/registry.py` `require()`).
   `scripts/gen_registry.py` 의 STATUS 에서 네 줄을 `"manual"` 로 바꾸고 주석에 팀장 판정 날짜를 적는다.
   ```bash

   uv run python scripts/extract_rationale.py
   uv run pytest -m gate
   ```
2. **대상 글 받기** — [수집대상_목록_2026-09-27.md](수집대상_목록_2026-09-27.md) 의 글만. 소스마다 폴더 하나에 모은다(하위 폴더 금지 — `register` 가 거부한다 · D-254).
   - `ftc_press` 77건 — 본문 HTML + 첨부(hwp·pdf). robots 는 `/www/search.do*` 만 금지.
   - `gg_press` 12건 — 🚨 **요청 사이 4초 이상**(반복 요청 시 「보안 정책에 의해 차단」 화면이 뜬다). 사진(JPG)은 받지 않는다.
   - `scourt_major` 12건 — 상세가 POST 폼(`fn_view(seqnum, 법원코드)`)이라 목록의 seqnum·법원코드로 연다. www 만(각급법원 도메인은 robots 금지). EUC-KR.
   - `easylaw_ad` 1건 — 텍스트만(사진·제3자 저작물은 정책상 제외).
   - 받은 파일은 **레포 밖 임시 폴더**에 둔다(예: `%USERPROFILE%\Downloads\copylane_tmp\<소스id>\`). `data/raw` 에 직접 넣지 않는다 — `register` 가 옮긴다.
3. **등록 → 업로드 → 원장 push**
   ```bash
   uv run python -m collect.ingest count <폴더>
   uv run python launcher.py register ftc_press <폴더> --use U1
   uv run python launcher.py raw-publish --dry-run
   uv run python launcher.py raw-publish
   git add data/manifest.jsonl scripts/registry_review.yaml
   git commit -m "수집 — 게시판형 4종"
   git push origin ksr
   ```
   (나머지 셋도 `register` 를 같은 꼴로. `collected_at` 은 `registry_review.yaml` 에 자동으로 찍힌다 — 칸은 이미 있다.)

   방식이 **(가)** 면 — `collect/` 에 수집기를 새로 쓰고 `collect/__init__.py` 의 `COLLECTORS` 에 넣은 뒤 STATUS 를 `collect` 로. 전처리·수집기 설계는 팀장 확인 후.
