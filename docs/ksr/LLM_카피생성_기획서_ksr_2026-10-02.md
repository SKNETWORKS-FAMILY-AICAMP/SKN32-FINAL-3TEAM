# LLM(GPT) 카피 생성 — 후보 다수 생성 → 내부 판정 → 통과분 출력 · 기획서

- **작성**: ksr (2026-10-02) · 초안 보조: Claude Code
- **상태**: 🟡 기획 초안 — 로컬 보관(저장소 미커밋). §8 「확인할 것」이 닫히면 구현한다.
- **위치**: 진입점 B(카피 생성)의 「제로베이스 생성」 경로. 판정은 **팀장 판정 코어를 그대로** 쓴다 (D-119 · 판정 코어는 하나).

---

## 1. 목적

- 규칙 조립만으로는 문구가 딱딱하고 틀이 반복된다 → **GPT 로 말투가 부드럽고 창의적인 후보**를 만든다.
- 🔴 창의성은 **후보 단계에서만** 허용한다. **나가는 문구는 전부 내부 판정 엔진을 통과한 것**뿐이다.
- 「LLM 이 지켰겠지」를 믿지 않는다 — **프롬프트로 막고, 코드로 거르고, 판정 엔진으로 확인**한다(3중).

## 2. 확정한 값

| 항목 | 값 | 비고 |
|---|---|---|
| 최종 출력 개수 N | **3** | `PARAMS.candidate_n` 과 같다 (D-34) |
| 1회 생성 후보 수 | **20** | GPT 1회 호출 = 후보 20개 |
| 자동 생성 상한 | **3회** (최대 60 후보) | ✅ 확정 — 팀 기본값과 같다 (`max_attempt=2` · D-126). 그 이상은 이용자가 버튼으로 고른다 |
| 「더 탐색」 횟수 상한 | ⬜ **미정** | 상의해서 정한다 — §5 · §8-2 |
| 부족 시 | **탐색 실패 + 「더 탐색」 선택지** | `GenerateOutcome.search_failed` — §5 |
| LLM | **GPT API** | 모델은 §8-4 |
| 판정 엔진 | **팀장 판정 코어** | 새로 만들지 않는다 |

## 3. 입력 — 분기 버튼 → 입력창

```
[카테고리]  화장품 / 식품 / 건강기능식품
[인증]      예 / 아니오
      ↓
[입력창]    분기에 맞는 칸만 보인다
```

| 분기 | 입력 칸(안) | 생성 규칙(고정) |
|---|---|---|
| **식품 · 인증 N** | 제품명 · 원재료 · 제품 특징(맛·식감·용도) · 톤 | 기능성·효능 표현 금지(건기식 오인) · 질병 금지 |
| **식품 · 인증 Y** | 위 + 인증 종류(HACCP·유기농 등) · 인증번호 | 위 + 인증은 **입력된 것만** 정확한 명칭으로 |
| **건기식 · 인증 Y** | 제품명 · **인정 기능성 문구(원문)** · 기능성 원료 · 섭취 시 주의사항 · 톤 | 🔴 인정 기능성 문구는 **글자 그대로** — 말투 다듬기 대상이 아니다 · 그 외 효능 추가 금지 |
| **건기식 · 인증 N** | (식품 · 인증 N 과 같음) | ✅ **확정** — 기능성 인정 없이 건기식으로 광고할 수 없다. 「건강기능식품 인정이 없어 **일반식품으로 생성합니다**」를 안내하고 **식품 분기로 진행**한다 |
| **화장품 · 인증 N** (일반) | 제품명 · 제형 · 사용감 · 성분(전성분 중 강조할 것) · 톤 | 의약품 오인 금지(치료·재생·세포·염증 등) · 기능성 효능(미백·주름·자외선 등) 금지 |
| **화장품 · 인증 Y** (기능성) | 위 + **심사·보고된 기능성 문구** | 위 + 기능성은 **심사받은 범위만** |

- 🔴 입력창에 적힌 것이 **「제품 사실」의 전부**다 — 주장 원장(D-30)의 기준이 된다. 여기 없는 사실은 문구에 나올 수 없다.
- 「인증」이 카테고리마다 뜻이 다르다 — 버튼 라벨에 풀어 쓴다.

  | 카테고리 | 「인증 Y」의 뜻 | 무엇을 보증하나 | 문구에 쓸 수 있는 것 |
  |---|---|---|---|
  | 식품 | HACCP 등 (유기농·전통식품 품질인증 등 포함) | **제조 공정의 위생·안전** · 효능 아님 | 인증 사실(정확한 명칭)만. 「HACCP 이라 몸에 좋다」처럼 효능으로 잇지 않는다 |
  | 건기식 | 식약처 **기능성 인정** (고시형 원료 / 개별인정형) | **원료의 기능성** | 인정받은 기능성 문구 **원문 그대로**만 |
  | 화장품 | **기능성화장품 심사·보고** (화장품법 제4조 · 미백·주름·자외선 등) | **제품의 특정 효능** | 심사·보고된 효능 범위만. 그래도 치료·의약품 표현은 불가 |

  🔴 식품의 「인증 Y」는 **효능을 하나도 열어 주지 않는다** — 분기 규칙은 「인증 사실을 언급할 수 있다」만 더한다.
  🔴 건기식 광고는 생성과 별개로 **자율심의**를 거쳐야 한다 — 결과 화면 고지에 넣는다.

```

   │
   ▼
┌─ 라운드 r (1 ~ 3) ─────────────────────────────────────────────┐
│ ① GPT 생성: 후보 20개 (JSON 배열 · structured outputs 로 강제)     │
│      r ≥ 2 이면 프롬프트에 추가:                                    │
│        · 이미 통과한 문구 → "이것들과 겹치지 않게"                    │
│        · 탈락 사유 유형·건수만 (문구 원문은 넘기지 않는다 · §4-1)      │
│ ② 코드 필터 (판정 전 · 싸고 빠름)                                   │
│      · 형식 · 길이 · 중복(이전 라운드 포함)                          │
│      · 분기별 금지어 (§3 고정 규칙 · 사전 정확매칭 재사용)              │
│      · 주장 원장: 제품 사실에 없는 수치·%·인증·성분·비교 → 탈락 (D-30)  │
│ ③ 판정 코어: 남은 후보를 한 문장씩 판정                               │
│      · 통과 = 확정 ∧ R0 만 (D-125) — 보류·근거없음·미판정은 탈락       │
│ ④ 통과 누적 ≥ 3 ?  ── 예 ──► 출력(3개) · 종착                        │
│                    └─ 아니오 ─► 다음 라운드 (통과분은 그대로 둔다)      │
└──────────────────────────────────────────────────────────────────┘
   │ 3회 소진 · 통과 < 3
   ▼
탐색 실패 (search_failed) — 「n개 찾았습니다」 + [더 탐색] 버튼 — §5
   │ 버튼을 누르면 통과분을 들고 라운드 묶음(3회)을 한 번 더 돈다
```

### 4-1. ② 코드 필터 — 무엇을 어떻게 거르나

판정 코어는 **법 위반**을 본다. **지어낸 사실**(입력에 없는 수치·인증·성분)은 위반이 아니라서 코어가 못 잡는다 → 판정 전에 코드가 거른다.
생성 그래프의 `claim_ledger` 노드(`신규주장 = 생성주장 − (제품사실 ∪ 입력주장)` · D-30)가 이 자리다.

🔴 원칙 — **의심스러우면 탈락.** 생성은 오탐 손해가 없다(다시 뽑으면 된다). 검사는 전부 결정적(정규식·목록 대조)이고 탈락마다 **사유 코드**를 남긴다.

| # | 검사 | 방법 | 사유 코드 |
|:-:|---|---|---|
| a | 형식 | 빈 문장 · 길이 범위 밖 · JSON 깨짐 | `format` |
| b | 중복 | 공백·문장부호를 접어 비교 — 통과분·이전 라운드 후보와 같거나 거의 같음 | `duplicate` |
| c | 수치 | 후보에서 숫자+단위(`%` · 배 · 시간 · 일 · mg · 위 …)를 뽑아 **입력에 같은 값이 없으면** 탈락 | `new_number` |
| d | 인증·시험 | 고정 목록(인증 · 특허 · 임상 · 테스트 완료 · 식약처 · 수상 · HACCP …)이 후보에 있는데 입력에 없음 | `new_cert` |
| e | 성분 | 성분 사전(`data/derived/cosmetic_ingredient.jsonl` 등)에 있는 이름이 후보에 나오는데 입력 성분 칸에 없음 | `new_ingredient` |
| f | 비교·최상급 | 최고 · 유일 · 1위 · 타사 · 대비 · 「보다 더」 | `comparison` |
| g | 분기별 금지어 | 판정 사전 547 + §3 분기 규칙 낱말(화장품은 지침 [별표 1] 에서 — §9) | `banned_term` |
| h | 고정 문구 | 인정·심사 문구 자리표시자가 정확히 한 번 있고 변형되지 않음 | `fixed_phrase` |

**예시** — 화장품 · 인증 N · 입력 = 제품명 「촉촉 수분크림」 · 제형 크림 · 사용감 「끈적임 없이 산뜻」 · 성분 「히알루론산」

| 후보 | 결과 | 사유 |
|---|---|---|
| 끈적임 없이 산뜻하게 스며드는 촉촉 수분크림 | ✅ 판정으로 | — |
| 히알루론산 5% 함유, 72시간 보습 | ❌ | `new_number` — 5% · 72시간이 입력에 없다 |
| 세라마이드가 피부 장벽을 채워 줍니다 | ❌ | `new_ingredient` — 세라마이드가 입력에 없다 |
| 피부과 테스트를 마친 순한 크림 | ❌ | `new_cert` — 시험 사실이 입력에 없다 |
| 타사 대비 2배 촉촉한 수분크림 | ❌ | `comparison` · `new_number` |
| 지친 피부를 재생시키는 수분크림 | ❌ | `banned_term` — 「재생」(화장품 분기 금지어) |

- 한계 — 표면 형태만 본다. 숫자·목록에 안 걸리는 **말로 풀어 쓴 새 주장**(「오래도록 촉촉」 등)은 지나간다. 이것은 프롬프트(§6)와 판정 코어의 몫이다.
- 탈락 사유 코드의 **유형·건수**만 다음 라운드 프롬프트에 넘긴다(탈락 문구 원문은 넘기지 않는다 — 같은 표현이 변형돼 돌아온다).

- **통과가 3개를 넘으면** — 판정 순서대로 자르지 않고 **서로 가장 다른 3개**를 고른다(틀 다양성). 선택 방법은 §8-5.
- **창의성 설정** — 생성 `temperature` 는 높게(예: 0.9 안팎). 걸러내는 장치가 뒤에 있으므로 생성은 넓게 뿌린다.
- **모든 후보를 기록한다** — 라운드 · 원문 · 탈락 단계(②/③) · 탈락 사유 · 판정 결과. 재생성 프롬프트와 나중의 분석이 이것을 쓴다.

## 5. 탐색 실패 정책 — 끝은 실패, 이어 갈지는 이용자가 고른다

- 자동으로는 **3회(60 후보)** 까지만 돈다. 그 안에 통과 3개를 못 채우면 **탐색 실패**(`search_failed`)로 끝낸다. 기준을 낮추거나 억지로 채우지 않는다 (D-59 · D-125).
  - ⛔ 종전 초안의 「보류(`hold`)」가 아니다 — `hold` 는 재판정이 보류·근거없음을 남긴 경우의 종착이다 (`app/graph.py` `route_after_rejudge`).
- 실패 화면에 **찾은 것을 그대로 보여 주고 선택지를 준다.**

  ```
  3개 중 n개를 찾았습니다.            (n = 0 ~ 2 · 찾은 문구를 보여 준다)
  [더 탐색하기]   [이대로 쓰기]   [입력 고치기]
  ```

  - **더 탐색하기** — 통과분은 그대로 들고 라운드 묶음(3회)을 한 번 더 돈다. 「통과분과 겹치지 않게」는 같다.
  - **n = 0** 이면 「더 탐색」보다 **「입력 고치기」를 앞에** 둔다 — 60개가 전부 탈락했으면 입력 자체가 분기 규칙과 부딪혔을 가능성이 크다(예: 일반식품에 효능을 요청). 탈락 사유 상위 몇 가지를 같이 보인다.
- 실패에는 반드시 사유를 붙인다 — 예: 「3회 · 60 후보 중 통과 2」 + 탈락 사유(코드 필터 사유 코드 · 판정 사유) 상위 몇 가지.
- ⬜ 정할 것 — 「더 탐색」을 **몇 번까지** 누를 수 있게 하나(비용 상한) · 버튼 한 번을 DB 에 어떻게 적나(§8-1).

## 6. 프롬프트 골격 (GPT)

**system**
1. 역할 — 한국 광고 카피라이터. 부드럽고 자연스러운 말투, 서로 다른 각도의 후보.
2. **절대 규칙** — 입력된 제품 사실만 쓴다 · 새 효능·수치·인증·성분·비교 금지 · 질병·의약품 어휘 금지 · 최상급·절대 표현 금지 · 경쟁사 비교·비방 금지 · 체험담 형식 금지.
3. **분기 규칙** — §3 표의 해당 행을 그대로 넣는다(분기마다 프롬프트가 다르다).
4. **인정·심사 문구** — 있으면 글자 그대로 포함하고 손대지 않는다.
5. 출력 — `{"candidates": [{"body": "...", "angle": "어떤 각도로 썼나"}, ...]}` 20개.

**user** — 분기 + 입력창 내용 (+ r ≥ 2 이면 통과 문구 · 탈락 사유 유형과 건수 — 탈락 문구 원문은 넣지 않는다).

- 「광고」 표시 · 필수 병기(건기식 주의사항 등)는 **GPT 에 맡기지 않는다** — 코드가 출력 뒤에 붙인다 (README 진입점 C 「구조적으로 빠질 수 없다」 취지).

## 7. 비용 · 시간 (감)

- GPT — 자동 최대 3회 호출(라운드당 1회) · 「더 탐색」 한 번마다 최대 3회 추가. 출력 토큰이 후보 20개분이라 호출당 수백~천여 토큰. 모델 가격은 **실행 직전 확인**.
- 판정 코어 — 자동 최대 60 문장. ②코드 필터가 판정 전에 최대한 걸러야 한다. 1문장 판정 시간은 **실측 후** 상한을 다시 본다.
- 1회 요청에 최악 3라운드 대기 → 라운드 진행 상황을 화면에 보여 줄지 §8-6.

## 8. 확인할 것 ⬜

| # | 질문 | 왜 | 누구와 |

## 9. 알려진 문제 — 「통과」는 「위반을 못 찾았다」는 뜻이다

- 계약상 **통과 = 확정 ∧ R0 = 확정 ∧ 위반 없음** 이다 (D-273 · `app/contracts.py`). 판정 코어는 **자기가 아는 표현**만 위반으로 잡는다 → 통과는 「적법이 확인됐다」가 아니라 **「아는 위반에 안 걸렸다」** 다.
- 🔴 **화장품 분기는 사전이 비어 있다** (2026-10-02 실측 · `banned_terms.jsonl` 547 항목).
  - 근거 법 — 표시광고법 334 · 식품표시광고법 214 · **화장품법 0**.
  - 사전 원천은 공정위 의결서 · 식약처 식품 부당광고 사례집뿐이다. 화장품 지침(`mfds_cosmetic_ad_guideline`) · 2013 별표 · 질의응답집은 원천에 없다(`preprocess/dictionary.py`).
  - 화장품 단골 낱말 41개 중 **19개가 사전에 아예 없다** — 소염 · 진정 · 치유 · 여드름 · 상처 · 흉터 · 발모 · 양모 · 습진 / 화이트닝 · SPF · 기미 · 주근깨 · 잡티 · 튼살 / 유기농 · 무첨가 · 안티에이징 · 줄기세포.
  - 있는 것도 식품 사례에서 온 긴 구절(「피부미백」 · 「주름방지」 · 「먹는자외선차단제」)이거나 단독 판정을 못 하는 항목(「염증」 · 「항염」 = 비주장문맥)이다.
- **결과** — 화장품에서는 「3중 방어」 중 판정 코어가 사실상 서 있지 않다. **프롬프트와 코드 필터 둘이 실질 방어선**이다. 통과가 쉽게 나오는 만큼 통과의 의미가 약하다.
- **대응**
  1. 화장품 분기의 금지어·허용 범위는 지침 [별표 1] 에서 직접 가져와 프롬프트(§6)와 코드 필터 g(§4-1)에 넣는다. 단 판정 사전과 기준이 두 벌이 되므로(D-99) **임시**다 — 지침이 사전에 편입되면 사전을 읽는 쪽으로 돌린다 (§8-10).
  2. 화면에는 「검수 통과」가 아니라 **「후보」** 로 낸다 — 생성의 종착은 증명서가 아니다 (D-59 · `frontier` 취지).
  3. 화장품 분기 결과에는 「화장품법 기준 검수는 제한적」임을 고지한다 — 안 본 것을 본 것처럼 말하지 않는다 (D-63).
- ⬜ 식품·건기식도 같은 성질이다(사전에 없는 새 표현은 지나간다). 화장품만큼 비어 있지는 않을 뿐이다 — §8-9 실측으로 정도를 본다.

## 10. 이 문서가 안 정하는 것

- 규칙 조립(기존 문구 교정 · D-264) 경로 — 그대로 둔다. 이 문서는 **새로 쓰는** 경로만 다룬다.
- sLLM(LoRA) 채택 여부 — 별도.
- 판정 기준 자체 — 판정 코어의 몫이다. 여기서는 「확정 ∧ R0 만 통과」라는 **읽는 법**만 정한다.
