## 1. 아키텍처

```
                    인터넷
                      │  🚨 80 · 443 만 열린다
                      ▼
            ┌───────────────────┐
            │      Caddy        │  Let's Encrypt 자동 발급·갱신
            └─────────┬─────────┘
                      │  Docker 내부 네트워크
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
  ┌──────────┐  ┌──────────┐  ┌──────────┐
  │ api:8000 │  │ 추론      │  │ postgres │  🚨 호스트 포트 미노출
  │ FastAPI  │  │ ONNX CPU │  │ +pgvector│     (컨테이너 네트워크만)
  └──────────┘  └──────────┘  └──────────┘

  ┌──────────────────────────────────────┐
  │ admin:8001 (SQLAdmin)                │  🚨 127.0.0.1 에만 바인딩
  │ → MobaXterm SSH 터널로만 접근         │     P2-10
  └──────────────────────────────────────┘
```

### 노출 경계 — 이것이 보안의 전부다

| 대상 | 노출 | 근거 |
|---|:-:|---|
| Caddy 80 · 443 | 🌐 공개 | 유일한 공개 진입점 |
| `api:8000` | 내부만 | Caddy 뒤 |
| `postgres:5432` | 🚨 **호스트 포트 매핑 없음** | **P3-14.** 보안 그룹에 5432를 여는 것이 사고 1위 |
| `admin:8001` | 🚨 **`127.0.0.1` 바인딩** | **P2-10 — 포트 분리는 보안 경계가 아니다.** SSH 터널로만 |
| SSH 22 | 접속 IP 제한 | 키 인증만 · 비밀번호 인증 차단 |

🚨 **NAT Gateway를 만들지 않습니다.** 월 $32.4가 아무것도 하지 않고 나갑니다. **퍼블릭 서브넷에 인스턴스를 직접 둡니다** — 단일 인스턴스 데모에 프라이빗 서브넷은 과잉입니다.

### 🔄 1-3. 확장 — 관리형(ECS Fargate)을 쓰지 않는 이유 (D-79 ⑦)

> 팀장이 강사 정기 미팅(8/31)에서 **대규모 트래픽 대응**을 질의했고, **ECS Fargate**(오토스케일링·배포 편의성)를 권유받았다.
> 🚨 **결론은 「기각」이 아니라 「조건부 보류」다.** 상세 근거는 **D-79 ⑦**.

- 🚨 **비용은 근거가 아니다** — 4 vCPU·16GB 기준 **m7i.xlarge $0.2478/hr** vs **Fargate 약 $0.233/hr** 로 거의 같다.
- **실무 기준으로는 Fargate 가 맞다.** 단일 EC2 + Compose 는 **SPOF · 무중단 배포 불가 · 스케일 불가**다.
- **그럼에도 지금 하지 않는 이유** — 전부 이 프로젝트의 제약이지 Fargate 의 결함이 아니다.

  | # | 이유 |
  |:-:|---|
  | 1 | 모델 가중치가 **수 GB** → 태스크 기동마다 이미지 pull → **스케일아웃에 수 분** |
  | 2 | postgres 를 Fargate 에 둘 수 없다 → **RDS·ALB·ECR·IAM** 으로 구성요소가 늘고, 배포는 9W 인데 **배포 전담이 없다** |
  | 3 | 🚨 **오토스케일링이 발동할 트래픽이 없다** — 데모 대상은 심사위원 몇 명이다 |

- **★ 그래서 답은 「구현」이 아니라 「측정」이다.**
  > **"오토스케일링을 붙였습니다"보다 "우리 병목이 어디고 어떻게 늘리는지 압니다"가 강하다.**
  > 앞은 누구나 하고, 뒤는 **잰 사람만** 한다.

  이 문서의 아키텍처가 이미 **api 와 추론을 분리**해 두었으므로 확장 축은 설계에 있다 —
  *"단일 인스턴스에서 N rps, 병목은 추론. api 는 무상태라 수평 확장이 자유롭고 추론만 태스크를 늘린다."*

- **이행 경로 — 셋 중 둘은 이미 충족돼 있다**

  | # | 조건 | 상태 |
  |:-:|---|:-:|
  | 1 | `DATABASE_URL` 주입만으로 RDS 전환 | ✅ `.env.example` 이 이미 그 형태 |
  | 2 | 컨테이너에 상태를 두지 않는다 | ✅ |
  | 3 | **부하 테스트 1회** — 단일 인스턴스 처리량 확보 | ❌ **W2 실측에 포함** |

- 🚨 **RDS 는 PostgreSQL 이다. MySQL 이 아니다** (D-95) — pgvector 가 PostgreSQL 확장이기 때문이며,
  **RDS for PostgreSQL 은 pgvector 를 정식 지원**한다(v0.5.0 HNSW ~ v0.8.0).
  배포 시 **파라미터 그룹에서 `CREATE EXTENSION vector` 허용 여부만 한 번 확인**한다.

## 3. MobaXterm 사용

### 3-1. 세션 설정

```
Session → SSH
  Remote host : <도메인 또는 EIP>
  Username    : ubuntu
  Advanced SSH settings → Use private key : <키파일>.pem
```

- 🚨 **`.pem`을 저장소 폴더 안에 두지 않습니다** (P0-2). `C:\SKN32_Final_project` 밖에 둡니다
- 🚨 **MobaXterm에 Master Password를 설정합니다** — `Settings → General`. 세션 자격증명이 **Windows 로컬에 저장**되므로, 설정하지 않으면 PC를 여는 사람이 서버를 엽니다
- 🚨 **`.pem` 한 장을 카톡으로 돌리지 않습니다.** 팀원 각자가 자기 키를 만들고 **공개키만** `~/.ssh/authorized_keys`에 등록합니다 — 누가 접속했는지 구분되고, 한 명이 빠져도 키 하나만 지우면 됩니다 (고시 제5조 접근권한 관리)

### 3-2. ★ 터널링 — P2-10의 해법이 정확히 이것입니다

관리자 콘솔(SQLAdmin)을 **인터넷에 열지 않고** 쓰는 방법입니다.

```
MobaXterm → Tunneling → New SSH tunnel → Local port forwarding

  [내 PC]  127.0.0.1 : 18001
      ↓  (SSH 암호화 터널)
  [SSH 서버]  <도메인> : 22   user: ubuntu
      ↓
  [원격]  127.0.0.1 : 8001   ← admin 컨테이너
```

터널을 켜고 브라우저에서 **`http://127.0.0.1:18001`** 로 접속합니다.
★ **관리자 화면은 공인 IP를 갖지 않습니다.** 포트 스캔에도 안 보이고, 보안 그룹에 구멍을 뚫지 않습니다.

같은 방식으로 DB 디버깅용 터널도 만듭니다 — `15432 → 127.0.0.1:5432`. **5432를 보안 그룹에 여는 일이 영영 없습니다.**

### 3-3. 파일 전송

- 좌측 **SFTP 패널**로 드래그 앤 드롭. `.env` 같은 작은 파일에 적합
- 🚨 **모델 가중치는 SFTP로 올리지 않습니다** — 내 PC 업로드 대역이 병목입니다. **서버에서 직접 받는 것**이 훨씬 빠릅니다 (§4 Phase 3)
- **MobaTextEditor**로 원격 `.env`를 직접 작성합니다 — ★ **로컬에 사본이 남지 않습니다**

### 3-4. 🚨 tmux — 선택이 아닙니다

```bash
tmux new -s deploy      # 작업 시작
# Ctrl+b, d 로 분리
tmux attach -t deploy   # 재접속
```

**MobaXterm 연결이 끊기면 `docker compose build`가 같이 죽습니다.** 이미지 빌드는 몇 분씩 걸리고, 무선 환경에서 한 번은 반드시 끊깁니다.

Caddy가 Let's Encrypt 인증서를 **자동 발급·자동 갱신**합니다. 갱신을 잊어서 발표 당일 만료되는 사고가 구조적으로 없습니다.

- [ ] `https://` 접속 확인 · HTTP → HTTPS 자동 전환 확인
