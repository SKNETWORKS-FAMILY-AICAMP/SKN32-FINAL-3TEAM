## 문제

> *"종아리 독소 · 붓기 · 지방, 한 번에 해결!"*
> *"모근이 강화되어 머리가 빠지지 않습니다!"*

이 한 줄이 위법인지는 **조문을 찾아봐야** 압니다. 그런데 현장에서 그 일을 하는 사람은 대개 법률 전문가가 아니고, 조문은 **식품표시광고법 · 화장품법 · 건강기능식품법 · 표시광고법**에 흩어져 있습니다. 같은 표현도 제품 카테고리가 달라지면 판단이 뒤집힙니다.

기존 도구들은 **사후**에 걸리거나, 걸러도 **왜 걸렸는지**를 말해 주지 않습니다.

## 해법 — 경계는 법령이 정하고, 문구는 그 안에서 움직인다

이름의 **Lane** 이 그것입니다. 차선이탈방지(LKAS) 은유가 브랜드가 아니라 **설계 그 자체**입니다 (D-04) — 차선은 우리가 긋지 않고 **법령이** 긋습니다.

진입점은 셋이고, 🔴 **판정 코어는 하나**입니다. 어디로 들어오든 같은 기준으로 잽니다 (D-119 · D-181 · D-266).

| | 진입점 | 하는 일 | 2026-10-14 상태 |
|:-:|---|---|---|
| **A** | **문구 검수** | 사용자가 쓴 문구를 문장 단위로 판정하고 **근거 조문**을 붙인다. 검수 그래프는 대체 문구를 만들지 않는다 — 뺄 구간 · 요건 안내 · 품목 전제별 분기 · 실증 지시까지다 (D-265 · D-337). 화면의 「이 문장 고쳐 쓰기」는 sLLM 서버가 따로 만들고 같은 코어로 다시 판정한다 (D-332 결정 3) | 🟢 **동작** — `POST /judge` 가 검수 그래프를 실제 DB 로 돌린다. 규칙 판정(`rule-0.3.0-dict`) + 판정 인코더의 **유형 후보**(판정은 읽지 않는다 · D-323) · 종착 넷 중 보류 · 증명서 · 지시가 나온다. 회원이 「검수 이력 보관」에 동의하면 판정을 저장한다(W10) |
| **B** | **카피 생성** | 품목 · 인증 여부(분기 6종)와 제품 정보에서 후보를 만들고, 후보마다 **판정 그래프 전체**를 지나게 해 걸린 것을 떨군다 (D-332) | 🟡 **화면 엔진 동작** — `/u/generate`(로그인한 회원만): GPT 후보 → 코드 필터 → 판정 그래프 · 이용자가 적은 인정 · 심사 문구는 따로 판정해 경고한다(D-341). 엔진은 스위치 · 키 · 인코더가 다 있어야 돈다. 코어 `POST /generate` 와 생성 그래프는 여전히 `501` · 빈 노드다 |
| **C** | **AI 광고 생성** | 문구를 매체 지면에 배치한다. **「광고」 표시가 없는 출력 경로를 두지 않는다** | 🟡 **화면 동작** — `/u/compose`: 문구를 코어 판정에 먼저 통과시키고 섹션 편집기를 연다(칸마다 재판정). 코어 `POST /compose`(템플릿 엔진)는 `501` |

B ↔ C 는 왕복으로 **설계돼 있습니다** (D-181). C 가 매체 프로파일을 B 에 넘기고, B 의 각색본이 C 의 지면으로 돌아옵니다. 매체가 바꾸는 것은 **길이 · 문장 수 · 문체 · 표시 배치**뿐이며, **판정 기준 · 허용 어휘 · 근거 조문은 매체에 따라 달라지지 않습니다** (D-93).

> [!NOTE]
> **B 는 화면 엔진으로 돕니다(2026-10-13 · D-332).** 생성 그래프(D-264 의 규칙 조립)가 남은 기간 안에 서지 않아, 권소라의 카피 생성 엔진
> (`app/routers/copygen/` — GPT 가 후보를 쓰고 · 코드 필터가 거르고 · **판정 그래프 전체**가 본다)을 화면 경로로 붙였습니다. 외부 생성 API 는 **생성**에만 쓰고 판정에는 쓰지 않습니다(D-78 개정).
> 「남았다」는 위반 후보를 못 찾았다는 뜻이지 적법 확인이 아닙니다.
>
> **검수 화면의 「고쳐 쓰기」** — `POST /u/review/rewrite` 가 로컬 sLLM 서버(`docs/lse/sllm_service.py` · `127.0.0.1:8765` · 별도 `.venv-sllm`)를 불러
> 지적 문장을 고쳐 쓰고, 고친 문구를 같은 판정 코어로 다시 판정합니다(D-332 결정 3 · `app/routers/sllm_client.py`). 서버가 없으면 후보를 그리지 않습니다.
> 쓰는 판은 모델 잠금 `models.lock.json` 이 정합니다 — Qwen3 4B 기반 LoRA 두 단계(1단계 q4b-v14 · 2단계 q4b_polish · D-335). ⬜ 서버가 잠금으로 판을 대조하는 것은 아직입니다(이서은).

## 판정 코어 — 순서와 불변식

![판정 코어](assets/diagrams/a-03-judge-core.png)

판정 코어는 **서브그래프 하나**이고 검수 · 생성 그래프가 같은 것을 부릅니다 (D-266). 순서의 정본은 `app/graph.py` 입니다.

```
split → classify → retrieve → match_dict → encode
      → 법별 노드 팬아웃 (표시광고법 · 식품표시광고법 · 화장품법 — 동시에 · D-267)
      → merge_laws → judge → assess_risk → premise_branches → doc_rules
```

| 노드 | 하는 일 | 2026-10-14 |
|---|---|---|
| `split` · `classify` | 문장 분할 · 받은 품목으로 적용할 법을 고른다(품목이 없으면 세 법 전부) | 🟢 |
| `retrieve` | 조문 검색 — 벡터 + 어휘 하이브리드, 문장마다 한 번 | 🟢 |
| `match_dict` | 금지 표현 사전 매칭 — 판정이 아니라 근거 후보 | 🟢 |
| `encode` | 판정 인코더 — 문장마다 **유형 후보 · 확신** | 🟢 **배선** — 응답의 `encoder_candidates` 칸에만 싣고 판정은 읽지 않는다(D-323 · D-341 결정 2). 쓰는 판은 잠금이 정한다(카드 17 · D-331 · D-333). 품목 입력 판이면 문장마다 「모름」 + 품목 셋을 한 배치로(D-336 · D-339). 근거 구간(스팬)은 내지 않는다 |
| 법별 노드 · `merge_laws` | 법마다 자기 근거 · 사전 적중만 거르고, 빠진 법이 없는지 대조한다 | 🟢 |
| `judge` | **규칙 판정**(`rule-0.3.0-dict`) — 단독판정 자격이 있는 사전 적중만 위반 확정, 나머지는 보류 (D-127 개정 · D-269 · D-311). 인코더와의 조합은 **표시**로만 닿는다(D-340 · 질병 합의 확정은 접었다 · D-341) | 🟢 |
| `assess_risk` | 서명된 제재표에서 위험도 **하한**을 찾는다. 못 찾으면 적지 않는다 (D-305). 확정된 실증형 거짓_과장에는 **실증 분기**를 붙인다(상한 R0 · D-337) | 🟢 |
| `premise_branches` | 품목을 모르면 전제마다 다시 판정해 **분기**를 내고, 기록은 가장 보수적인 쪽으로 (D-319). 화장품 전제에서는 인코더 후보 질병 · 건기식 오인을 의약품 오인으로 옮긴다(D-338) | 🟢 |
| `doc_rules` | 문서 단위 규칙 | ⬜ 빈 노드 |

검수 그래프의 종착은 **보류 · 증명서 · 지시 · 통과** 넷이고 **루프가 없습니다** (D-265 · D-268). 지금 실제로 나오는 종착은 보류 · 증명서 · **지시**입니다 — 지시는 2026-10-14 에 섰습니다(확정 ∧ 사유 B ∧ 거짓_과장뿐 ∧ 근거 법 하나인 문장에 실증 분기 · D-337 · dev 749 행 중 지시 63 · 원장 10-14(A) ⑧ · 클론 A). 통과는 **확정 ∧ R0(위반 없음)** 일 때만입니다 (D-273). 품목을 모르는 요청과 주된 광고법을 보지 않은 품목에는 통과 표시가 없습니다 (D-319 · D-277).

불변식은 **DB 제약과 계약 검증기가 강제**합니다. 「그렇게 하기로 했다」가 아니라 **그렇게 안 하면 저장이 안 됩니다.**

| | 불변식 | 강제 지점 |
|:-:|---|---|
| ① | **코드가 정한 하한을 모델이 낮출 수 없다** | `ck_judgment_final_not_below_floor` — 하한은 제재표(별표)에서만 온다 (D-09 · D-305) |
| ② | **재생성은 3라운드까지** | `CHECK attempt BETWEEN 0 AND 2` — 라운드는 **생성**의 것이고, 검수 응답은 계약이 `attempt = 0` 만 받는다 (D-265) |
| ③ | **보류에는 반드시 사유가 있다** | `CHECK (verdict='hold') = (hold_reason IS NOT NULL)` · 사유는 여섯 값 |
| ④ | **위험도를 올리려면 근거 스팬이 있어야 한다** | `ck_judgment_raise_needs_evidence` |

판정 결과는 통과/위반 둘이 아니라 **넷**입니다 — `confirmed` · `hold` · `no_basis` · `unjudged`. **미판정을 통과로 세지 않습니다** (D-127 · D-273). 위험도는 **R0~R3** 이고(R4 는 도달 불가 · D-227) 한 번 올라가면 내려오지 않습니다(래칫 · D-09).

## 거버넌스가 코드 안에 있습니다

이 프로젝트의 중심은 모델이 아니라 **「그 판정을 믿어도 되는가」** 입니다.

**① 수집이 fail-closed 입니다.** 모든 수집기는 `registry.require(source_id, use=)` 로 시작합니다. 등급(G0~G3) × 용도(U1 학습 / U2 RAG / U3 인용 / U4 배포)가 허용하지 않으면 **첫 줄에서 거부**합니다. 등급 판정에는 **2인 확인 서명**이 필요하고, 서명이 없으면 수집 자체가 안 됩니다. 원천이 신고한 건수보다 덜 받았으면 「수집 완료」로 기록하지 않습니다.

**② 데이터의 위치가 곧 권한입니다.** `g3/` · `g2_facts/` · `g2_norepub/` · `quarantine/` — 디렉터리가 게이트입니다. 재배포 금지 자료는 물리적으로 다른 곳에 있고, 미판정 자료는 **어떤 스크립트도 읽지 않습니다**.

**③ 근거 없는 판정을 내지 않습니다.** 위험도를 올리려면 근거 스팬이 있어야 하고, 그것을 DB 제약이 강제합니다.

**④ 모르는 것은 모른다고 적습니다.** 평가 표본이 유형별 30건 미만이면 **「측정 불가」**로 표기합니다 — 좋다는 뜻도 나쁘다는 뜻도 아닌, 아무것도 모른다는 뜻입니다 (D-40).

**⑤ 평가셋은 봉인합니다.** 학습에 쓰지 않는 것은 물론이고 **채점 규칙을 고르는 재료로도** 쓰지 않습니다 (D-175). 게이트 테스트가 유출을 검사합니다.

**⑥ 외부로 나가지 않습니다.** 판정 경로에 외부 트레이싱 도구를 쓰지 않습니다. 배제한 도구가 **전이 의존으로 딸려 들어오면 그래프 빌드가 멈춥니다** (D-184) — 「안 쓴다」는 약속이 아니라 구조입니다.

## 데이터 — 두 층으로 나눕니다

**데이터층 19표**(법령 · 사전 · 골든셋 · 위험도)와 **런타임층 12표**(사용자가 쓴 것 + 계정 · 운영)를 분리하고, **두 층 사이에 FK 를 두지 않습니다.** 사용자 데이터가 판정 근거를 오염시킬 경로 자체를 없애기 위함입니다.

모델은 셋으로 갈립니다.

| 자리 | 모델 | 2026-10-14 |

### 데이터 — 누가 무엇을 치나

기기마다 **역할**이 하나입니다. 처음 한 번 `data-setup` 이 역할·폴더를 `.env` 에 적습니다(손으로 열지 않습니다).
파생물을 **만드는** 명령은 정본에서만 돌고, 다른 기기에서는 이유와 할 일을 말하고 멈춥니다 (D-226).

| 역할 | 누구 | 처음 한 번 | 평소 |
|---|---|---|---|
| **정본** | 클론 B 한 대 | `data-setup --role canonical` | `collect` → `data-refresh <원천>` → `data-publish` → 원장 커밋·push → `load` · 🆕 원문 거울 `raw-mirror-publish` (D-256) |
| **사본** | 클론 A · 팀원 · 서버 | `data-setup` | `git pull` 뒤 그냥 쓴다 — `load`·`chunk`·`embed` 가 부족한 파생물을 **스스로 받는다** (`data-sync`) · 🆕 팀장 기기만 `data-setup --mirror` → `raw-mirror-sync` 로 원문을 받아 `extract <원천> --preview` (D-256 · 파생물은 안 바꾼다) |
| **수집 팀원** | 사본 + 수집 | `data-setup --device <별칭>` | `collect` → `raw-publish` → 수집 원장을 **자기 브랜치**에 push → 팀장이 `raw-import --from <브랜치>` 로 검사·병합·`raw-import` |

🚨 별칭은 팀 회의로 겹치지 않게 정하고 **실명을 쓰지 않습니다** — 수집 원장은 이 공개 저장소에 올라갑니다.
🚨 별칭은 **기기마다 하나**입니다 — 한 사람이 기기 두 대로 수집하면 계정은 그대로, 별칭만 둘(`collector-1a` · `collector-1b`). 같은 별칭을 두 기기에 쓰면 서로 받은 원문을 잃어버린 것으로 보고 **다시 받습니다** (D-250). `raw-publish` 는 기기마다 따로 칩니다.
🚨 공유 폴더(Drive)는 초대받은 계정만 엽니다. 폴더 이름을 알아도 들어갈 수 없습니다. 키는 `.env` 에만 있고 원문에 키가 섞이면 올리기가 멈춥니다.
